## 1. Cached input never recorded — and it was my capture, not the mapping

You were right that it still didn't work. I traced it properly this time.

Anthropic-native upstreams report cache counters on **`message_start`**, so that's the only place my capture looked. Everything translated from an **OpenAI-shaped** provider learns them from the final usage chunk, which arrives on **`message_delta`** — so the value was extracted correctly by the provider and then discarded by the recorder.

**Proven against live OpenRouter**, a repeated 4k-token prompt:

```
OpenRouter usage    : prompt_tokens 4011, prompt_tokens_details.cached_tokens 3968
provider maps to    : {'cache_read_input_tokens': 3968}
recorded tokens_in  : 4011
recorded cache_read : 3968          ← previously recorded as nothing
```

That's a **98.9% hit rate** that was showing as zero. Both event shapes now have regression tests.

Worth noting OpenRouter also returns `cache_write_tokens` inside `prompt_tokens_details` (not as a separate Anthropic-style field) and a real `cost` in dollars — neither is consumed yet, but both are now visible as follow-ups.
