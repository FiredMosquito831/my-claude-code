## Description

## What was wrong

Reported directly: *"get started doesn't allow you to see already done steps like it did before."*

4.32.0 made the checklist advance to the next action once the expanded step became done. That advance ran on **every render**, with no regard for how the step got expanded — so clicking a completed step's header set it as expanded, re-rendered, saw it was done, and immediately advanced away. Finished steps could not be opened at all; they collapsed the instant you clicked them.

## The fix

Auto-advance now applies only to a step **the app chose for you**. Opening a completed step to re-read what you did is a legitimate thing to want, and a convenience feature must not overrule an explicit click. The toggle records whether the expansion was user-initiated; the advance skips those.

The behaviour it was added for is unchanged: finish the step the checklist put in front of you and it still moves to the next one.

## Residual risks

The expand/collapse interaction is DOM state with **no test coverage** — the existing suite covers the derived step data, not the state machine. That is precisely why the first version shipped broken, and why this fix is verified by reading plus the user's own report rather than by a test. Worth a jsdom-level test if this area changes again; I have not added one here because the suite has no DOM harness at all and introducing one belongs in its own change.
