## What

One parameterized RotationEngine in core/credential_rotation.py now serves both key pools. Every historical point of divergence between the provider engine (async, SDK-classified failures) and the websearch KeyPool (sync, caller-classified) is a RotationTuning field; PROVIDER_TUNING and WEBSEARCH_TUNING reproduce both engines' documented behavior exactly. providers/credential_rotation.py keeps SDK failure classification on top; websearch/rotation.py becomes a thin adapter carrying key material, masking, and admin snapshots. parse_websearch_keys deleted in favor of parse_credential_keys; admin_routes rewired to surviving symbols.

Closes the "two rotation engines" structural debt item.

## Follow-up fix (c5ee5e1)

Linux CI caught three behavioral divergences between the consolidated engine and both historical pools; all three fixed on this branch and re-verified green:

1. refresh() re-woke already-awake HALF_OPEN slots on every choose(), clearing an outstanding probe reservation (unlimited probe admission). It now skips any slot already in the wake state.
2. In both historical pools the lockouts counter doubles as the live escalation index (backoff keyed off it, success zeroed it). Recovery now resets it alongside auth_failures instead of preserving a lifetime total.
3. KeyPool.health_at() returned point-in-time snapshots where the old pool handed out its own mutable record; ported tests hold references across transitions. KeyHealth is now a live-backed facade over the engine slot with an identical attribute surface; snapshot/dashboard payload shapes unchanged.
