## Description

## A key is judged only on signals about the key

Rotation stops rotating on the model's failures, and stops benching working credentials for faults they did not cause. Every duration a key waits now comes from the provider or from a setting — none is invented here.

## What was wrong (measured on a live 3-key NVIDIA NIM pool, `round_robin`, chains 5–10 models deep)

**1. Keys rotated on a ~25s timer nobody configured.** `_first_token_budget` (shipped in #214) divided the executor's per-model attempt share (≈60–75s) by the untried credentials and abandoned any key that had produced no first token inside its slice, floored at a hardcoded `MIN_CREDENTIAL_FIRST_TOKEN_SECONDS = 5.0`. The live log line:

```
Credential 3 produced no first token within 25.0s of its share of this attempt
```

#214's own comment classified a timeout as "route-shaped" and rotated on it anyway.

**2. Healthy keys kept landing in cooldown — 1,529 times in one day.** On 08-28 the pool answered `All API keys for this provider are in cooldown` 1,529 times. What charged key health: `410 model gone` on `nvidia_nim/thinkingmachines/inkling` (38×), `400 top_p immutable` (42×, fixed in #209), and first-token timeouts (partly fixed in #214). 5xx / 410 / transport still charged health as `"transient"` and walked an invented 10s → 30s → 60s → 120s ladder, tripping a circuit breaker at three in a row. A 429 escalated the same ladder, and the provider's own `Retry-After` was never passed into the engine at all.

**3. Half-open probes leaked.** `mark_acquired` set `is_probing` on a HALF_OPEN slot; only `fail()`, `succeed()` or `release_probe()` cleared it, and the uncharged-failure path returned before any of them ran. A probing key that took a timeout or a 400 stayed unselectable until someone reset it by hand.

## Mechanism

Health and rotation were one deny-list that defaulted to "charge it", so every newly discovered class of route-shaped failure needed a new exemption, and everything not yet enumerated was still wrong. They are now two positive allow-lists:

| Signal reaching the pool | Rotate? | Key health |
|---|---|---|
| 401 / 403 | yes | escalating auth lockout (`CREDENTIAL_LOCKOUT_TIERS`) |
| 429 | yes | benched for exactly the provider's `Retry-After` / `x-ratelimit-reset-*`, else `RATE_LIMIT_COOLDOWN_SECONDS`, capped at 1h. No ladder, no tier, no breaker |
| connection / transport | yes | **none** |
| timeout | **no** | none — raises, executor tries the next **model** |
| 5xx / overloaded / 410 | **no** | none — raises, next model |
| 400 / context length / any other 4xx | no | none |
| unclassified | no | none |

`ExecutionFailure` gained `retry_after_seconds`, filled at classification from a real header only (new `retry_after_from_error`), and carried through the rotation adapter into `RotationEngine.fail(..., retry_after=...)`. `PROVIDER_TUNING` now runs `rate_limit_mode="fixed"` with `rate_limit_seconds` sourced from settings.

Also removed: the per-credential first-token timer and `core/attempt_budget.py` entirely; `PoolHealthState.HALF_OPEN`, `is_probing` and `release_probe` from the core engine; and `route_health.py`'s `min(self.eject_seconds, 1.0)` clamp, which silently overrode `FALLBACK_EJECT_SECONDS` with one second for timeout/5xx — i.e. for almost every real ejection.

Confirmed while investigating: `_create_single_provider` builds a fresh `ProviderRateLimiter` per call and `create_provider` calls it once per key, so **each credential really does own its own limiter** — the engine's 429 ladder was a second, invented bench sitting on top of a correct one.

## What to expect now

- A model that stalls costs one key one attempt, then the chain moves to the next model. No key is benched.
- A throttled key waits exactly as long as the provider asked, and no longer.
- A pool of working keys can no longer be emptied by a bad model, a bad chain entry, or a bad request.

## Action required

**`CREDENTIAL_CIRCUIT_THRESHOLD` is removed.** The breaker it configured no longer exists for provider pools. `Settings` is declared `extra="ignore"`, so an existing `~/.fcc/.env` still carrying the line starts normally and the value is ignored — there is nothing to edit. A test pins that. The admin form no longer writes the key back.

New settings, each replacing a hardcoded literal and wired constants → settings → limits → manifest → `.env.example` → consumer, with a contract test per hop:

- `CREDENTIAL_LOCKOUT_TIERS` (default `300,3600,86400`)
- `FALLBACK_COOLDOWN_STEP_OVER_FLOOR` (5.0)
- `PROVIDER_RETRY_BACKOFF_BASE_SECONDS` (2.0), `PROVIDER_RETRY_BACKOFF_MAX_SECONDS` (60.0), `PROVIDER_RETRY_BACKOFF_JITTER_SECONDS` (1.0)

Removing an env var is MAJOR: **5.73.0 → 6.0.0**, with `uv lock` in the same commit.

## Known and deliberate

- The generic cooldown ladder and circuit breaker stay in `core/credential_rotation.py` because `WEBSEARCH_TUNING` still uses them (threshold 4, exact mode, fixed 60s window). The provider adapter simply never classifies a failure as `"transient"`, so that path is unreachable from a model provider. `tests/websearch/test_rotation.py` is unchanged and green.
- `credential_lockout_tiers` stays a `str` on `Settings`, parsed by `parse_lockout_tiers` at the consumer, so the admin form round-trips the value it displays and the manifest-default contract test still holds.
- `error_justifies_rotation` excludes `openai.APITimeoutError` explicitly: it subclasses `APIConnectionError`, so the transport check would otherwise read a silent model as a broken socket and spend the rest of the pool on it.
- The rotating loop now adds the credentials this request already tried to `acquire`'s avoid set. Rotation previously relied on the failure having benched the key it left behind; once a transport fault costs nothing, `failover` re-picked slot 0 and gave up with the other keys untouched.

## Residual risks

1. **A genuinely broken key is no longer benched** if it fails with 5xx or transport on every request. Rotation tries it once per request and the chain absorbs the cost. This is the deliberate trade: the failure classes that could identify such a key are the same ones that were emptying healthy pools, and 401/403 — the signal that actually names a bad credential — still locks out.
2. **Stale `CREDENTIAL_CIRCUIT_THRESHOLD` lines** in existing `.env` files are ignored rather than reported. Someone who tuned it will find it no longer does anything; the removal is in the release notes and the setting's replacement (`CREDENTIAL_LOCKOUT_TIERS`) is adjacent in the form.
3. **Timeout/5xx model benches now last the full `FALLBACK_EJECT_SECONDS`** (30s default) instead of the 1s the clamp silently imposed. That is the configured behaviour, but it is a visible change for anyone who had grown used to the clamp.
4. The provider-pool path no longer exercises the engine's generic ladder, so a future regression there would only be caught by the websearch tests.
