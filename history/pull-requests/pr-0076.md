## Description

Follow-up to #75. Requested: *"make sure you can independently configure opencode go and opencode zen — both add and remove the keys or set rotation type, and when done for one to happen to the other and sync"*.

4.53.0 got half of that. Both cards could add and remove keys, but the **rotation select stayed only on OpenCode Zen** — I withheld it on the reasoning that a second control bound to one variable was exactly what the field deduplication existed to prevent.

That reasoning was too cautious. `changedValues()` keys its payload by `data-key` and `updateDirtyState()` counts *keys*, not controls:

```js
values[input.dataset.key] = value;      // last-wins, one entry per variable
const count = Object.keys(changedValues()).length;
```

So duplicate controls are only a problem if they are allowed to **disagree**. `syncSharedControls()` mirrors the value across every control bound to the same key on edit, which makes the duplicate a second *view* of one value rather than a second copy of it. Element ids stay unique via a card-scoped suffix.

Both cards now carry the whole pool: add, remove, per-key health, and rotation.
