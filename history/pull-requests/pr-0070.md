## Description

## The problem

A fallback chain could only fire on an **exception**. A model that accepted the request and then went silent raised nothing, so the only thing that ever ended the attempt was the transport read timeout — 300s later — after which the *same stalled model* was retried.

Measured on a real 51,000-request log:

- 4 requests reached their fallback after **566s on average**, all cancelled by the client first
- 190 stalled requests burned **25.7 hours** of wall clock

The chain was picking the right model. It was picking it nine minutes too late.

## The fix

Slow is not the same as failed. Three limits, all disabled by setting them to `0`:

| Setting | Default | Why |
| --- | --- | --- |
| `FALLBACK_FIRST_TOKEN_TIMEOUT` | 120s | Nothing has reached the client before the first chunk, so handing over is invisible |
| `FALLBACK_TOTAL_TIMEOUT` | 600s | Backstop for a stream that committed and then stalled — no chain can rescue it, but it should stop |
| `FALLBACK_EJECT_AFTER_FAILURES` / `FALLBACK_EJECT_SECONDS` | 3 / 30s | Skip a model that just failed repeatedly instead of re-paying its timeout |

## Where the defaults come from

Replayed against the log rather than picked:

```
first token, 51,118 successful requests:  p50 4.5s   p90 8.9s   p99 38.9s   p99.9 181.7s
  120s deadline -> 0.209% of healthy requests re-rolled onto the next model

whole request, 51,549 successful:         p50 7.5s   p90 21.0s  p99 99.8s   p99.9 255.7s
  600s budget   -> 0.025% cut short
```

A re-roll is not a lost request: it is one extra hop, paid at the next model's own TTFT (p50 4.5s).

## Safety

- **Ejection never empties a chain.** If every model on a route is benched, the chain is tried in order anyway — skipping a bad model is an optimisation, refusing to try anything is an outage.
- **A provider's own timeout is not misreported as ours.** `asyncio.wait` rather than `wait_for`, so a `TimeoutError` raised by the provider stays distinguishable from this deadline elapsing.
- **The commit boundary is unchanged.** Once bytes are on the wire no fallback runs, so two models can still never be spliced into one reply.
