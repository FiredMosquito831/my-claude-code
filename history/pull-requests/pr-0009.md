## Description

Adds a version panel, release announcements, and an in-place upgrade. 4.14.2 -> 4.15.0 (MINOR).

## What it does

- **Version panel** (Providers → Version): running version, latest release, last-checked time. Version also always visible in the sidebar.
- **Announcement banner** when a newer release exists, linking to the release notes. Dismissal is remembered *per version*, so hiding 4.15.0 still surfaces 4.16.0.
- **Update now** button, plus a manual **Check for updates**.

## Design decisions worth reviewing

**The upgrade mirrors `scripts/install.sh` rather than inventing a second install path** — download the wheel, verify SHA-256 against the digest GitHub publishes per asset, hand to `uv tool install --force`. A checksum mismatch aborts, exactly as the installers refuse.

**Extras are preserved.** A naive reinstall would silently drop voice support. The uv receipt records extras and the Python pin, so both are carried across.

**Upgrading does not restart the server.** A live process keeps serving already-imported code, so an upgrade can never truncate an in-flight stream. The caller gets a restart-required banner instead. This was the explicit tradeoff chosen over auto-restart.

**Failure is expected, not exceptional.** Offline / rate-limited still renders the running version and keeps the last good payload, so the panel never blanks. The check is cached 6h and single-flighted.

**Numeric version comparison** — 4.14.10 correctly outranks 4.14.9; lexical comparison would get this wrong. Unparseable versions never register as newer.

The install subprocess runs via `asyncio.to_thread`, so a multi-minute resolve doesn't block the proxy.

## Security

`/admin/api/version*` is loopback-gated like the rest of the Admin API. The subprocess uses a fixed argv (never a shell string), so release metadata cannot inject arguments.
