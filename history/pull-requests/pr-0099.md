## Description

## The bug (found by the live test)

The hybrid's "did the install actually land?" check read `uv-receipt.toml` and matched `version = "$Version"`. The live test showed uv does **not** reliably write that receipt into a recreated tool dir, so the check returned false even though the install succeeded — the installer wrongly threw and rolled back after a successful tool-env update.

## The fix

The `.dist-info` directory (`my_claude_code-<ver>.dist-info`) exists only if uv actually installed the package into the fresh tool dir. It needs no python to run and is testable with a stub.

## Verification

- Live: after a uv exit-2 on a locked shim, the canonical tool dir's `site-packages` contains `my_claude_code-5.3.4.dist-info`.
- New locked-shim test stub creates the dist-info dir. All 6 rename tests pass; ruff/ty clean.
