## Description

The last piece of the arc. Everything measured since 5.42.0 — per-rule fire counts, tokens never sent, RTK's own savings, discovery candidates, cache effectiveness — existed only as columns and endpoints. This is where a human reads it.

## Layout

**Variant A ("ledger")**, chosen by the owner from three clickable previews: measurement-led, single column, nothing hidden. Reads top to bottom as *what you saved → what is saving it → what could save more*, with controls beside the number they affect. No accordions, no categories, no tabs.

Measurement is markup filled by **four independent reads**, so one failure cannot blank the rest — *"RTK could not be asked"* is a fact about RTK, not about the request log.

Trimming is a real **settings section**, not hand-rolled controls: a new `optimizer` manifest section owns the 8 trimming fields (moved out of `limits`) and the 2 skip-rule fields (moved out of `runtime`). One owner per setting. The switch and three-state segments wrap the real manifest input — which is why flipping the master switch reports **one** unsaved change, not two.

## New plumbing

`optimization_stats()` in the request log (none existed), a `/admin/api/requests/optimization-stats` route merging the rule registry with what the log measured, and `PROVIDER_KEY_SQL` shared by the breakdown, the export dimension and the filter predicate so those three cannot drift.

## "(unknown)" is fixed

5.42.0 correctly stopped crediting a provider that never served a request — but `(unknown)` is a poor label for something we know exactly. The synthetic key `local:<rule>` is emitted in SQL and rendered as **"answered locally · title generation skip"** across the requests table, the detail drawer, the provider breakdown, the filter datalist and the new cache table. It is a **working filter value**, not just a label.

## The trimming warning states the measurement

Not a caution — the numbers. Shipped `protect_recent_results=2` costs **10.9% more fresh input tokens** than leaving trimming off; enabling mid-conversation costs one near-total cache miss at **3.8% hit**; break-even is a baseline hit rate of **~90.9%**. The five-row table is on the page and the copy tells you to run **Observe** first.

## Never a fabricated zero

RTK absent says "not installed". A rule that never fired shows an em dash for tokens avoided, not `0`. A provider reporting no cache figures gets an em dash. All four pinned by mutations.
