## Description

## What was missing

There was no general way to control which models MCC lists. A gateway can publish hundreds — `nous_portal` alone lists 343 — and every one of them landed in `/v1/models` (what `mcc-claude --discover-models` writes into Claude Code, and what the Codex catalog is built from) and in every Admin model picker. The only allow/deny list in the tree was hardcoded inside `chatgpt_oauth` for its own models, and nothing else could reuse it.

Separately, `parallel_tool_calls` was the single request parameter 5.61.0 left behind when the rest of `NimSettings` became "unset by default".

## Mechanism

`core/model_visibility.py` — `ModelVisibility` plus `parse_model_patterns`. Two comma-separated glob lists matched case-insensitively against the full `provider/model` ref with `fnmatchcase`:

* **`MODEL_VISIBILITY_ALLOW`** — empty means allow everything; a non-empty list makes visibility opt-in.
* **`MODEL_VISIBILITY_DENY`** — applied **after** allow, and wins.

An explicit model pick is just a pattern with no wildcards, so ticking a model and writing `*:free` stay one mechanism. A future Models page writes exact refs into the same two lists rather than growing a second one.

Filtered at two presentation boundaries:

1. `build_models_list_response` (`api/model_catalog.py`) → `GET /v1/models`, which also covers `cli/launchers/codex.py` since it reads that endpoint over HTTP.
2. `_model_options` (`api/admin_routes.py`) → the option lists behind the `model` / `optional_model` / `model_chain` fields, and `blind_models` with them.

## Non-obvious choices

* **Hide only — visibility never reaches routing.** A model named by `MODEL`, a tier override or a `MODEL_*_FALLBACKS` chain still resolves and still serves requests while hidden. `test_visibility_patterns_never_change_a_resolved_route` pins it with `ALLOW` matching nothing and `DENY=*`, asserting the three-model chain resolves unchanged. A filter that silently broke a working chain would surface as an outage nowhere near the setting that caused it.
* **Filtered at the boundaries, not in the cache.** `cached_prefixed_model_infos()` also feeds routing and capability lookups, so it stays unfiltered.
* **The Claude aliases are never filtered.** `claude-opus-4-…` is a protocol name, not a provider ref; hiding it would not shrink a catalogue, it would stop the client naming a model at all.
* **The Admin picker keeps a configured-but-hidden ref**, unlike `/v1/models`. A select has to be able to render the value that is actually saved.
* **`fnmatchcase` on pre-folded strings, not `fnmatch`.** `fnmatch` runs both sides through `os.path.normcase`, which on Windows rewrites `/` as `\`, so slash patterns would behave differently per platform. A test pins that.
* **Matching lives in `core/`, taking raw strings**, because `config` is a declared leaf package that may not import `core` (`test_import_boundaries.py`). `api/model_catalog.settings_model_visibility()` is the one place that builds the filter from `Settings`; both boundaries call it.

## Residual risks

* **`parallel_tool_calls` is a real behaviour change for NIM routes.** Every NIM request used to carry `parallel_tool_calls: true`. It no longer carries the field at all unless set, so NIM's own per-model default now applies. If any NIM model defaults to something other than `true`, its tool-calling behaviour changes. That is precisely what "use the provider default" means, but it is a behaviour change and not only a cleanup. Setting `parallel_tool_calls` explicitly restores the old wire form.
* A denied model that is still named in a route is invisible but alive. That is the deliberate contract, and it means the Admin picker's model list and the set of models that can actually serve traffic are no longer the same set. The picker keeps configured refs visible so this cannot orphan a saved value, and `/v1/models` is the surface where a hidden configured model genuinely disappears.
* Patterns are unvalidated by design — a typo hides nothing rather than raising. Blank and whitespace-only entries are dropped, so a stray comma cannot become a match-everything pattern.

## Deliberately not done

Per-model/per-provider parameter overrides and their JSON store (PR B); the Admin Models page UI (PR C); `chatgpt_oauth`'s hardcoded allow/deny list, which is prior art here and is left untouched.
