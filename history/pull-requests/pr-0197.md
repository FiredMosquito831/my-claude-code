## Description

## What was broken

Four issues found by a research pass comparing this proxy's reasoning-effort handling against 20+ routers, gateways and native provider APIs (LiteLLM, OpenRouter, Helicone, Portkey, vLLM, OpenClaw, AI Proxy, llmgateway, Envoy, Vercel AI SDK, Pydantic AI, LangChain, Docker Agent + OpenAI/Anthropic/Gemini/xAI/Bedrock natives). Full comparative write-up kept out of the repo (untracked scratch); the actionable gaps were:

- **R1 — effort floor invalid.** `_EFFORT_BUDGET_TOKENS` had MINIMAL/LOW at 512 tokens. Anthropic enforces `budget_tokens >= 1024` (hard 400 below that); every surveyed system floors at 1024. A 512-token thinking budget could only ever fail or be silently re-clamped downstream.
- **R2 — gating was silent.** `adapt_reasoning_policy` narrowed a requested policy against per-model capability (clamp, substitute, drop, suppress) but surfaced the reason only as a server log line. A client asking for "max" on a model topping out at "medium" could not learn why the request changed.
- **R3 — always-reasoning models were unhandled.** Models that cannot disable thinking (Claude Fable/Mythos-class, some Grok) would 400 on an explicit OFF, or silently get the provider's own floor with no signal.
- **R4 — dead encoder.** `GeminiReasoningEncoder` (providers/google_openai/reasoning.py) was defined and re-exported but never instantiated; the shipped Gemini path uses `NamedEffortReasoning` + `apply_gemini_request_quirks`. Dead code that looks like an unimplemented feature is a maintenance trap.

## The mechanism

- **R1:** MINIMAL/LOW 512 -> 1_024 in `core/reasoning.py`, with the regression baseline (`reasoning_request_baseline.json`) and the two stale NIM expectations updated to match. The client-visible budget ladder otherwise unchanged.
- **R2:** `adapt_reasoning_policy` returns `tuple[ReasoningPolicy, ReasoningAdaptation]`. New `ReasoningAdaptationKind` (UNCHANGED/SUBSTITUTED/CLAMPED/DROPPED/SUPPRESSED) + `ReasoningAdaptation(kind, message)` in `core/reasoning.py`. The adaptation threads routing (`RoutedMessagesRequest.reasoning_adaptation`) -> capture (`request_capture.py`) -> request log (schema column + guarded `ALTER TABLE` migration + INSERT + read) -> detail export (`export.py` field/order/label) -> dashboard (`admin.js` Thinking pane, `formatReasoningAdaptation`). NULL on ungated requests and pre-migration rows; "no warning" and "nobody recorded" are deliberately indistinguishable in storage, matching the `requested_reasoning` convention. A clamp+substitute chain merges into one descriptor at the worse of the two kinds.
- **R3:** `mandatory: bool | None = None` on `ModelReasoningCapability`, parsed from a conventional `reasoning_mandatory` models.dev key — **explicit True only**; absent stays None (unknown), so the "unknown changes nothing" invariant is preserved and a wrong True can never rewrite every OFF request. When mandatory is True and the client asks OFF, `_mandatory_off_rewrite` sends the lowest supported effort (or adaptive without a vocabulary) with a `REASONING OFF SUBSTITUTED` warning. **No models.dev entry publishes the key today, so this is ship-as-ready: zero behavior change until a source carries the flag.**
- **R4:** encoder + exclusive helper + re-export deleted; `test_adaptive_reasoning.py` gemini branch and the 35 `gemini|*` baseline keys removed. `VertexReasoningEncoder` (wired at `vertex/client.py:37`) untouched.

A cheap static test (count columns vs placeholders in the INSERT string) would close it — not written here to keep the diff scoped.

- **R3 is a no-op today** (no models.dev entry publishes `reasoning_mandatory`). It lights up the day one does; until then the field is parsed-but-never-True in production.
- **The `reasoning_adaptation` column migration is additive** (`ALTER TABLE ... ADD COLUMN`), same pattern as `requested_reasoning`. Old rows keep NULL forever, deliberately not backfilled — same reasoning as that column's migration comment.
- **`mandatory` parse lives before the options early-return** so bare `reasoning: true` entries still carry it; covered by the new `test_reasoning_mandatory_flag_is_parsed_and_silence_stays_unknown` (True / explicit False / absent -> None).
