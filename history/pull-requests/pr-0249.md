## Description

## The defect

Installing on Windows (`irm ... | iex`) while an `mcc-claude` window and the `mcc-desktop` tray were running left **seven commands missing** and printed **"installed and verified"**.

`uv tool install --force` writes the entrypoint shims in ASCII order of the file name *including* the `.exe` suffix (`mcc-claude-old.exe` < `mcc-claude.exe`, because `-` < `.`) and **aborts the whole install on the first shim it cannot overwrite**. A running launcher holds its own `.exe`, so everything alphabetically after it was never written and uv left no `uv-receipt.toml` — `uv tool list` then reported `my-claude-code` as *malformed*.

The installer then reported success because `Invoke-RenameThenReinstall` treated that abort as "expected and harmless", set `$script:NeedDeferredFinish`, and `Configure-AndConfirmFreeClaudeCode` **skipped the command list entirely** in that state, verifying with `mcc-server --version` alone. That check can never fail: the shims are version-agnostic launchers, so an *old* shim reports the *new* version.

## What changed

**`scripts/install.ps1`**

- `Invoke-RenameThenReinstall` renames the tool dir **and every launcher shim** aside to `<name>.exe.old-<stamp>` before `uv tool install`. New helpers `Rename-LauncherShimsAside` / `Restore-LauncherShim` / `Remove-StaleShimBackup`. The shim list is `Get-LauncherCommands`, so a neighbour tool sharing the uv bin directory is never touched (asserted).
- Post-success sweep of `*.exe.old-*` (this run's and any earlier run's); still-locked ones are skipped and reaped next install.
- On any uv failure the tool dir **and the shims** roll back, and the real error is thrown. The old "install landed, keep it and defer the one shim" branch and `$script:NeedDeferredFinish` are gone — the rename is what made that branch necessary.
- `Configure-AndConfirmFreeClaudeCode` always enumerates `Get-LauncherCommands` — one list, not two. Missing commands print `Installed, but these commands are missing: …` / `Close the mcc-claude window(s) and re-run the install command.` and `exit 1`. No "verified", no command reference.
- Deferred helper: `& $uvPath @installArgs` (was `@$installArgs`, which is *not* splatting — it collapses the array into one argument), process identity pinned by creation time as well as id (mirrors `release_updates.py:527`), and the staged wheel is swept on the failing branch too.

**The deferred helper survives**, for exactly one case: the **tool-directory** rename being refused (`Invoke-RenameThenReinstall` returns `$false`), or `uv tool dir` being unreadable. That is a genuine hard lock we cannot work around in-process. It is *not* reachable from a shim lock any more. Its wait set is still every running launcher including the tray, and that is correct now: every launcher runs its interpreter out of the tool directory, so every one of them holds the thing that is locked.

**`src/my_claude_code/application/release_updates.py`** — the dashboard/tray updater's detached helper renames the same shims aside before its uv call, sweeps them after, and reports `missing_commands` in the receipt; `ok` is now `exit code 0 AND nothing missing`. The command list comes from the installed distribution's entry points (`_published_commands`), so it cannot drift from `pyproject.toml`. `bin_dir` is taken from `server_launcher.parent` rather than a second `uv tool dir --bin`, so no uv process is spawned while the server is alive.

**`scripts/install.sh`** — reports every missing command at once instead of stopping at the first, with the same wording; `mcc-anthropic-oauth-login` added (it was published but never verified). No POSIX rename change: POSIX unlinks running files.

**Docs** — README install-troubleshooting row and a `docs/USAGE.md` §15 entry.

## Residual risks

- **A shim held with `FileShare.None`.** A normal running `.exe` is not, but a debugger, some AV products, or a handle opened deliberately can be. uv still aborts; we roll back fully and report honestly. Verified live (output above).
- **A launcher started between `Get-RunningLaunchers` and the uv call.** The no-launchers path installs directly with no rename, so that race still fails — loudly, with a real uv error, and now with honest verification behind it. Renaming unconditionally would close it; kept scoped to the reported defect.
- **`Get-ApplicationCommand` resolves through `PATH`.** If a shim exists but an identically-named command earlier on `PATH` shadows it, verification throws "resolved outside the uv tool bin directory" — pre-existing behaviour, unchanged.
- **The rollback does not remove shims uv wrote for names that did not previously exist** (a new command in the new version, when the install then fails). They are stale but harmless and are overwritten by the next install.
- PowerShell runtime installer tests **never run on Linux CI**, so a PS-only regression can still ship green there. The static guards in `tests/scripts/test_installers.py` and `tests/contracts/` run everywhere and are what CI actually enforces.
