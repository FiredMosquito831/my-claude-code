## Description

## What this changes

Four required dependencies — `openai`, `openpyxl`, `aiohttp` and `tiktoken` —
were imported while the ASGI app was being built, and none of them is asked a
single question between process launch and the first `/health` 200. Together
they were **2.9 s of the 5.3 s** it cost to import `runtime.bootstrap`. Each now
loads on the first call that genuinely needs it.

Nothing on the wire moves: same routes, same responses, same discovery
behaviour, same error text. Import ordering only, so this is a **PATCH**.

## Measurements

Method is §4.0–4.2 of the shutdown/startup spec: scratch server
(`MCC_CONFIG_DIR` pointed at a throwaway config dir with fake keys, one Ollama
provider against a fake upstream on `:8299`, `PORT=8199 HOST=127.0.0.1`),
`.venv/Scripts/mcc-server.exe` launched directly (not through `uv run`, which is
two processes), wall clock from `Popen` to the first `/health` 200. Runs are
**interleaved A/B** (base, branch, base, branch, …) so machine load hits both
arms equally. The live server on `:8082` was never touched.

### Honest note: the `openai` deferral is worth ≈ 0 s end-to-end on a typical install

Measured on its own (3 paired rounds, the `openai` deferral only):
**−0.083 s — inside the noise.** The spec estimated ~1.3 s, but that estimate did
not account for `ApplicationRuntime.start`, which awaits
`validate_configured_models` → `resolve_provider` → `OpenAIChatProvider` →
`AsyncOpenAI`, i.e. it imports the SDK *inside the lifespan startup*, still
before the port answers. The cost moves; it does not go away.

It is kept anyway, because it is the whole saving for an install whose
configured models are all Anthropic / Gemini / Vertex — no OpenAI-compatible
provider is ever constructed — and it costs nothing on the installs where it
merely breaks even. The **−0.853 s** above is therefore essentially
`openpyxl` + `aiohttp` + `tiktoken`.

## Per-step, with file:line

**Step 1 — lazy `openai`.** `import openai` moved into the function that asks the
SDK an exception-class question:

- `src/my_claude_code/providers/failure_policy.py:251, :303, :358, :387, :495`
- `src/my_claude_code/providers/credential_rotation.py:129, :204, :245`
- `src/my_claude_code/providers/stream_recovery.py:342`
- `src/my_claude_code/providers/recovery/complaint.py:116`
- `src/my_claude_code/providers/openai_chat/usage.py:76`
- `src/my_claude_code/providers/nvidia_nim/client.py:219`
- `src/my_claude_code/providers/openai_chat/provider.py:102-135` — the client
  class resolves through a module-level `__getattr__` plus
  `_async_openai_client_class()`, and `:202` constructs through it. This
  deliberately keeps `provider.AsyncOpenAI` a real, patchable module attribute:
  about fifty provider tests patch exactly that name, and a plain function-local
  import silently stops honouring the patch (it did — 61 tests went red before
  the seam was restored).

**Step 2 — lazy admin route modules: audited, not actionable.** `create_app`
calls `app.include_router(admin_router)` while the app is being built; the router
object must exist at that moment or the admin URLs would 404 until something
touched them. That is a user-visible routing change, not import ordering. The
2.4 s the spec attributed to `admin_*` was almost entirely `openai` and the
provider graph reached *through* them; after step 1 the admin modules' own body
cost is ~0.10 s. What was genuinely deferrable behind them is deferred at the
leaf instead (step 3), which also helps the non-admin paths.

**Step 3 — defer the leaves nothing on the startup path needs.** This is where
the wall-clock saving is.

- `src/my_claude_code/core/export.py:853` — `import openpyxl` inside `render_xlsx`.
- `src/my_claude_code/api/web_tools/__init__.py` — the convenience re-exports now
  resolve through `__getattr__`. `admin_routes.py:190` imports
  `web_tools.search_providers`, which ran the package `__init__`, which imported
  `streaming` → `outbound` → `aiohttp`. `search_providers` itself never needed
  any of it.
- `src/my_claude_code/api/handlers/messages.py:461` —
  `stream_web_server_tool_response` imported in the one method that streams a web
  server tool.
- `src/my_claude_code/core/token_encoder.py` (new) — one memoised `cl100k_base`
  build replacing three module-level `tiktoken.get_encoding` calls, in
  `core/anthropic/tokens.py`, `core/anthropic/streaming/ledger.py` and
  `core/openai_common/usage.py`. The failure is memoised too, so a broken
  encoder is not retried on every token count.

Per-provider module deferral (the rest of the spec's step 3) is a no-op once
step 1 lands: `providers.runtime.factory` no longer appears anywhere near the top
of the import profile (< 0.12 s), and every module it loads is needed by
`validate_configured_models` during lifespan startup anyway.

**Step 4 — duplicate `build_asgi_app`: audited, none exists.** The only production
call is `cli/commands.py:383`; `runtime/bootstrap.py:21` is the sole definition.
Every other reference in the tree is a test double. The spec's "if present, ≈ 4 s"
does not apply.

## Behaviour deltas, stated plainly

- `core.anthropic.tokens.count_text_tokens` falls back to the same
  4-chars-per-token estimate `core.openai_common.usage` already used, if the
  encoder cannot be built. Previously that module built the encoder at import,
  so an unbuildable encoder stopped the server from starting at all — the new
  path is strictly more forgiving, and unreachable on a working install.
- The first request that counts a token pays the ~0.3 s BPE build that a start
  used to pay. Every start saves it; only the first count on a process pays it.

## Not in this PR

`ProviderRuntimeManager._refresh_generation`, dispatched as the "non-blocking"
background discovery sweep, holds the event loop for **~2.5 s** on this
one-provider scratch config before `/health` can answer — measured with an
in-process uvicorn probe that timestamps each startup phase. It is now the single
largest remaining item in a cold start, larger than everything this PR removed.
Fixing it moves discovery timing, so it needs its own change and its own version
decision.
