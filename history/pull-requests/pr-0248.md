## Description

## What this is

MCC accepted three inbound shapes and none of them was the one almost every
OpenAI-compatible client actually sends. Cline, Aider, Goose, Droid and every
IDE plugin that says "point me at an OpenAI base URL" speak
`POST /v1/chat/completions`; MCC answered 404. This adds that surface, and fixes
the auth fail-open (§63F) in the same release because both are about who can
reach this proxy and on what terms.

`POST /v1/chat/completions` sits beside `/v1/messages` and `/v1/responses` and
is built the way the Responses adapter was: a `core` package that only
translates, and a handler that hands the result to the same `ModelRouter` ->
`ProviderExecutor` every other surface uses. Routing, fallback, pause, reasoning
gating, output budgets, wire capture, the upstream ladder, the request log,
analytics and the optimizer rules therefore apply to all three doors
identically.

## Request translation (Chat Completions -> MessagesRequest)

| Client field | Anthropic |
| --- | --- |
| `model` | `model` (the same refs the other two accept, through the existing resolver) |
| `messages[system\|developer].content` | `system`, joined with a blank line |
| `messages[user].content` string | `content` string |
| `messages[user].content` parts | `text` blocks; `image_url` -> `image` with a `base64` source for a data URL, a `url` source for http |
| `messages[assistant].content` | assistant `text` block (dropped when empty and only tool calls remain) |
| `messages[assistant].tool_calls[]` | `tool_use` blocks, arguments JSON-decoded |
| `messages[assistant].reasoning_content` | `Message.reasoning_content` |
| `messages[tool]` | `tool_result` blocks; consecutive ones coalesce into **one** user turn |
| `max_completion_tokens` / `max_tokens` | `max_tokens` (the newer field wins when both are sent) |
| `temperature`, `top_p` | same |
| `stop` (string or list) | `stop_sequences` |
| `tools[].function` | `tools[]` `{name, description, input_schema}` |
| `tool_choice` `auto`/`none`/`required`/`{type:function}` | omitted / tools withheld / `{"type":"any"}` / `{"type":"tool","name":…}` |
| `parallel_tool_calls: false` | `tool_choice.disable_parallel_tool_use` (built even with no `tool_choice`) |
| `reasoning_effort` | `output_config: {"effort": …}` — the name travels, routing prices it |
| `response_format` `json_object` / `json_schema` | a system instruction; `json_schema` carries its schema verbatim |
| `metadata`, `user` | `metadata` (+ `metadata.user_id`) |
| `stream` | recorded as the client's intent; the internal request is always `stream: true` |
| `n` > 1 | **400** `invalid_request_error`, `param: "n"` |
| `seed`, `logprobs`, `top_logprobs`, `frequency_penalty`, `presence_penalty` | dropped, with one trace row naming them |
| unknown `response_format.type`, non-function tool, unknown role | **400** naming the value |

## Stream translation (Anthropic SSE -> chat.completion.chunk)

| Anthropic event | Chunk |
| --- | --- |
| `message_start` | first chunk, `delta: {role:"assistant", content:""}`; seeds prompt/cache counts |
| `content_block_delta` `text_delta` | `delta.content` |
| `content_block_start`/`delta` `thinking` | `delta.reasoning_content` **and** `delta.reasoning` (same text) |
| `content_block_start` `tool_use` | `delta.tool_calls[{index, id, type:"function", function:{name, arguments:""}}]` |
| `input_json_delta` | `delta.tool_calls[{index, function:{arguments: fragment}}]` |
| `message_delta.stop_reason` | `end_turn`/`stop_sequence` -> `stop`, `max_tokens` -> `length`, `tool_use` -> `tool_calls` |
| `message_stop` | finish chunk (`delta: {}`), then the usage chunk, then `data: [DONE]` |
| `error`, or a failure after the first frame | `data: {"error":{…}}` then `[DONE]` — what the OpenAI SDK stream readers raise on |

The tool-call index is **not** the Anthropic block index: a reply whose first
block is text and whose next two are tool calls streams as tool-call 0 and 1.
`stream_options.include_usage` appends one choiceless chunk carrying
`prompt_tokens` (including cache reads), `completion_tokens`, `total_tokens`,
`prompt_tokens_details.cached_tokens` and a capped
`completion_tokens_details.reasoning_tokens`.

Non-streaming assembles that same internal stream into one `chat.completion` at
the API boundary, the way `/v1/messages` already does. There is no second
pipeline to drift.

## The auth decision

Both options were investigated.

- **First-run flow.** `mcc-init` writes `.env.example` into `~/.fcc/.env`, and
  that template sets `ANTHROPIC_AUTH_TOKEN="freecc"`. The admin manifest offers
  the same default. `mcc-server` never creates a `.env` itself. So a fresh
  install always has a token and a startup refusal cannot break first run —
  pinned by `test_the_shipped_defaults_start_without_a_refusal`.
- **Generating a token on first run** would silently break every client already
  configured to send nothing, and would have to be written into the managed
  `.env` on a path that today has no reason to write there.

So: **refuse to start**, in `cli/commands.py::_run_supervised_server`, before
`uvicorn.Config` and before the port probe. The policy itself is
`config/proxy_auth.open_proxy_without_auth_error`. The compare in
`require_proxy_auth` is untouched. Loopback binds with no token still run.

Live, on the scratch server:

```

who can reach it. Set ANTHROPIC_AUTH_TOKEN to a secret, or set HOST=127.0.0.1
to serve this machine only (change either on the dashboard under
```

The page and card the message names are read back out of the shipped `admin.js`
and the admin manifest by `tests/contracts/test_proxy_auth_startup_policy.py`,

## Deviations from the brief

- **`response_format` is a system instruction, not a forced tool call.** The
  brief allowed "the nearest Anthropic mechanism or a clear 400". A forced-tool
  encoding is arguably nearer, but it changes `finish_reason` semantics and the
  whole streaming shape; an instruction carrying the schema verbatim is honest,
  cheap, and what every OpenAI-compatible proxy does. Unknown types still 400.
- **Small refactor outside the new package.** `core/openai_common/` was created
  for the error envelope, the failure-kind map, the Anthropic SSE reader and the
  token estimator, rather than copying ~150 lines into the new adapter.
  `core/openai_responses` keeps every one of those names importable, so its
  tests and its public surface are byte-identical in behaviour.
  `api/wire_surfaces.py` similarly replaces two hand-written path literals in
  `app.py` that would otherwise have had to be extended in two places.

## Residual risks

- **`status: cancelled` on some streamed rows.** A client that stops reading at
  `[DONE]` leaves the capture recording `cancelled` rather than `success`. This
  is **pre-existing and shared with `/v1/responses`** — verified on the same
  server in the same session, where a `/v1/responses` request recorded
  `cancelled` and a `/v1/messages` one recorded `success`. Not introduced here
  and not fixed here.
- **Clean truncation after a committed stream stays off** for this surface, as
  it is for Responses (`wire_api != "messages"` in `execution.py`). A stream that
  dies mid-answer ends with an `error` object rather than a clean `length`
  finish. Chat Completions *could* express that ending; choosing to is a
  behaviour change worth its own review.
- **`reasoning_tokens` is an estimate**, capped by the real `completion_tokens`.
  Anthropic reports one output count and never says how much of it was thinking.
- **No harness targets the new protocol yet.** `HarnessProtocol.OPENAI_CHAT_COMPLETIONS`
  exists and is labelled; Cline & co are PR 9.
- **`GET /v1/models` advertises ids with a slash in them** (`anthropic/lmstudio/…`).
  Unchanged by this PR, but a client with a strict model-id parser may struggle;
  every id the other two surfaces accept is accepted here.
- The live proof used a **fake** upstream gateway. No real provider credential
  was exercised for this surface.

## Action required for operators

An install that both listens beyond loopback (`HOST` other than `127.0.0.1` /
`localhost` / `::1`) **and** has an empty `ANTHROPIC_AUTH_TOKEN` will refuse to
start after this release. Set a token, or set `HOST=127.0.0.1`. The refusal
message names both. Installs created by `mcc-init` are unaffected: the shipped
template sets a token.
