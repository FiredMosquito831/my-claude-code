## Description

## What this changes

The desktop shell had no logo. `app-icon.png` was a 2,567-byte "MC" monogram committed as a real file, while `desktop_assets.py` described it as a runtime placeholder for an asset that "has not shipped" — so nothing rendered the product's actual mark, and there was no way to put it in a Start Menu entry or a Dock.

This ships the owner's designed mark and an opt-in `--desktop` / `-Desktop` installer flag that creates a native launcher per platform.

## The mark

Keyed to transparency with an **un-blend**, not a colour threshold:

```
C = (observed - (1-a)*bg) / a
```

The source background is a flat `#050c1d`, and a plain threshold leaves a navy fringe on every antialiased edge — which is precisely what shows up at 16px.

**Two PNG renders ship on purpose**, not one file scaled at render time. A tray draws at 16–24px, where the 10% margin the app icon wants shrinks the glyph below legibility, so `tray-icon.png` is the same mark cut at 2%.

| Asset | Margin | Size | Use |
| --- | --- | --- | --- |
| `app-icon.png` | 10% | 256², RGBA | window / taskbar / docs |
| `app-icon.ico` | 10% | 16–256 multi-size | Windows `.lnk` |
| `app-icon.icns` | 10% | 16–512 slots | macOS `.app` |
| `tray-icon.png` | **2%** | 128², RGBA | tray at 16–24px |

Palette quantising was tried and reverted: it folds the fully transparent background into a nearest palette entry with non-zero alpha, shipping a faint box behind the mark. Caught by probing the decoded alpha channel for a zero value and not finding one.

## A shipped bug caught before merge

`mcc-desktop` is a `[project.gui-scripts]` entry, so `mcc-desktop.exe` is a **GUI-subsystem** binary and PowerShell's call operator does not wait for it. The first version exported the icon through `Invoke-NativeCommand`, then pointed `IconLocation` at the result:

```
call-operator returned after : 476 ms
LASTEXITCODE                 : 0          <- false success
icon exists IMMEDIATELY after: False      <- shortcut points at nothing
icon exists after 6s         : True
```

A shortcut with a blank icon, reported as success. Now uses `Start-Process -Wait -PassThru` and verifies the file exists before use. Same class as the earlier `$argumentsLiteral` and `.Count` installer failures: parse-clean, runtime-broken, reports success.
