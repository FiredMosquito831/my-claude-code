## Description

A pause click cost seconds, and none of that work had anything to do with pausing. It now costs the write and nothing else. Separately, one entry in the 6.34.0 quota classifier was a bare word and had to go.

## What a pause was actually doing

`_apply_admin_config_locked` called `ProviderRuntimeManager.replace()` without `background_refresh`, which defaults to `True`. Every admin write — a pause included — therefore rebuilt every provider client and scheduled a full `/models` sweep. A pause is read off `Settings` at plan time (`routing.py`, `_paused_for`) and never reaches `create_provider`, so none of that work can change what a pause does.

The sweep also blocked the event loop. `ProviderModelDiscovery._refresh_model_infos` resolved each provider inside a loop with no `await` in it: an SSL context and an HTTP client per provider, entirely synchronous, and the task did not reach a suspension point until the whole loop had run. So `_cancel_refresh`'s `task.cancel()` could not land until the sweep it was abandoning had finished, and click N+1 paid for click N — which is where the alternating fast/slow pattern in the user's `server.log` came from.

## The changes

**`background_refresh` is computed from the update, at the call site.** The decision is a manifest fact, not a key list written at the caller: `ConfigFieldSpec` gains `affects_providers: bool = True`, the six `MODEL_*_PAUSED` fields declare `False` beside their own label and help text, and `update_affects_providers()` answers `True` for any key the manifest does not own. A key added tomorrow is slow-but-correct rather than fast-but-wrong. The generation swap itself is **kept** — it costs under a millisecond and it is what makes a pause visible to the very next plan.

**`await asyncio.sleep(0)` per provider in the discovery resolve loop**, so a sweep never holds the event loop for its whole length and a cancel can land inside it. This helps every config apply, not only a pause.

**Two UI defects.** A failed pause reported only into `#messageArea` at the top of the page; the pause control's own panel (`#routeStatus`) said nothing and the row snapped back with no explanation. It now announces `Could not pause <ref> on the <route> route -- nothing changed. <reason>` in that panel, with no Undo button (nothing happened, so there is nothing to undo) while keeping the `#messageArea` message. And Undo passed `button: null`, leaving the row's own toggle live during its POST; it now passes the originating button, so the same disable guard covers both writes.

Driven in Chrome against the scratch server, three screenshots in `screenshots-pause-fix/`, **zero console errors**: a successful pause, a forced-500 pause showing the failure sentence in `#routeStatus` with the row back to `Pause`/not-paused/re-enabled, and an Undo held open mid-POST with the row toggle `disabled: true` (re-enabled and re-paused after release).

Kept unchanged on purpose: the disable-during-flight guard, the in-place patch instead of a refetch, and the dirty-drag isolation were already correct.

**Pause semantics are untouched.** Pause stays per rail. The USAGE and in-app Guide now say so plainly — *pausing an entry on one route does not pause the same model on other routes* — rather than changing what the button means.

## `QUOTA_PHRASES` no longer contains the bare word `billing`

The condition on the 6.34.0 classifier was no false positives, and one bare word cannot meet it: `billing` matches *"see our billing documentation for limits"* in an ordinary 400, which would classify a merely malformed request as `quota` and bench the whole key pool. It is removed and **not** replaced: no measured provider body was on hand to justify a narrower `billing ...` phrase, and the rule this list already states is that an entry needs one. The comment block now records why it must not come back. README and USAGE phrase lists updated.

## Residual risks

1. **The provider-inert set is exactly the six pause keys.** `MODEL`, `MODEL_*_FALLBACKS` and the visibility keys still trigger a full rebuild and sweep, deliberately: they can name a provider whose catalogue is not cached, and being wrong there is worse than being slow. If the user wants route edits fast too, that is a separate, better-evidenced change.
2. **`await asyncio.sleep(0)` changes cancellation timing for every config apply**, not just pause. It is the correct change and it has its own test, but it touches a shared path.
3. **The event-loop stall is now prevented, not measured.** I did not drive `/v1/messages` concurrently with a pause before and after; the mechanism is confirmed from the code and the yield removes it, but the stall itself was never timed.
4. **The scratch numbers are this machine's.** The scratch env carries a fake key for all 52 credential-bearing providers, so its sweep is broader than the user's live 17-19 and the before-figures are correspondingly larger than the ~2 s in the original investigation. The after-figure — zero provider work per click — is the transferable one.
5. **Nothing was verified against the live 8082 server**, which was read-only throughout and never restarted. The measurements are the scratch server's.
