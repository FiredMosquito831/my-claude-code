## Description

## What was wrong

Two `innerHTML` template sinks rendered manifest-provided strings (custom-provider display_name among them) as HTML — a stored-injection path inside the loopback-only dashboard. A full audit of all 47 innerHTML sites confirmed these were the only two interpolating untrusted data.

## The fix

Both sinks converted to createElement/textContent (matching renderProviderCard's existing pattern). Plus: a reusable **jsdom XSS harness** (204 lines) executing the real admin.js against malicious payloads asserting text-only rendering, a pytest contract wrapper (8 tests) so it runs in CI, and a static guard enumerating every remaining allowed `innerHTML` site. Bonus surface: renders the new `messaging_auth_open` config field as a warn notice when non-empty (companion to the messaging-auth PR).
