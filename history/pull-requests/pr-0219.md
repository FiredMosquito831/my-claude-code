## Description

# What goes on the wire is now decided by two facts, not one

Reasoning controls used to be chosen from what the **model** supports alone. What the **host in front of it actually parses** was never asked, so a control could be sent into a field the gateway does not read, or dropped because the model had no knob while the host had a perfectly good one. This PR makes both facts required, and makes every adaptation say which field the request actually left through.

## What was wrong

**Gating read the model's knobs from a self-contradictory vote.** For `commandcode/minimax/minimax-m3-free` the cross-provider record resolved `supports_effort_control=False` from **one** row at tier 5 *and* `supported_efforts=[high, low, medium]` from **twelve** rows at tier 8 — because booleans needed 1 reporter and vocabularies needed 3. Gating believed the veto, returned `ReasoningPolicy.on()`, and logged `REASONING LEVEL DROPPED … discarding effort 'max'`.

**The encoder then re-invented a rung.** Command Code's `NamedEffortReasoning(_EFFORTS, enabled_value="max")` has no on/off field, so "thinking on" became `reasoning_effort: "max"`. Correct only because the user happened to ask for `max`; `REASONING_SONNET=low` would still have sent `max`. Thirteen other providers share that shape (groq / cerebras / sambanova / nararoute fall through to `medium`; cohere / wafer / deepinfra / ollama / ollama_cloud / fireworks to `high`; nebius to `xhigh`), and gemini, opencode and llamacpp emit **nothing at all** for the same policy while the log still claims thinking was enabled.

**Encoders fell through to their own default for an out-of-vocabulary effort.** `efforts.get(policy.effort)` missing meant `enabled_value`, so a request for `max` against a `low/medium/high` host left as groq's `medium` — a level *below* the ask, not the nearest one at or under it.

**The one per-model statement a gateway makes was parsed and thrown away.** `nous_portal` publishes `reasoning_effort` in `supported_parameters` for `tencent/hy3:free` and not for `meituan/longcat-2.0:free` — one gateway, two dialects — and `model_listing.py` read that list only to set `supports_thinking`.

**And there was no reference rung.** Tiers 5–8 went straight from the provider's own bucket to a vote across every models.dev bucket. OpenRouter spells tags `vendor/model:free` and Command Code spells them `vendor/model-free`, so `minimax/minimax-m3-free` could never match `minimax/minimax-m3:free` except by losing its tag entirely.

## The mechanism

A new `ReasoningDialect` (neutral, in `core/reasoning.py`) states which reasoning **fields** one host parses for one request: an effort field and the words it takes, an on/off field, a budget field, an OFF spelling, an adaptive channel. Every encoder and every provider that builds its own body declares one; the provider manager narrows it per model by the gateway's own `supported_parameters` where one is published (narrowing only — a gateway advertising a field the profile cannot emit is a profile gap, logged, not a runtime guess).

Gating now emits a control only when **the model has that knob and the host has a field for it**. Otherwise the nearest thing both can express goes instead, and the adaptation names the field — or says plainly that nothing is being sent.

Two subtleties worth calling out:

- **A host's on-value written into its own effort field is a default rung, not an on/off switch.** So a toggle-only model behind an effort-only gateway now sends *nothing* and lets the model's own default stand, instead of answering a request for `low` with the gateway's `max`.
- **An encoder's effort map is not a vocabulary.** Cohere sends `"high"` for all six rungs; Gemini folds `xhigh`/`max` onto `"high"`. A dialect declares the rungs the host spells under their own name, so the flattening is recorded as a clamp instead of vanishing. `providers/reasoning_vocabulary.py` — a hardcoded table of exactly those two hosts — is deleted and its facts now live in those hosts' dialects.

Supporting changes: an **OpenRouter reference rung at tiers 5–6** (one curated catalogue outranks a vote across strangers, never outranks the host's own answer) with `-free` ⇄ `:free` tag respelling; the ladder is now **11 rungs**; boolean quorum **1 → 3**; a vocabulary and an effort flag reconciled as one statement; `supported_parameters` read as capability; and an unrecognised client effort string now logs `REASONING EFFORT IGNORED` instead of being swallowed.

## Known and deliberate

- Where MCC has neither fact, gating is **byte-identical** to before — pinned by a capability × policy matrix that runs both paths and compares.
- `reasoning_request_baseline.json` did **not** move. That baseline bypasses gating entirely, and no encoder-clamp cell changed, so no re-baseline was needed and none was done.
- PR C owns the wire-side wording around `formatReasoningEmitted`; untouched here.
- Vertex now declares a dialect (its Google thinking-config encoder); Cloudflare, LM Studio and GitHub Models keep `None`, which behaves exactly as before.
- Dialects narrow but never widen. A gateway advertising a field the profile has no code for is a profile gap, logged at DEBUG.

## Residual risks

1. **A dialect that undersells its encoder suppresses a control the gateway would have honoured.** Mitigated by a sweep that encodes every policy shape against every profile and asserts the emitted fields are a subset of what the dialect claims, plus a second sweep asserting every declared rung actually changes the body — but a wrong *host* claim (as opposed to an inconsistent one) is only caught by a live probe.
2. **Tier renumbering changes the numbers shown on the Models page** and in the cross-provider log line. Nothing persists a tier number, so this is display and log text only.
3. **Boolean quorum 3 makes some capabilities unknown that used to be stated** off a single row. Unknown never adds a restriction, so the effect is more requests passing through untouched rather than fewer — but a model whose only evidence was one row now resolves as unknown.
4. **`providers/reasoning_vocabulary.py` is removed.** Mistral and Cohere now clamp through their dialects instead. Mistral's `{high}` is declared on the provider; Cohere's is derived from its encoder map. A future Cohere profile that gave its efforts distinct wire values would silently widen that vocabulary.
5. **`model_reasoning_dialect` constructs a provider on first use** for a provider the request path has not touched yet. One-off, cached by `ProviderRuntime`, and any construction failure degrades to unknown.
6. **The two probes above are unverified end to end**, for the reasons stated.
