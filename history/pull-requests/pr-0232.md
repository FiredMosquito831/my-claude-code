## Description

## What was wrong

`req_dfc8ac9da90d458fa5dc396b8eed0b1d` (2026-08-31 01:01Z, 6.13.0) reached Claude Code as a **400 `context_length`** — 496k tokens asked of a model holding 262k. Every model on that route that *could* have held the prompt was `skipped ejected "benched after recent consecutive failures"`: kimi-k3, glm-5.3-flash, minimax-m3-free, deepseek-v4-flash. `chatgpt_oauth` was `unavailable` (no credentials), and the request was answered by the one model left standing.

Ejections in the three hours before it: nemotron-ultra **238**, kimi-k3 **201**, minimax-m3-free **193**, glm-5.3-flash **145**.

## Mechanism

`RouteHealthRegistry.record_failure()` counted **every** failure. A ~330k-token prompt 400s identically on every model, so eight of those per model crossed the operator's own rate window (`FALLBACK_EJECT_WINDOW=10`, `FALLBACK_EJECT_FAILURE_RATE=0.5`, `FALLBACK_EJECT_MIN_SAMPLES=8`) and benched the whole chain for 30s. The models tried first — the ones with the largest context windows — were benched first. NIM's 429s fed the same counter.

The bench was measuring the **request**, not the model. And the skipped row said "benched after recent consecutive failures" on a build whose default mode has been `rate_based` since 5.61.0, so the one line the reader got was about a counter that was never consulted.

## What changed

1. **`FALLBACK_BENCH_ENABLED` ships `false`** — new `FALLBACK_BENCH_ENABLED_DEFAULT` constant, `Settings`, manifest default and help, README / USAGE / in-app Guide. It went `false`→`true` in 5.61.0; a guard that *removes capacity* is opt-in. **A default only applies where the key is unset**: an install with `FALLBACK_BENCH_ENABLED=true` written into `~/.fcc/.env` keeps benching on until the line is removed (the field's *set here* chip says so).

2. **Only model-shaped failures count.** `failure_counts_toward_bench(kind: FailureKind) -> bool` beside `RouteHealthRegistry`, backed by an allow-list `BENCH_COUNTING_KINDS = {UPSTREAM, OVERLOADED, AUTHENTICATION, PERMISSION}` — the same allow-list-not-deny-list shape `CREDENTIAL_SHAPED_KINDS` uses. `record_failure()` consults it and returns early otherwise, logging at DEBUG what it ignored. `TIMEOUT` (first-token / stall / budget), `RATE_LIMIT`, `CONTEXT_LENGTH`, `INVALID_REQUEST` and the executor's own `UNAVAILABLE` sentinel never bench. Success still clears the counters.
   *Consequence:* 429s no longer bench, so the rate-limit bench-duration branch (and `_provider_retry_after`, its only caller) had no reader left and is deleted rather than left unreachable.

3. **The skipped row says why.** `registry.why(model_ref) -> BenchReason | None` = `{mode, failures, window, rate, last_kind, last_status, remaining_seconds, since}`. The executor writes it into the skipped attempt's `params.bench` (nested beside `wire`/`ladder`) and into `error_message` as *"benched: 5 upstream errors in the last 10 attempts (rate_based >= 50%), 22 s left"*. The request-detail modal renders the breakdown (`createElement`/`textContent` only) and the chain panel counts *"N models were benched and never tried on this request."* No new column.

4. **Master switch on Model Config.** The same `FALLBACK_BENCH_ENABLED` renders at the top of the routing view with the sentence *"Tuning (window, rate, duration) lives on Limits & Resilience → Chain benching"* as a view-switching link — the `FALLBACK_SKIP_KINDS` cross-link pattern in reverse. **One manifest field, one section, one saved key**; the two controls are mirrored by `syncSharedControls`. The Limits card keeps its copy and gains a link back.

## Deviations from the brief

- **`.env.example` is denied in this environment.** Tried once, refused; its `FALLBACK_BENCH_ENABLED` comment still names the old default. Reported, not routed around.
- **Empty/no-output does not bench.** The 5.50.0 "model only thinks" / produced-nothing outcomes are all `_timeout_failure(...)` → `FailureKind.TIMEOUT` today. The predicate's signature is kind-only, and the brief says timeouts must not count, so they do not. Splitting that outcome into its own kind is the prerequisite for counting it and is deliberately out of scope — said so in the predicate's docstring.
- **"N models were benched" is a chain-level line in the request detail**, not a clause inside the stored 6.12.0 `ladder_root_cause`. That sentence is computed per attempt from that attempt's ladder and only renders when `tries > 1`; an attempt that was *benched* has no ladder at all, so it could never have carried it.
- **Two loguru lines fixed in passing.** `route_health`'s two `MODEL EJECTED` warnings used `%s`/`%d`/`%g` against loguru's `str.format`, printing the template literally. Found by the verification run; fixed in the function this PR already rewrites.

## Residual risks

- **The default cannot reach an install that already wrote the key.** `FALLBACK_BENCH_ENABLED=true` in a managed `.env` keeps benching on. This is the 6.1.0 lesson and it is deliberate — a value on disk is effective configuration — but it means the users hit hardest by the incident (the ones who have pressed Save) are the ones the new default does not reach. Called out in the field help, the Guide, USAGE, README and the release notes.
- **`AUTHENTICATION`/`PERMISSION` count towards the route bench** at the user's explicit request. They also charge the *credential* pool (`CREDENTIAL_SHAPED_KINDS`), so a genuinely bad key is now penalised in two places. The two benches have separate clocks and separate scopes (model-ref vs key), so nothing compounds silently, but a route whose key is wrong will be benched as well as its key.
- **A model failing only with timeouts is never benched again.** That is the intent — a deadline is a share of the request's clock — but a genuinely hung model now costs its share on every request instead of being parked. `FALLBACK_ATTEMPT_SHARE_FLOOR` and the first-token deadline are what bound that cost.
- **Two controls for one value.** Mirrored on edit and asserted in both jsdom and the browser, but it is still the only field this project renders twice; a future renderer that builds a control without going through `buildFieldControl`/`syncSharedControls` would re-open the divergence.
- **`params.bench` is a new shape in a JSON column.** Old rows have no `bench` key and render exactly as before; the modal guards on `typeof bench === "object"`.
