## Description

Fixes the failure mode behind "it tried to install Pi and then nothing worked". 4.15.0 -> 4.16.0 (MINOR).

## The bug

The main flow was:

```
claude -> codex -> pi -> uv -> Free Claude Code
```

and every failure path in those first three calls `fail()`, which is `exit 1` (PowerShell: `throw` under `$ErrorActionPreference = 'Stop'`). So a missing `npm`, an offline mirror, a slow network, or an unrelated `pi` already on PATH aborted the script **before Free Claude Code was ever installed** — the one thing the script exists to do.

Pi is the most likely trigger: it installs via npm, and `verify_pi_command` also hard-fails if the installed `pi` isn't the Pi Coding Agent.

## The fix

Order is now:

```
uv -> Free Claude Code -> (claude, codex, pi)  [each optional]
```

Each agent runs through a wrapper that downgrades failure to a warning — a subshell in `sh`, `try/catch` in PowerShell — and the summary lists what was skipped and states the proxy works without them. Adds `--skip-agents` / `-SkipAgents`.

**The original safety property is preserved:** an existing incompatible `claude`/`pi` on PATH is still never silently replaced. It just no longer aborts.

## Test changes

`test_install_{sh,ps1}_rejects_broken_existing_client_without_replacing_it` encoded the old contract (exit non-zero, no downloads). Replaced with tests asserting the new one, plus new coverage:
- broken agent -> exit 0, FCC still installed
- `--skip-agents` skips all three and still installs FCC
- **ordering**: the wheel is downloaded before any agent is touched

## Docs

Rewritten install tutorial: per-platform steps, explicit warning against installing in **both** PowerShell and WSL (two configs, one server), the reopen-your-terminal PATH note, what the installer does and in what order, and a troubleshooting table keyed by symptom.

## Verification

Dry-run and `--skip-agents`/`-SkipAgents` exercised on both scripts; `sh -n` and the PowerShell parser both clean; ruff/ty pass. The POSIX installer tests only run on Linux, so CI is the real gate for those. v4.16.0 tag and wheel are published so the pinned URL resolves.
