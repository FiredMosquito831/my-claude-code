## Description

The Providers tab rendered every provider as one flat field grid in catalog order: **76 visible inputs**, no grouping, no search, and a provider's key, base URL and proxy scattered across the same undifferentiated grid rather than sitting together. Tolerable at 12 providers; not at 35.

## What replaces it

Each provider gets a **card** carrying its own status pill, credential env name and its own fields — including a per-card "Advanced options" fold for proxy and base URL, instead of one section-wide advanced toggle that revealed everything at once.

Cards sit in **collapsible groups** driven by the catalog metadata added in 4.38.0: coding plans, model providers, inference platforms, gateways, local runtimes, custom. Each group summary carries a configured count and a rail of status dots that double as jump links.

Above them: a **search box** matching display name, provider id, credential env var and base URL, plus a **Configured only** toggle. Searching `alibaba` narrows 35 cards to 4.

**Ordering answers the common question first.** Configured providers sort to the top of their group, then missing-key, then unknown. The first group with anything configured opens by default, so the page never lands fully collapsed with no way in.

The separate provider status strip is **gone** — it was a second place to read the same status. Now every card carries its own pill.

**Web Search** gets the search box and the same filter, and nothing else. Ten providers already rendered as cards there; a second card system would have been change for its own sake.

## Filtering hides, never detaches — this is load-bearing

`changedValues()` finds fields by walking `[data-key]` across the document. An input removed while filtered would silently stop being saveable — the exact defect that made fallback chains unusable from 4.31.0 until 4.34.1. So filtering sets the `hidden` attribute, which also removes the element from the tab order, so a filtered-out card cannot trap keyboard focus.

## Residual risks

- **None of this has been rendered in a browser.** There was no browser tooling in this session. jsdom proves structure, wiring and the DOM invariants; it says nothing about how any of it *looks*. The three things most likely to need a second pass: spacing/density inside a card, the dot rail at ~10 dots, and the card grid at narrow widths.
- The group taxonomy is a judgement call. NVIDIA NIM is filed under "Inference platforms" rather than "Model providers"; Ollama Cloud likewise. Reasonable people could file those differently — it is one line in the catalog to move.
- Group summary counts do not update while a filter is active; they always describe the unfiltered group.
