## Description

Backend for turning **Configure Claude Code** from a two-key connect screen into a real settings editor. No UI yet — the page lands in the next PR.

## What it does

Built on the generated catalog from #114, so the editable surface tracks upstream instead of drifting: **518 entries**, each carrying the control it wants (`toggle`, `select` + option list, `number`, `path`, `list`, `JSON`, `secret`).

| Route | Purpose |
| --- | --- |
| `GET /admin/api/claude-config/catalog` | what Claude Code can be configured to do |
| `GET /admin/api/claude-config/document` | what this machine's settings file says |
| `POST /admin/api/claude-config/plan` | what a set of edits *would* change |
| `POST /admin/api/claude-config/apply` | make those edits |

## The three traps, enforced in code

A naive editor does the **opposite** of what the user asked on these, so they're handled server-side rather than left to the UI:

- **Six presence-read variables.** Writing `"0"` to `DISABLE_TELEMETRY` leaves telemetry *off*. A request to set one falsey is **rewritten into a key removal**, with a warning explaining why.
- **`FORCE_HYPERLINK` is parsed as a number**, so `"false"` enables hyperlinks. Setting it to a word is **rejected**, pointing at `0`.
- **Ten credential variables** are masked on the way out.

## Write safety

Two-stage. `plan_changes` touches no disk — resolves each request against the catalog, records `before`/`after`, attaches warnings. `apply_plan` writes only what the plan said, **after re-reading the file**: a plan the user reviewed for a minute must not clobber an edit made meanwhile. Backup taken once, atomic `os.replace`.

Two smaller correctness points, both with tests that fail without them:
- Unsetting the last key under `permissions` **removes the empty parent** — Claude Code treats `{}` and absent identically, and a leftover `{}` makes the file look configured.
- Keys the catalog doesn't know are read and written **verbatim** — upstream adds settings weekly, and silently hiding one would misreport the file.

## Path guard

Any path that isn't a Claude Code settings file is refused: must be absolute, named `settings.json` / `settings.local.json`, inside a `.claude/` directory. An admin endpoint that writes JSON anywhere on the box is a different and much larger thing than a settings editor.
