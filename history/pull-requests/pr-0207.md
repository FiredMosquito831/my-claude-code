## Description

## What was broken

Capability and limit lookup for a model had two paths: the provider's own bucket in models.dev, or — when models.dev has no bucket for that provider — an approximate match by model name across every other provider's bucket.

**The cross-provider path did no tag stripping and no vendor-prefix stripping**, so a tagged model id matched almost nothing:

```
_normalize_candidates("minimax/minimax-m3-free") -> ['minimax-m3-free', 'minimax/minimax-m3-free']
_normalize_candidates("tencent/hy3:free")        -> ['hy3:free',        'tencent/hy3:free']
```

Neither `-free` nor `:free` came off. The tag allow-list lived in `_lookup_in_bucket`, which only runs when a bucket **exists** — i.e. never on the path that needed it. And a one-sample result was reported as authoritative:

```
APPROXIMATE cross-provider match for minimax/minimax-m3-free:
  matches=1, output limit 1048576 (100% agreement), efforts unknown
```

1,048,576 off a single row. "100% agreement" because one sample always agrees with itself. The true modal output limit for that model is 512,000. The missing effort vocabulary is also why the model fell through to toggle-only in reasoning gating.

## Mechanism

One normaliser now owns id shape (`core/model_ids.py`): the allow-listed pricing/routing tags, tag stripping across both `:` and `-` separators, and the rung order. `_normalize_candidates` and `_tag_stripped_candidates` are gone — nothing has a private idea of what a model id is any more.

Resolution walks an explicit ladder. Each rung loosens exactly one thing, **tag before vendor prefix** (`ResolutionTier`, 1-9), and stops at the first rung that answers:

| # | source | scope | id form | for `commandcode/minimax/minimax-m3-free` |
| --- | --- | --- | --- | --- |
| 1 | provider `/models` | that provider | exact | `minimax/minimax-m3-free` |
| 2 | provider `/models` | that provider | tag stripped | `minimax/minimax-m3` |
| 3 | models.dev | provider bucket | exact | `minimax/minimax-m3-free` |
| 4 | models.dev | provider bucket | tag stripped | `minimax/minimax-m3` |
| 5 | models.dev | cross-provider | exact | `minimax/minimax-m3-free` |
| 6 | models.dev | cross-provider | tag stripped | `minimax/minimax-m3` |
| 7 | models.dev | cross-provider | bare + tag | `minimax-m3-free` |
| 8 | models.dev | cross-provider | bare model | `minimax-m3` |
| 9 | — | — | — | the caller's own default |

Three properties:

1. **Field by field, not source by source.** Each field walks the rungs independently, so a gateway that publishes `max_completion_tokens` but no `reasoning` takes its limit from tier 1 and its efforts from tier 6. This extends the existing `merge_reasoning_capabilities` / `_first_stated` merge rather than replacing it.
2. **The rung is carried back.** `model_output_limit_tiered`, `model_reasoning_capability_tiered` and `ProviderModelCache.cached_model_info_tiered` return it; `ResolutionTier.is_approximate` / `.is_authoritative` classify it. The admin Models page renders the real per-field tier in place of its coarse three-way split.
3. **A minimum-sample guard on the approximate rungs.** Numeric limits and effort vocabularies need **3** reporting rows; booleans need **1**.

### Why those thresholds

- **Numbers and vocabularies: 3.** One reporter is a transcription, not a vote, and always agrees with itself — that is exactly how 1,048,576 got shipped at "100% agreement". Two cannot break a tie from evidence. Three is the smallest sample where the modal value can be a real majority rather than an arbitrary pick. Below it the field is **unknown** and the caller falls through to its own default.
- **Booleans: 1.** Across the live index, same-named rows are near-unanimous about whether a model reasons at all (28/28, 32/32, 50/51), because that is a property of the model. A limit is a property of the *deployment* — the same model is 512,000 on most hosts and 16,384 on NVIDIA. So the guard differs per field, not per tier.

**Tier 2** is the rung that did not exist before: a tagged model whose own host publishes limits under the untagged name used to skip straight past it into a stranger's catalogue.

The log line now names the rung that answered each field, the rows behind it, and the real agreement — and says `withheld: 1 of the required 3 rows reported one` instead of inventing a ratio.

## Residual risks

- **Hyphen tag stripping is new.** `-free`, `-paid`, `-nitro`, `-floor`, `-online`, `-extended`, `-discounted` are now stripped from the last path segment, where before only the colon form was. A real model whose name genuinely ends in one of those seven words would now also match its untagged sibling. The allow-list is deliberately narrow and excludes everything that changes reasoning behaviour (`:thinking`, `:low`/`:medium`/`:high`/`:max`, numeric budget tags), which is pinned by test.
- **`paid` is a new allow-list entry**, added because `tencent/hy3-paid` returned nothing at all before. It is a routing word in every observed use.
- **Tier 2 changes real answers.** A gateway listing `minimax/minimax-m3` while routing `minimax/minimax-m3-free` now takes that gateway's own limit instead of falling through to models.dev. That is the intended direction (the model's own host outranks a stranger), but it is a behaviour change on live traffic, not just a widening.
- **The guard can now return unknown where a number used to be returned.** By design — the number it replaced was a single unverified sample — but a caller relying on the old value now falls through to its own default.
- `match_count` on `CrossProviderMatch` is now the rows at the rung that answered the *output limit* (falling back to the tightest matched rung), so the admin's "guessed from N same-named rows" no longer contradicts the agreement ratio printed beside it.
