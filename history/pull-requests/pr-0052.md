## Description

Adds Qwen access through Alibaba Cloud Model Studio (Bailian), and gives the provider catalog the grouping metadata the Admin UI needs now that there are 35 providers.

## Why four providers and not one

Alibaba splits Qwen access along two axes at once, and **both are credential boundaries**:

| Provider | Endpoint | Key |
| --- | --- | --- |
| `alibaba_coding` | `coding-intl.dashscope.aliyuncs.com/v1` | `sk-sp-...` subscription |
| `alibaba_coding_cn` | `coding.dashscope.aliyuncs.com/v1` | `sk-sp-...` subscription |
| `alibaba` | `dashscope-intl.aliyuncs.com/compatible-mode/v1` | pay-per-token |
| `alibaba_cn` | `dashscope.aliyuncs.com/compatible-mode/v1` | pay-per-token |

A Coding Plan key is rejected by the pay-per-token endpoints, and a key issued for Singapore is not valid in Beijing. Collapsing either pair would hand a request a credential its endpoint refuses — the most commonly reported Alibaba misconfiguration. Each provider also takes a base URL override, so the US region and workspace-scoped endpoints (`{WorkspaceId}.ap-southeast-1.maas.aliyuncs.com`) need no new code.

Alibaba publishes an Anthropic-protocol path (`/apps/anthropic`) on the same coding hosts. FCC uses the OpenAI-compatible one because that is the dialect it speaks upstream, so no Anthropic passthrough is needed.

## Reasoning: read, never requested

The profiles replay `reasoning_content` from the stream but do **not** send DashScope's `enable_thinking`, which some models on these endpoints reject outright — and the Coding Plan roster proxies third-party models (GLM, Kimi, MiniMax) that cannot be tested without a subscription. An unsent control costs thinking on some models; a wrongly-sent one fails every request. `extra_body` passes through, so a user who knows their model accepts it can send it themselves. Same narrow-rather-than-wide choice made for Cline.

## Catalog grouping

`ProviderDescriptor` gains `group`. The admin config response gains `provider_groups`, a `provider` id on every field in the providers section, and `group` on each `provider_status` entry. **Nothing consumes them yet** — the Admin UI lands separately.

The providers section currently emits **91 inputs into one flat grid**, so the association between a provider and its key, base URL, proxy and rotation fields is the structure that view has been missing.

`group` defaults to empty rather than to a plausible value, so a provider that forgets to declare one fails a test instead of quietly filing itself somewhere wrong.

## Verification

All four endpoints were probed live **before any code was written**:

```
coding.dashscope.aliyuncs.com/v1/chat/completions        POST 401 {"error":{"code":"invalid_api_key",...}}
coding-intl.dashscope.aliyuncs.com/v1/chat/completions   POST 401 {"error":{"code":"invalid_api_key",...}}
dashscope-intl.aliyuncs.com/compatible-mode/v1/models         401 OpenAI-shaped error body
dashscope.aliyuncs.com/compatible-mode/v1/models              401 OpenAI-shaped error body
```

That probe corrected two things the sources disagreed on: the international coding host appears only in third-party write-ups and **is** real; and the plausible-looking `token.dashscope.aliyuncs.com` hosts do not resolve at all (curl exit 6 — a command that fails is not a command that found nothing).

All four instantiate through the real factory with the expected base URLs, and an `ALIBABA_BASE_URL` override was confirmed to take effect:

```
alibaba              https://dashscope-intl.aliyuncs.com/compatible-mode/v1/
alibaba_cn           https://dashscope.aliyuncs.com/compatible-mode/v1/
alibaba_coding       https://coding-intl.dashscope.aliyuncs.com/v1/
alibaba_coding_cn    https://coding.dashscope.aliyuncs.com/v1/
override honored:    https://myworkspace.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1/
```

The catalog enforcement points caught the missing README rows and the frozen order exactly as intended. The new group guards were checked by breaking what they guard — removing one provider's `group` makes them fail by name, rather than merely being observed passing.

```

```

Those 6 are the documented PowerShell installer baseline and fail identically on unmodified `main` in the same shell. (The usual 8 websearch failures were neutralised with `env -u ENABLE_WEB_SERVER_TOOLS -u EXA_API_KEY`; GitHub runners have neither variable.)

## Residual risks

- **No live chat completion against any of the four.** No key is available for either plan or either region, so model listing, tool calling and the `reasoning_content` replay are verified against the published shape only. The first user with a key is the real test.
- **The Coding Plan hosts 404 on `/models`**, so model discovery will not populate the picker for those two providers — same situation as Cline. The Token Plan endpoints do serve `/models` (401 without a key).
- Example model IDs in the README and smoke config (`qwen3-coder-plus`) come from Alibaba's documented roster, not from a live catalog read.
