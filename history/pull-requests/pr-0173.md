## Version: MINOR, not MAJOR — deliberately

The repo rule lists "removed env vars" under MAJOR, whose stated purpose is *"migrations users must act on"*. **There is no migration here, and that was verified rather than assumed:**

```
$ env -i HOME=/tmp/fresh FAST_PREFIX_DETECTION=true \
    ENABLE_NETWORK_PROBE_MOCK=false ENABLE_FILEPATH_EXTRACTION_MOCK=1 \
    uv run python -c "from ... import Settings; Settings()"
Settings() constructed OK with all three removed vars set
has fast_prefix_detection: False
```

`Settings.model_config` sets `extra="ignore"`, so a leftover key never raises. The keys toggled rules that have **never once fired**, so removing them cannot change any observable behaviour. Spending a major version on a no-op would make the versioning signal less useful, not more. Called out explicitly in the release notes instead. *(Owner's call, asked and answered.)*

**One real file effect:** `unmanaged_env_values()` preserves a key only if it is in the manifest, in `settings_env_aliases()`, or `FCC_`-prefixed. These are now none of those, so a stale line disappears from a user's `~/.fcc/.env` on their next admin Save. Harmless — it configured nothing — but it is a write to their file and the release notes say so.
