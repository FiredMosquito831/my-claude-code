## Description

4.22.0 added the cache columns but **nothing populated them for the providers most people actually use**. PATCH `4.22.0` → `4.22.1`.

## Why it showed 0

My capture only understood Anthropic-shaped fields (`cache_read_input_tokens`). OpenAI-compatible upstreams report cache hits under `usage.prompt_tokens_details.cached_tokens`, and the shared `_anthropic_usage_fields` returned `{}` — so NVIDIA NIM, OpenRouter, Novita and every other OpenAI-shaped provider reported 0 cached and 0.0% regardless of what the upstream said.

**Confirmed with a live NVIDIA NIM call**, not assumed:

```json
{"prompt_tokens": 1243, "completion_tokens": 2,
 "prompt_tokens_details": {"audio_tokens": null, "cached_tokens": 32}}
```

NIM does report caching. We were dropping it.

The lookup now lives in the shared OpenAI-chat base so the whole family gains it at once. DeepSeek keeps its override — it uses non-standard `prompt_cache_hit_tokens`/`prompt_cache_miss_tokens`.

## The rate maths was also wrong

`prompt_tokens` **already includes** the cached tokens (and DeepSeek's hit + miss likewise sum to the prompt total). 4.22.0 treated `tokens_in` as an *uncached* figure and added cache reads on top — counting them twice and understating the rate.

Corrected:

| | |
|---|---|
| Input (uncached) | `tokens_in - cache_read` |
| Cache hit rate | `cache_read / tokens_in` |

Against the sample above: **1211 uncached, 2.6%** — matching the upstream.

## Verification

Helper checked against the real NIM numbers plus boundaries:

```
NIM real sample -> uncached 1211 | hit 2.6%
no cache        -> uncached 500  | hit 0.0%
fully cached    -> uncached 0    | hit 100.0%
no data         -> uncached 0    | hit —
```

New tests cover the dict and SDK-object shapes, and assert a provider that doesn't report caching yields **no fields at all** rather than a fabricated zero — so "unsupported" stays distinguishable from "measured zero".

Full suite passes except the 14 failures that also fail on unmodified `main`.

## Residual risks

Only new traffic populates this. Existing rows keep `NULL`, so the dashboard will show a low overall hit rate until history turns over — the totals mix pre- and post-upgrade requests.

Cache *writes* remain unpopulated for OpenAI-shaped providers: the OpenAI schema has no cache-creation counter, so that card stays 0 for NIM. It's only meaningful for Anthropic-shaped and DeepSeek upstreams.
