## Description

## What was wrong

The dashboard's automatic update/restart was aggressive: a hard-coded 5-second
graceful-shutdown budget force-cuts healthy long requests on every handoff, and
the supervisor had no defense against a held port, an incomplete runtime close,
or a failed relaunch. On WSL this could leave the service unavailable or
apparently stuck on its port.

## What changed

- Add a bounded `Settings` field `SERVER_GRACEFUL_SHUTDOWN_SECONDS` (default
  300s, range 1-600s) surfaced through the Limits page. The default sits just
  over the measured p99.9 whole-request budget so most requests drain; the
  dashboard reconnect budget is composed from install + drain + startup instead
  of a fixed 120s.
- Supervisor restart requests are now priority-ordered so a self-update
  `REPLACE_PROCESS` cannot be downgraded by a later config-driven `RELOAD`.
- Process replacement is refused loudly (logged + `SystemExit`) when the runtime
  did not finish closing, instead of silently degrading to a clean stop.
- `os.execv` is wrapped with a logged recovery command on launch failure.
- Read-only port diagnostics (probe, bounded wait, `ss`/`netstat` owner lookup)
  and a held-port gate before rebind; never kills an unrelated owner.
