## The report

> "the models page is a bit weird and unstable regarding hide/show and multi select — the hide button tick when unticked doesn't change to show or the other way around; there seem to be 2 overlapping functions for showing/hiding: the proper one where I select the models in the tick then alter it (one or more at once), and a per-model tick that does nothing or is forced by the show/hide logic."

Every clause of it was correct.

| What was said | What it was |
|---|---|
| "the tick when unticked doesn't change to show" | The single-write repaint set `tick.checked` and never touched the word; the bulk repaint set both. Same row, two behaviours. |
| "2 overlapping functions" | A per-row checkbox POSTing `/visibility/toggle` then re-reading the 3.4 MB catalogue, and a select column POSTing `/visibility/bulk` and patching the payload in place. Two owners of one state. |
| "a per-model tick that does nothing" | An exact pattern cannot beat a broader glob. The box was bound to the *recomputed* visibility, so it sprang back, explained only by a toast that would not name the glob. |
| "or is forced by the show/hide logic" | `Hide all` wrote `provider/*` **and deleted every exact pattern under it**, so `Show all` could not restore the per-model choices — they were gone, not shadowed. |

Measured on the reporter's install (`GET /admin/api/model-admin`, 2026-09-01): **1,120 models, 990 hidden, 994 exact deny patterns, 0 globs** — a ~30 KB single line in the managed env file, parsed, folded and rewritten on every tick.

## What changed

**One write path.** The select column plus the action bar is the only way this page changes what the catalogue shows — for one row exactly as for three hundred. A single row goes out as a one-element `refs` through `apply_visibility_bulk`. One endpoint (`/admin/api/model-admin/visibility/bulk`), one repaint (`applyModelsBulkResult` → `refreshModelRows`). `toggleModelVisibility`, its refetch and the divergent `refreshModelRow` are deleted.

**The second checkbox is a readout.** `Shown` / `Hidden` / `Hidden by <pattern>` — a state, never a verb. It is fed by a new `hidden_by` field that the page payload and the bulk result both compute through one function, `hiding_pattern`, so a row a glob dictates says so *every time it is drawn* rather than once in a toast. The pattern is a button: it scrolls to the editor that owns it and offers to remove it, confirmed in place and undoable. A row a glob dictates must not present an affordance that cannot change it — and must not be a dead end either.

**Hide all shadows; it no longer deletes.** Writing `provider/*` leaves the exact patterns beneath it alone, so the first `Show all` lifts only the glob and the per-model state comes back exactly. A second `Show all` clears those too. Hide all → Show all is an identity.

**A 100 %-provider selection is offered a glob, never given one.** `Hide all as one pattern, opencode/*` appears in the bar when the selection covers every model a provider publishes.

**"Migrate exact patterns to globs"** folds every wholly hidden provider into one `provider/*`. Previewed first, verified ref by ref that it hides exactly the same models, abandoned whole if it would not, and undoable.

**Also:** the bar says how much of the work is already done (`Hide 3 selected (2 already hidden)`) instead of growing a tri-state control; `/visibility/toggle` still exists for API callers and now names the blocking pattern.

## Residual risks

- **A `provider/*` written by the migration is a policy, not a snapshot.** It will also hide models that provider publishes later. That is the point of a glob and the preview says so, but it is a behaviour change over time that the identity check (which is about *now*) cannot cover.
- **The migration drops exact deny patterns naming refs that are no longer in the catalogue**, if they sit under a provider being folded. Visibility is unaffected — the glob covers them if they return — but the literal pattern text is gone. The Undo record carries it back.
- **`Show all` is now two presses to mean "show everything"** on a provider that has a glob: the first lifts the glob, the second clears the exact patterns. The panel says which happened, and it is what makes Hide all reversible, but it is a changed gesture for anyone used to the old one.
- **D6 (a late single-toggle response clobbering a newer bulk result) is moot rather than fixed.** There is only one write path now, so the race has no second participant. It was never reproduced in the investigation either, and it stays [S].
- **jsdom cannot prove layout.** The row's grid was checked in a real browser (`32px 55.86px 896.14px`, still three columns) precisely because it cannot.
- **The browser drive used an emulator, not the app.** The rules it ran are the real imported functions and the payload is the real catalogue, but the settings-commit path (`apply_admin_config`, the config lock, the restart bookkeeping) is exercised only by the Python route tests, not by the browser.
