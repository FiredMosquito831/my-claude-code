## Description

Second follow-up to #280, after #281. The re-dispatched shell build for
v6.45.2 got further: all four legs green, the image built, the snapshot taken,
the volume mounted, the `.app` found, the `/Applications` symlink found — and
then:

```
  ok: attached read-only at /var/folders/.../volume
DMG SMOKE FAIL: the image root is 'Applications,My Claude Code.app,', not exactly the app and the symlink
```

**The image was right. The assertion was wrong.** It compared an `LC_ALL=C`
sorted, comma-joined listing against `"My Claude Code.app,Applications,"`, and
`A` sorts before `M`. A correct artifact reported as broken is the worst way
for a check to fail.

## The fix

"And nothing else" is a count, not a string. The two members are already
asserted **by name** on the two lines immediately above (`[ -d "$app" ]`,
`[ -L "$mount/Applications" ]`, and the symlink's target). All that assertion
had left to say is that there is no third entry — so it counts:

```bash
entries="$(ls -1 "$mount" | wc -l | tr -d ' ')"
[ "$entries" -eq 2 ] || fail "the image root has $entries entries, ...: $(ls -1 "$mount" | tr '\n' ' ')"
```

`ls -1` rather than `ls -1a`: an HFS+ volume carries its own `.fseventsd` and
`.Trashes`, which are filesystem bookkeeping rather than anything this project
put in the image.

A contract test pins the counting form, so the comparison cannot come back.

## One hedge, while here

`hdiutil imageinfo -format` now falls back to parsing `Format:` out of the full
report if the option is ever rejected, so a changed `hdiutil` CLI surface is
not a red release.

## Progress so far, for the record

The dmg job is now proven to: download both legs' binaries, `lipo` them,
build the bundle, ad-hoc sign it, verify the seal, build a UDZO HFS+ image,
mount it read-only, and find the exact two things it should contain. What has
not yet run is everything from the `Info.plist` reads onward — the plist keys,
`spctl`'s expected rejection, the quarantine handling and the launch.
