## Description

## What was broken

The failover badge and panel added in 4.35.0 have been **rendering unstyled on main since 4.35.1**. Six classes were emitted by `admin.js` with no CSS rule at all:

```
fallback-badge           css:0  js-emits:1
fallback-route           css:0  js-emits:1
fallback-route-path      css:0  js-emits:1
fallback-route-arrow     css:0  js-emits:1
fallback-route-count     css:0  js-emits:1
fallback-route-served    css:0  js-emits:1
```

## How, because the mechanism is not obvious

My mistake. While landing 4.35.1 I hit a conflict in `admin.css` between the failover block and a reduced-motion block, **resolved it correctly by hand, verified both sides were present**, and then ran `git checkout --theirs .` to clear the conflicted state. That threw the resolution away and took the stashed side wholesale — the side that predated the failover CSS.

The commit that followed looked clean and CI was green.

## The real problem

**An unstyled class is not an error.** The page loads, the script runs, every test passes, and the only signal is a person looking at it. This surfaced purely because I ran a class cross-check by hand while rebasing the next branch — not because anything caught it.

So the fix is the restored CSS *plus* a test that makes this failure loud: every class `admin.js` emits under a feature prefix must have a rule in `admin.css`. Scoped to prefixes rather than every class in the file, so it stays a real assertion instead of a list nobody maintains.

## The guard needed two passes of its own

A naive `` [`"]([^`"]+)[`"] `` capture stops at the first quote **inside** a template interpolation, and a nested template literal leaves an unterminated `${` behind. Both produced fragments that were never class names, which would have made the test noise that gets deleted. Now: template literals and plain strings are matched separately, complete interpolations are stripped, and a trailing unterminated one is cut — so it checks base classes and does not dictate how the script writes its interpolations.

## Verification

I checked the guard **actually catches the bug it exists for**, rather than only passing:

```

$ pytest ...::test_admin_static_styles_every_class_the_script_emits

```

Restored to green afterwards.

```
$ uv run ty check

$ env -u ENABLE_WEB_SERVER_TOOLS -u EXA_API_KEY uv run pytest tests/api/test_admin.py -q

```

Braces balance, and `.analytics-empty` is not duplicated — it survived on main, so only the genuinely lost rules were restored.

## Residual risks

- The guard covers class **names**, not whether a rule is correct or reachable. A rule that exists but is overridden still passes.
- It is prefix-scoped (`fallback-`, `route-`, `get-started-`, `ws-`, `model-chain-`). A future feature using a new prefix is not covered until the prefix is added — deliberate, since the alternative is a whole-file check that fails on every shared utility class.
