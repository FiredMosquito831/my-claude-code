## Description

**What was broken.** NVIDIA NIM requests silently lost their reasoning
instruction. On the user's live data `nvidia_nim/moonshotai/kimi-k3` produced
thinking on 2 of 111 requests, while `nvidia_nim/minimaxai/minimax-m3`, which
was not 400ing, produced thinking on 7 of 10.

**Mechanism.** NIM's reasoning instruction lives entirely in
`extra_body.chat_template_kwargs` (`thinking` / `enable_thinking`, plus
`reasoning_budget`). The chat-template rung of `_get_retry_request_body` decided
whether to strip that field by testing `"chat_template" in error_text`, where
`error_text` was `str(error)` concatenated with `json.dumps(error.body)`. Both
halves can contain the *echoed request*: a pydantic-style validation 400 carries
the objection in `msg`/`loc`/`type` and the entire submitted body under `input`,
and the OpenAI SDK's `str()` renders the whole response payload. So a rejection
about something else entirely — kimi-k3's was
`Validation: top_p is immutable for this model and must be 0.95, got 1` — could
match on the request's own `chat_template_kwargs` and retry without it. The
retry then succeeded, so the user saw an answer, just never a thinking block.
The same substring test made the rung fire on any 400 whose text happened to
contain the token, with no requirement that the provider was complaining about
it.

**Fix.** Split evidence from surgery in `providers/nvidia_nim/retry.py`,
following the shape of `providers/openai_chat/output_cap.py`, which already
parses a named cap out of a 400 rather than guessing.

`upstream_complaint()` builds the evidence string from the structured error body
only, walking message-bearing keys (`message`, `detail`, `msg`, `loc`, `param`,
`type`, ...) and skipping request-echo keys (`input`, `body`, `request`,
`payload`, `ctx`, `value`, ...) outright. It falls back to `str(error)` only when
the body yields nothing readable. Word-boundary matchers then report *which*
field the provider named: `chat_template_evidence`, `reasoning_content_evidence`,
`reasoning_budget_evidence`, `sampling_parameter_evidence`.

The ladder in `nvidia_nim/client.py` now reads, in order:

1. `reasoning_budget` — narrowest removal, and the only rung that keeps the
   thinking flags themselves; still the only rung that accepts a 500.
2. `chat_template` / `chat_template_kwargs` — fires only when the complaint names
   the field. Ordered ahead of the sampling guard on purpose: naming the field is
   direct evidence, whereas a sampling name is only a negative signal, so a
   complaint naming both still strips. This keeps the load-bearing recovery for
   models that reject the field outright.
3. sampling-parameter guard — a 400 naming `top_p`, `top_k`, `min_p`,
   `temperature`, `seed` or a penalty, and *not* naming the chat template,
   returns `None`. Removing the reasoning instruction cannot fix a sampling
   complaint; it only trades a visible failure for an invisible loss of thinking.
4. `reasoning_content` — fires only when named.
5. anything unrecognised — `None`. Re-sending an unchanged body is pointless and
   re-sending a degraded one is worse than failing, so an unreadable 400 now
   surfaces instead of costing the request its reasoning.

Every rung logs which rung fired and the matched token plus a bounded excerpt of
the provider's own words, so "why did my thinking disappear" is answerable from
the log. The no-retry paths log too.

`reasoning_emitted` on `request_attempts` needs no change: `record_wire_request`
is called inside `_create_stream`'s retry loop and `WireTrace.record` recomputes
`reasoning_was_emitted(body)` per attempt, last-write-wins, so a stripped retry
already records `reasoning_emitted=0` for that attempt.

*phrase* rather than a bare field name, so neither is fixed here.

**Residual risks.**

- The evidence walk trusts key *names*. A provider that reports its objection
  under a key not in the complaint list, and nothing else readable in the body,
  falls back to `str(error)` — which still carries the echoed payload. That
  fallback is strictly no worse than the old behaviour, and it only applies when
  the structured body yields nothing.
- A NIM deployment that rejects `chat_template_kwargs` without ever naming it
  (a bare "invalid request") no longer recovers; it fails visibly instead. That
  is the deliberate trade in rung 5 — a visible failure beats a silent downgrade
  — but it is a behaviour change for any such deployment.
- The sampling guard's parameter list is fixed. A provider complaining about a
  sampling knob not on the list falls into the unrecognised bucket, which is
  also no-strip, so it fails safe.
