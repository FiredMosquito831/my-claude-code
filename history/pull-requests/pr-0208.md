## Description

## What was broken

`commandcode` has **never** sent a reasoning instruction, and could not have surfaced one if it arrived.

Its profile carried `NO_REASONING` (whose `encode()` body is literally `return`), so the outbound body was:

```json
{"model": "minimax/minimax-m3-free", "max_tokens": 32000}
```

No `reasoning`, no `reasoning_effort`, no `thinking`, no `chat_template_kwargs`. Separately, `reasoning_delta_field` defaulted to `"reasoning_content"` while the gateway emits `reasoning` — so even reasoning that *did* arrive was dropped before reaching the client.

Two live databases:

```

  nvidia_nim    24914 reqs  18869 (75.7%)
  opencode      47480 reqs  12160 (25.6%)
  commandcode   16944 reqs      0 (0.0%)   <--
```

~23,000 requests, zero thinking blocks, across all seven models. Not a regression — a missing feature. Added in #78; `git log v5.60.0..main -- providers/commandcode/` is empty.

### What the probe establishes

- **`reasoning_effort` is the only reasoning parameter the gateway parses.** An invalid value 400s *and names the enum in the error*; a deliberately invalid `reasoning: {"effort": "bogus_value"}` returns 200 with reasoning unchanged, proving the object is never read. Same for `thinking` and `chat_template_kwargs`.
- **Its vocabulary is `low|medium|high|xhigh|max`.** `none` and `minimal` both 400.
- **It is honoured, not merely accepted** (MiniMax-M3: 0 → 8032).
- **Reasoning arrives as `reasoning` + `reasoning_details` deltas.** Never `reasoning_content`, and no response in any variant put a `<think>` tag in `content`.
- **`minimax/minimax-m3-free` — the dominant model in the request log — has no reasoning channel at all** under any dialect. Its 0% is a property of that model, not of this bug. The rest of the catalogue is not.

## What this does

Wires `NamedEffortReasoning` over the probed enum — no new encoder needed, and nothing branches on a model name:

| Decision | Value | Why |
|---|---|---|
| Encoder | `NamedEffortReasoning(_EFFORTS)` | top-level `reasoning_effort` string is the only parsed knob |
| Vocabulary | `MINIMAL→low, LOW→low, MEDIUM→medium, HIGH→high, XHIGH→xhigh, MAX→max` | the gateway's own rejection message; `minimal` 400s so it folds onto `low` |
| `disabled_value` | **none** | the enum has no off rung; `none`/`minimal` both 400, so OFF sends no reasoning field — the dialect's only correct disabled shape |
| `enabled_value` | **none** | a bare request already reasons the most on offer (rc≈3000 vs rc≈180 at `high`); naming a rung for "on, effort unspecified" would *reduce* reasoning |
| `use_extra_body` | `False` | `reasoning_effort` is a first-class SDK param and the gateway reads it top-level |
| `reasoning_delta_field` | `"reasoning"` (fallback `"reasoning_content"`) | what the gateway actually emits |
| `reasoning_replay` | `REASONING`, was `THINK_TAGS` | no probe response ever produced a `<think>` tag; history was re-encoded in a shape this gateway never emits |
| `include_extra_body` | `True` + `validate_extra_body_does_not_override_canonical_fields` | matches `openrouter_gateway`/`zenmux`; caller extras reach the gateway but cannot forge `reasoning_effort` |

**Anthropic-protocol half: no change needed.** `claude-*` models route to `AnthropicMessagesProvider`, which goes through `build_anthropic_messages_body`; its `_apply_reasoning` already emits the native `thinking` object (`adaptive`, or `enabled` with `budget_tokens`) and pops it on OFF. Only the OpenAI half was blind. Verified by reading `providers/anthropic_messages/request.py`, not assumed.

## Tests

Ten new tests in `tests/providers/test_commandcode.py`:

- outbound body for `minimax/minimax-m3-free` at effort=max carries `reasoning_effort: "max"` and *none* of the silently-discarded shapes;
- every `ReasoningEffort` encodes inside the published enum (parametrized);
- an effort clamped to the model's vocabulary (`['high','low','medium']`, tier 8 of 5.68.1's ladder) still encodes;
- OFF emits no reasoning field;
- ON with no effort keeps the gateway default;
- caller `extra_body` passes through, and a forged `reasoning_effort` raises `InvalidRequestError`;
- `reasoning_delta()` reads the `reasoning` field, and assistant history replays as `reasoning` with no `reasoning_content` and no `<think>`;
- regression guard: `bedrock`/`cline` still send no reasoning at all, while `ollama` keeps `reasoning_effort: "max"` and `zenmux` keeps `extra_body.reasoning = {"effort": "xhigh"}` — so a future edit to the shared encoders can neither spread this change nor erase a neighbour's dialect.

## Residual risks

- **`high` measures lower than `medium` on `glm-5.3-flash`** (rc≈180 vs rc≈1700). The mapping is faithful to the vendor's published enum rather than to that measurement; re-ordering the rungs to fit three samples would be over-fitting to one model on one day, and would be exactly the model-name branching the architecture forbids. SUSPECTED gateway-side routing variance across upstreams, not a mapping error.
- **`reasoning_details` are received but not replayed.** The gateway emits them (OpenRouter family), and `zenmux`/`cline`/`openrouter_gateway` handle them via `apply_reasoning_details_replay` + `structured_reasoning_details`. Plain-text `reasoning` replay is coherent on its own; signed-block replay is a separate change and deliberately out of scope here.
- **`include_extra_body` flipping `False → True` is a behaviour change** for any caller already sending `extra_body` to Command Code: it now reaches the gateway instead of being silently dropped, and a caller sending a canonical field now gets a loud `InvalidRequestError` instead of silence. That is the intended contract everywhere else in the fleet.
- **`minimax/minimax-m3-free` will still show 0% thinking.** CONFIRMED as a model property; no dialect changes it. Reasoning on that family needs `MiniMaxAI/MiniMax-M3`.
- The probe covers two models directly and the gateway's shared validator for the rest. Per-model reasoning support beyond those two is SUSPECTED from the gateway-wide enum, not individually measured.
