## Description

## The asymmetry this closes, measured

Read-only over the live request log (`~/.fcc/logs/requests.db`, `mode=ro`), 272,132 rows:

> **Across the whole history, the number of non-Claude-Code requests that ever named a tier-style
> alias is ZERO.** Every coding-agent request named a concrete `provider/model` ref, because that
> was the only thing that existed for it — while 99.98% of Claude Code traffic names an alias and
> almost never a ref (115,825 alias rows vs 7 gateway-ref rows for `claude-cli` all-time).

Claude Code asks for `claude-sonnet-5` and MCC maps that onto whatever `MODEL_SONNET` points at, so
moving a route moves every session already running on it. A model id typed into OpenCode's config a
month ago is still that id today, however many times the route it should have been following moved.

## What ships

Five names, at the head of the picker MCC generates for each of the **thirteen** agents that carry a
catalogue (codex, pi, opencode, opencode2, kilo, commandcode_cli, kimi_code, qwen_code, crush,
cline_cli, aider, droid, gemini_cli):

| Name | Route it names | Chain it uses |
| --- | --- | --- |
| `mcc/best` | `MODEL` | `MODEL_FALLBACKS`, `MODEL_PAUSED` |
| `mcc/good` | `MODEL_OPUS` | `MODEL_OPUS_FALLBACKS`, `MODEL_OPUS_PAUSED` |
| `mcc/medium` | `MODEL_SONNET` | `MODEL_SONNET_FALLBACKS`, `MODEL_SONNET_PAUSED` |
| `mcc/cheap` | `MODEL_HAIKU` | `MODEL_HAIKU_FALLBACKS`, `MODEL_HAIKU_PAUSED` |
| `mcc/vision` | `MODEL_VISION` | `MODEL_VISION_FALLBACKS`, `MODEL_VISION_PAUSED` |

Pointer semantics, **including the collapse**: on a default install the four optional routes are
unset, so all five resolve to `MODEL` — primary, fallbacks and pause list together — exactly as
`claude-opus-5` already does. MCC does not invent a distinct model for an unset tier; the card says
*"Same as global Opus — currently `<ref>`. MODEL_OPUS is unset, so it follows MODEL."*

Per-agent overrides live in `~/.fcc/harness_tiers.json` (three states per `(agent, tier)`: key
absent = inherit; entry with no `model` = global primary + this agent's own fallbacks; `model` set =
this agent's chain leads) and are edited on the Coding agents card's new **Tiers** section, which
renders the *same* rail component Model Config uses.

## Resolution flow

`ModelRouter.resolve` / `resolve_chain` intercept a tier **before** `_direct_provider_model`.
`mcc/best` already "worked" on `fork/main` — by accident: `mcc` is not a supported provider id, the
direct branch declined it, `_matched_route` matched nothing and `_resolve_model_ref` fell through to
`settings.model` with no fallbacks, no pause and no trace in the log. This **replaces** that, rather
than layering a rule over it.

`application/tier_chains.resolve_tier_chain` is the single rule, with two callers that must never
disagree — the router answering a request, and `catalogue_model.py` writing the alias entry whose
display name states which model the tier points at today. Order: this agent's entry with a `model` →
its chain leads; entry with no `model` → global primary + this agent's fallbacks; otherwise → the
global chain. **An unknown harness takes the third branch** — a raw curl or an old launcher still
gets a working tier, it simply gets the global one.

Both wire spellings parse, because the fleet is split (bare ref from Codex/Command Code/OpenCode/
Kilo/Pi/Kimi, `anthropic/<ref>` from Cline/Crush/Droid/Gemini CLI/Qwen/Aider). The tier segment is
matched **exactly**, never as a substring — `_matched_route` is a substring match, and repeating that
hazard with five more names would be a routing bug nobody could see.

## Deviations from the spec

- **The alias carries its own ref**, not the primary's. The spec had `gateway_id = "mcc/best"` with
  `provider_model_ref` left as the primary's; that collides in the six serialisers that key their
  document on the bare ref and skip a duplicate, so the alias would have silently vanished from
  Codex, Command Code, OpenCode, Kilo, Pi and Kimi. It is now `provider_model_ref = "mcc/best"` and
  `gateway_id = "anthropic/mcc/best"`, which also gives both spellings from one record with no
  per-CLI code. `parse_model_name` still sees two segments and Pi's extension still accepts it.
- **`config` may not import `core`.** `test_import_boundaries.py` declares `config` a leaf, so
  `TIER_NAMESPACE` and the tier names are mirrored in `config/constants.py` and pinned equal to
  `core.tier_refs` in both directions — the pattern `FAILURE_KIND_NAMES` already uses.
- **Model Config is untouched**, per the decision taken up front; no `ROUTE_TIERS` change, so
  `test_admin_routing_view.py` and `test_deadline_hint_labels.py` needed nothing.
- **Tier edits do not join Apply.** The spec had them posting on the page's Apply; they are not env
  keys, and collecting them in `changedValues()` would post unknown keys to `/admin/api/config/apply`
  on every Apply and make the page read dirty from a section the dirty count cannot explain. Each
  tier row has its own Save; Pause posts immediately, exactly as it does on Model Config.
- **Per-harness catalogue builds are conditional.** The spec's "13 builds instead of 1" is done only
  for an agent that actually has overrides — which is none of them until somebody opens the section.
- **`mcc-opencode run -m mcc/best` is spelled `-m mcc/mcc/best`.** OpenCode's `-m` is
  `<provider>/<model>` and its provider id is `mcc`, so the tier is addressed `mcc/mcc/best`; the
  wire `model` value is `mcc/best`, which is what the log shows.

## Residual risks

- **The `:has()` selector for the two-column card.** Supported in every browser this dashboard
  targets, but it is the first use in `admin.css`; a browser without it renders the previous, cramped
  layout rather than a broken one.
- **A tier resolving to a model the catalogue does not list gets no entry.** Correct (an alias the
  picker cannot select is worse than none), but an operator who hides `MODEL` behind
  `MODEL_VISIBILITY_DENY` loses `mcc/best` from the pickers while the router keeps answering it.
  Documented, not reconciled.
- **`MODEL` vs `MODEL_FABLE` divergence.** An operator who sets them to different refs gets `mcc/best`
  on `MODEL` and Claude Code's `claude-fable-*` on `MODEL_FABLE`. Surfaced in the docs; deliberately
  not reconciled.
- **Per-harness reasoning overrides are out of scope.** A tier inherits `REASONING_OPUS`/`_SONNET`/
  `_HAIKU` from the route it names; Best and Vision have no per-route setting and fall through to the
  global policy, because `settings.py` defines exactly four.
- **Crush and Cline now open on `mcc/best` rather than on `MODEL`'s raw ref.** Deliberate and the
  point of `is_primary_route` moving, but it is the one behavioural change to an existing generated
  document.
- **Kimi Code's key reads `mcc/mcc/best`.** Ugly in one CLI's `--model` help, correct everywhere; the
  alternative was a per-serialiser exception that breaks the "pure function of the records" property
  this layer is built on.
