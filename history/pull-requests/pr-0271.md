### On decision 5 — no special-casing

Transient refresh failures get **no OAuth-specific retry loop**. `AnthropicOAuthProvider._classify_credential_failure` maps them onto the *existing* `FailureKind`s and the existing machinery does the rest:

| Token-endpoint result | `FailureKind` | Retryable | Wire type | Benches the model |
|---|---|---|---|---|
| 429 | `RATE_LIMIT` | yes, honours `Retry-After` | `rate_limit_error` | no |
| 5xx / transport | `OVERLOADED` | yes | `overloaded_error` | yes |
| 400/401/403 + OAuth body | `AUTHENTICATION` | no | `authentication_error` | yes |
| no credential | `UNAVAILABLE` | no | `api_error` | no |

**No `FailureKind` was added**, so the three wire tables, the constants mirror and the enumerating tests are untouched. The override is threaded into *both* `execute_with_retry` and `classify_provider_failure` via a new `set_failure_override()` setter, matching the `set_auth_retry`/`set_response_observer` house pattern.
