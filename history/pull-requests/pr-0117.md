## Description

The page had grown three sections in the order they were *built*, not the order you need them. This reorders it, regroups the settings, and replaces the worst control on the page.

## Structure, top to bottom

| | |
| --- | --- |
| **1. Connection** | The one-click panel that writes `ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN` — **back at the top**. It's what most people came for and it was third. |
| **2. No setup needed** | Launcher commands for **every** agent, not just Claude Code: `mcc-claude`, `mcc-claude --discover-models`, `mcc-codex`, `mcc-pi`, `mcc-claude-old` — each with a copy button, plus one line noting the `fcc-*` spellings still work. |
| **3. All settings** | Unchanged in behaviour, regrouped. |

The old two-card "choose how you connect" block is gone — it said *"use the Configure panel below"* and duplicated what the panel already said.

## Nine groups instead of sixteen categories

Named for **what you're configuring**: Model and reasoning · Context and cost · Permissions and safety · Tools · Agents, skills, and automation · MCP · Connection and providers · Interface · Privacy, telemetry, and updates.

The previous grouping was the docs' own mechanical categories — several held one or two rows while *every* `settings.json` key fell into a single "settings" bucket. The group is computed in the generator and carried in the catalog, so the page and `docs/CLAUDE-CODE-CONFIG.md` can't disagree about where a setting lives.

## Array settings are lists now, not JSON

Each entry is a row with a remove button plus an add field — so the most common edit in the file, **adding one permission rule**, stops being an exercise in matching brackets.

For `permissions.allow` / `ask` / `deny` that add field is a **rule builder**: tool dropdown (Bash, PowerShell, Read, Edit, WebFetch, Agent, Cd, WebSearch, `mcp__server`), a specifier field with a per-tool placeholder and hint, and a live preview of the rule it will add.

## Accessibility (from the ui-ux-pro-max checklist)

- Every control now has a real **`<label for>`** carrying the setting name — previously styled text with nothing associating it. List and rule editors have no single control to point at, so those are `role="group"` + `aria-labelledby`; a label aimed at a nonexistent id reads as labelled and isn't.
- JSON errors appear **next to the field** with `role="alert"` and `aria-invalid`, not only as a toast at the top.

## Bugs found by driving the page

- **A bulk edit had injected `input.id = controlId` into `inputForField()`** — the *generic* field renderer shared by **Model Config, Limits and Messaging**, where no such variable exists. Every boolean toggle on those three pages would have thrown. Caught by the page reporting `controlId is not defined`; fix verified by counting rendered checkboxes on all three (2, 11, 1).
- The toggle wrapped its checkbox in a second `<label>`, so **41 rows were unlabelled**.
- The `group` field was computed but never carried through `CatalogEntry`, so **all 101 rows rendered in one section**.
- Copy buttons were wired once at startup, when the view is hidden.
- Long commands ran **underneath** the absolutely-positioned copy button.
- Descriptions showed raw markdown (`**Default**:`, backslash-escaped underscores).
- One more undefined-token usage fixed — the stylesheet now has **none**. Dead `.claude-connect-*` rules removed with the markup that used them.
