## What was wrong

Telegram/Discord platforms started with **no allowlist** accepted any user/channel as operator — silently. No warning, no dashboard signal; the risk was invisible unless you already knew to check `.env`.

## The fix (loud warning only — zero behavior change, per owner decision)

- Startup warning per platform when running allowlist-free, naming the real env locks (`ALLOWED_TELEGRAM_USER_ID` / `ALLOWED_DISCORD_CHANNELS`).
- New top-level config-payload field **`messaging_auth_open": [...]`** (platform ids running open; `[]` when locked) so the dashboard can render the state.
- Blank-after-strip counts as unconfigured everywhere; Discord's predicate delegates to the inbound parser so degenerate lists (`","`) report open exactly as runtime treats them.
