## Description

`WORKING-NOTES.md` (git-ignored, repo root) is the operating manual for this project — standing preferences, the release sequence, CI quirks that waste hours, domain gotchas, product principles, and known gaps. Nothing pointed at it, so each session rediscovered the same things and re-litigated settled decisions.

Adds a **WORKING NOTES (READ FIRST, THEN MAINTAIN)** section to `CLAUDE.md` and `AGENTS.md` (kept byte-identical) covering:

- **Read it first**, and say so if it's missing rather than silently proceeding.
- **Specific triggers to add an entry**: time lost to something non-obvious, a correction from the user (record the *principle*, not just the instruction), a shipped release, a gap you're deliberately not fixing.
- **Correct stale sections rather than appending contradictions** — stale guidance is worse than none. The release process already had to be rewritten once when version pinning was removed.
- **Write findings so they're useful cold**: symptom, cause, rule. "PowerShell installer tests never run on Linux CI, so a PS-only regression ships green" beats "be careful with CI".
- **Keep it local** — it's git-ignored on purpose and references machine-specific paths and running processes.

Docs only, no version bump. Verified `CLAUDE.md` and `AGENTS.md` remain identical, and that `WORKING-NOTES.md` stays ignored (only the two doc files are staged).
