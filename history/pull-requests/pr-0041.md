## Description

## What was wrong

The Get Started checklist shipped in 4.29.0 told you *what* to do but not *how*, and its button dropped you at the top of a long settings page with no indication of which control it meant. "Connect a model provider" → Providers, then hunt.

## What changed

**Per-step instructions.** Each step carries an ordered list of concrete steps naming the real controls. Every label cited was checked against `index.html` rather than written from memory — the footer button is literally `Apply`, the nav entries are `Providers` and `Model Config`. A wrong label in a walkthrough costs more than a wrong label anywhere else: the reader looks for the thing you named and concludes the app is broken when it simply is not there.

**Buttons that point at the right place.** Each step carries an optional DOM target, so the button scrolls to and briefly highlights the specific card or field. Every selector was confirmed present before being wired.

**It reads as a walkthrough, not a wall.** The first incomplete required step is expanded with its instructions visible; everything else collapses to one line. It also *advances* — once the expanded step becomes done, the next incomplete required step takes its place.

That last part was the first version's real defect, caught in review: the expanded id was chosen once and never re-derived, so completing the provider step left it expanded showing "Done" while the next action sat collapsed out of sight — defeating the entire premise of the feature.

## Nothing new is persisted

Which step is expanded is view state. The only two things this feature stores remain `dismissed` and the guide's `visited` list; every done-state is still derived from live configuration (Part IV §5).

## Residual risks

- **The collapse/expand interaction and the scroll-and-highlight have not been driven in a browser.** The state machine is covered by reading it and the API payload above is real, but the highlight itself is unverified.
- Instructions are static prose. If a control is renamed later, nothing asserts these strings still match the UI — the same unguarded docs-drift already noted for `docs/USAGE.md` and the in-dashboard Guide.
- The messaging step still knows Telegram and Discord by name rather than deriving from a catalog, unchanged from 4.29.0.
