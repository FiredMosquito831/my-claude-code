## Why

The **Configure Claude Code** page writes exactly two keys today — `ANTHROPIC_BASE_URL` and `ANTHROPIC_AUTH_TOKEN`. To grow it into a real guided editor (dropdowns with the actual option lists, a description per setting, permission rules) we first need to know what the full surface is. Nothing in this repo described it, and the upstream surface is large and moves weekly.

So this lands the reference **and the generator that produces it**, rather than a hand-written snapshot that goes stale the week after it merges.

## The traps it documents

A naive editor would do the *opposite* of what the user asked on three classes of value:

- **Six "set or unset" variables** — `DISABLE_TELEMETRY`, `DISABLE_ERROR_REPORTING`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`, `CLAUDE_CODE_TMUX_TRUECOLOR`, `FALLBACK_FOR_ALL_PRIMARY_MODELS`, `IS_DEMO`. They read only *whether the variable exists*. Writing `"0"` **enables** them. They must be present/absent switches that delete the key.
- **`FORCE_HYPERLINK`** is parsed as a **number**, so `false` / `no` / `off` all *enable* hyperlinks. Only `0` disables.
- **Ten credential variables** must be masked and never echoed back.

Plus the things that change what an editor may safely write: scope precedence including the managed-tier ordering, the restrictive-value exceptions that let a lower scope override a managed one, which keys need a restart (`model`, `outputStyle`), and that removing a variable from an `env` block does *not* unset it in a running session.
