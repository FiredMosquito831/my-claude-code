## What changed

Two user-reported issues on the just-shipped 5.5.0:

### 1. Applying a restart-required websearch setting crashed the server
Setting `WEBSEARCH_LOG_MAX_ROWS` / `WEBSEARCH_LOG_CONTENT_MAX_CHARS` from the Web Search page → instant server crash; the values applied after a manual restart. Root cause: `_run_supervised_server` fell through to `return ServerExitAction.STOP` when the runtime was still draining after `server.run()` returned, so a config-driven **RELOAD became a process exit**. The `serve()` loop is designed to re-run on RELOAD and the port-wait at the top of the next iteration handles the lingering socket, so returning RELOAD keeps the server up. **Reproduced** against a copy of the live `websearch.db` (server died after apply; the log showed a clean shutdown with no restart).

### 2. Truncated websearch rows dumped raw JSON in the detail modal
Legacy rows (stored before the 2M capture cap) render their `preview` — the first chunk of serialized output — as a raw JSON blob. `previewResultsFromJson` now parses the preview: it extracts the leading answer and walks the results array, pulling title/url/snippet from a result even when its huge `content` string is cut mid-way (the common exa shape). The modal renders readable answer + result cards; a note points to the raw pane for the exact stored preview.
