## Description

4.50.0 registered a `limits` section and 18 fields — but **no view claimed the section**, so the fields were served by `/admin/api/config` and rendered nowhere. I checked the manifest and the API and called it done; the page itself did not exist.

This adds the view. Verified against a real server rather than the manifest:

```
nav: Get Started, Providers, Model Config, Messaging, Analytics, Web Search, Limits, Guide
#limitsSections -> 26 unique fields rendered
```

It also claims `diagnostics`, which no view claimed either, so the logging flags stop falling through to a leftover bucket.

Ordered by what a value costs — live requests, then disk, then noise — rather than by the subsystem that reads it. Each field keeps the description that says what the number costs, not just what it is.

Note: fields render twice in the DOM here (26 unique / 52 elements). That is pre-existing across every view — Web Search is 19/38, Model Config 20/34 — so it is not introduced by this change and is left alone.
