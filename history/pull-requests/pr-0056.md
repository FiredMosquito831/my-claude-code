## Description

Opening a provider showed **"Configured — enter a new value to replace"** in a full-width field, and directly beneath it the key list with a Remove button per key and an Add key row.

Two mental models stacked on each other, and the one on top was the destructive one: that field wrote the **entire** comma-separated value, so using it silently discarded every other key in the pool. Nobody wants to replace a pool. They want to add to it and remove from it.

## What changed

**The raw field is no longer shown.** It stays in the document, hidden and unfocusable, so the shared dirty/apply machinery is untouched and nothing can set it — it therefore never goes dirty. The `hidden` attribute alone only sets `display:none` at UA level, which any later display rule beats, so `.field-pooled > [hidden]` pins it. The label no longer points at it either; it now heads the key pool rather than an input nobody can reach.

**Configure goes straight to the pool.** Pressing it opens the key manager for that provider instead of revealing a second "Manage keys" button to press. Opening eagerly at render time would fire one request *per provider* on every page load, so the card triggers it when it expands.

**Adding several keys at once still works, through the right control.** `POST /admin/api/credentials/{env}/keys` used to reject any value containing a comma, which left the replace-everything field as the only way to enter a pool. It now splits on commas and appends every key that is new, **skipping duplicates instead of failing the batch**, and reports `added_count` / `skipped`. An all-duplicate paste is still a 409.

**Copy that described the removed control is gone.** The NVIDIA NIM description no longer advertises a comma-separated field, and the rotation help says "across the keys you have added" rather than naming a list nobody types.
