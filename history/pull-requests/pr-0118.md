## Description

Configuring the endpoint and token meant typing a path into a text box, with one "candidate" listed whether or not anything was there. On a machine running WSL that's precisely the wrong affordance: **there are two Claude Code installations and two `~/.claude/settings.json` files**, and *"my setting didn't apply"* is nearly always the other one.

## Connection is now a choice, not a text box

```
 ◉  [WINDOWS]  Not configured
    C:\Users\you\.claude\settings.json

 ○  [WSL]  Ubuntu-24.04   Points somewhere else
    \wsl.localhost\Ubuntu-24.04\home\you\.claude\settings.json
```

- **Only files that exist.** A path that could exist is noise on a list describing what's real.
- **Labelled by world** — Windows, WSL (with distro name), Linux, macOS — as prominently as the path.
- **Status against this server**: configured for My Claude Code · points somewhere else · not configured · unreadable.
- Pick one, press **Configure**. **Remove** appears only when there's something to remove, and Configure reads **Reconfigure** when the file already points here.
- **The editor follows the same selection** — selecting a file loads that file's keys, so choosing where to connect and choosing what to edit are one decision instead of two that can disagree. The editor names the file it's editing.
- Nothing found → the section says so and offers to create at the default location.

## Discovery

Native home (including a `CLAUDE_CONFIG_DIR` override) · the Windows-side home when running under WSL · every WSL distribution's home when running on Windows.

That last one enumerates via `wsl.exe --list --quiet` **with a timeout**, rather than listing `\wsl.localhost` — that UNC root blocks for as long as the service takes to answer when no distribution is running, and this runs while a page is loading. Every probe is wrapped: a world that can't be reached contributes nothing rather than failing the page.

Project `.claude/settings.json` still needs a typed path (the server can't know which repo you're in) — that moved into a collapsed **"Use a different file"** row instead of being the primary control.

## Two bugs fixed

- **The list vanished after Configure or Remove.** Both handlers adopted the write response as new state, and that response carries only the status of the file just written — no targets. Both now re-read, which also refreshes the *other* files' states after a write changes them.
- **The Remove button stayed on screen with `hidden` set** — `hidden` only sets `display: none` as a UA default, and `.secondary-button { display: flex }` beat it. Added the standard `[hidden] { display: none !important }` guard, fixing this class of bug dashboard-wide; verified view switching and the review modal still work.
