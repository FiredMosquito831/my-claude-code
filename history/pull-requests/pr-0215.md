## Description

PR #205 shipped this page without ever rendering it. Driven now against a
live install (10 providers, 1,021 models, a 2.93 MB /admin/api/model-admin
payload) in Chrome via DevTools MCP, these are the measurements:

- The tree built **186,290 DOM nodes and 9,279 `<select>` elements** on first
  render, while every provider was still collapsed. Nothing was lazy: the
  render walked every provider's every model and built a full nine-parameter
  override editor plus two tables for each. 191,045 nodes on the page, 1.2 s
  to first paint.
- Chrome reported **1,021 accessibility issues**: "interactive element inside
  of a `<summary>`" — the visibility checkbox, which also needed a
  `stopPropagation` so ticking it did not fold its own row.
- **A save that worked showed nothing.** `saveModelOverrides` called
  `renderModelsPage()`, which rebuilt the tree, so `status.textContent =
  "Saved"` landed in a node that had already been discarded — measured as an
  empty string after a save that had in fact persisted. The same rebuild threw
  away unsaved edits in every other open editor.
- **"Force value" with an empty box saved the empty string**, forcing
  `temperature: ""` onto the upstream body. No validation.
- Opening a provider put a **nine-row override form above its models** — a
  screenful of `Inherit` selects between the provider you clicked and the
  models you clicked it for. The value box was ~590 px wide for a number like
  0.7, beside a mostly empty label column, with no column headers.
- Typing a three-letter filter **force-opened every matching provider** (9 of
  10 on "gpt"), 12,038 px of page, and re-showed nine provider forms.
- The middle of three sections, "Parameter overrides", was **a heading and
  three paragraphs with no controls in it**; the editors it described were in
  the section below. Its "Not editable here" line was a run-on wall repeating
  "the reasoning pipeline owns thinking parameters" four times.
- "Effective request parameters" restated the nine `Inherit` selects directly
  above it as nine rows of "not sent". `317 shown / 0 hidden` on every
  provider. Filtering re-ran on every keystroke over 1,021 refs.

## What changed

Page only — the endpoints, the `model_overrides.json` store, the visibility
globs and the tier resolution are untouched and correct.

- **Lazy, paged tree.** Provider bodies, model bodies and a provider's own
  override editor are built on first open; a provider's models page in at 40
  a time. 186,290 tree nodes -> 50; 9,279 selects -> 0; 1,233 ms -> 113 ms;
  18,879 px -> 1,485 px.
- **The tick left the `<summary>`.** It is now a labelled sibling of the
  disclosure. All 1,021 a11y issues gone, and `stopPropagation` with them.
- **Saves patch, they do not rebuild.** `refreshModelRow` / `refreshProviderRow`
  repaint only the affected summary chips and the two read-only panels;
  `fillModelReadouts` leaves the editor and its status element standing.
  "Saved" is now visible, and other editors keep their unsaved edits.
- **Empty "Force value" is refused** with the parameter named.
- **Two sections, not three.** The override explanation moved beside the
  editors as a disclosure; every heading now owns controls. "Not editable
  here" is grouped by owner: seven repeated clauses became two lines.
- Provider-wide overrides are one line of disclosure below the models.
  Column headers on the grid, the value box sized like a value, "what this
  forces onto the request" lists only what is forced, `0 hidden` dropped, a
  guessed capability badge now says "— guessed" and its tier reads "tier 5 of
  9". A filter auto-opens a provider only when it is the sole match, is
  debounced, and the tree says how much it is hiding.

## Label correction (semantics unchanged)

`MODEL_VISIBILITY_DENY` was "Never show these models" but is hide-only: a
denied model still routes when a chain names it. Now "Hide these models from
the listings", with help that says it out loud ("it is simply not listed... to
stop using a model, take it out of the route that names it"). Allow becomes
"Only list these models". The tick's toast says "Routing is unaffected either
way." No behaviour changed.

## Residual risks

- The visibility toggle and the override saves were exercised against a local
  harness that emulated the three write endpoints, so the user's live config
  was never modified. The read path and the render were entirely real. The
  write endpoints are unchanged and still covered by their own tests.
- Paging is a cap, not virtualisation: a user who presses "Show more" through
  all 330 open_router models rebuilds roughly the old node count for that one
  provider. Collapsing it frees nothing; a reload or a filter change does.
- `refreshModelRow` matches rows by the text of `.models-ref`. Two rows with
  the same ref cannot occur today (the ref carries the provider), but a future
  grouping that repeated a ref would repaint both.
- The reworded manifest labels change strings a user may have searched for.
  The env var names and the semantics are unchanged.
