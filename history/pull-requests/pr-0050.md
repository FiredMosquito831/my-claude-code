## Description

## What was wrong

Fourteen provider cards competed equally for attention, and the one genuinely diagnostic fact on the page — **what the last real request actually did** — was a flat muted line with the same visual weight as everything else.

## The route summary is now a hero

An eyebrow, the effective provider set large, and the route path below it. The path is **segmented rather than a flat string**, so the primary hop reads at full contrast and every fallback after the first arrow drops to muted.

That is the thing a search route has which a generic "pick one option" control does not: a try-order with a primary and a safety net. Now legible without reading the sentence under it.

## Configured vs observed

Those two can disagree, and that gap is what someone debugging cost or latency actually cares about. The observed line now compares its primary against the configured one and, on mismatch, says the configuration has changed since and switches to the warn colour.

A `webSearchConfiguredRoute()` helper is the single source of truth for both the headline and that comparison, so the two cannot drift into different definitions of "the route" as the manifest grows. No new endpoint, no new field, no routing behaviour touched.

## Presence, not brightness

Secondary cards previously dropped to `opacity: 0.85`, which **dimmed the status pill along with everything else** — exactly the information worth keeping sharp on a card you are about to compare against, since "has a key" is how you judge which alternate you could switch to.

Now only the effective card is a raised surface; the others drop to the section's own background and are held by their border alone, the way an inactive tab sits flush. Content stays at full contrast throughout, which also removes reduced-opacity text that contrast guidance flags even when still readable.

One line replaced three, including a reduced-motion guard with nothing left to guard.

## Also tidied, inside websearch-owned CSS

Masked key labels and provider meta use `--font-mono` instead of a duplicated hardcoded stack; the advanced disclosure summary became a small tracked label; and two rules still carried `var(--border, #333)` / `var(--panel, #1b1b1b)` fallbacks from a palette this project no longer has.

## The static assertion moved twice, deliberately

`"Configured route:"` copy genuinely went away, and the template string that briefly replaced it stopped being real once the path became segmented spans. It now asserts the two span classes exist — checking structure rather than paraphrasing old copy.

## Residual risks

- **No browser**, so the flush de-emphasis, the weighted path and the 320/560px breakpoints are reasoned from the CSS and DOM, not seen rendered.
- The drift signal compares the observed *primary* against the configured primary. A change confined to the fallback tail is not flagged — deliberate, since the primary is what serves nearly every request, but it means a fallback edit shows no drift warning.
