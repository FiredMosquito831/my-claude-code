## Description

Two small fixes from a manual audit of the previous two releases. **One of them is notable mainly for what it does NOT do.**

## 1. The tag fallback was one-directional

A user who configures `foo` found nothing when the upstream index lists only `foo:free`. The lookup now tries, in order:

```
exact  ->  tag-stripped  ->  a single tagged variant in the SAME provider bucket
```

The third step fires **only when exactly one** allow-listed tagged entry exists. Two or more (`foo:free` *and* `foo:nitro`) return unknown — choosing one would assert a variant the user did not write.

## 2. Client adaptive was recorded as "on" — and the obvious fix was wrong

A client asking for Anthropic's adaptive thinking resolved to `control=on`, indistinguishable in the log from a client asking for `enabled`.

The obvious fix — resolve it to the `ReasoningControl.ADAPTIVE` member added in v5.35.0 — was designed, attempted, and **abandoned**, because `ADAPTIVE` has `requests_reasoning=False`. That property is exactly what makes an adaptive **tier** correctly send nothing to providers with no adaptive channel. Applying it to the **client** path stops those providers being asked to think at all:

```
groq         {'reasoning_effort': 'medium'}                     ->  {}
fireworks    {'reasoning_effort': 'high'}                       ->  {}
zai          {'thinking': {'type':'enabled', ...}}              ->  {}
featherless  {'chat_template_kwargs': {'enable_thinking':True}} ->  {}
```

**Claude Code sends `thinking: {"type":"adaptive"}`.** So that would have been a silent capability regression across most providers, shipped as a logging improvement. v5.35.0's committed baseline snapshot catches it, and an explicit "prove it or stop" instruction caught it before that.

**So the resolved policy is deliberately left alone.** Control stays `on`, every encoder keeps sending exactly what it sends today, and the client's own wording is recorded beside it as `client=adaptive` — on the *requested* policy only.

The test asserts the zero wire delta **directly** rather than by argument: it emits bodies for a client-adaptive and a client-enabled request across five encoder families and requires them to be equal.

## Residual risks

**`client=adaptive` is a string convention, not a column.** It rides inside the existing `requested_reasoning` text, so a query for it is a `LIKE`, not an indexed lookup. Deliberate — a column for one provider family's flag would be heavier than the distinction warrants.

**The reverse lookup adds up to six dict probes per candidate.** Bounded and inside an already-memoised per-provider bucket, but it is more work per request than the previous two steps.
