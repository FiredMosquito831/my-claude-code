## Description

The docs were current as of **5.41.1**. Eight releases landed since. Refreshing them turned up three things that were wrong *before* this arc started, which are worth more than the refresh itself.

## Already wrong

**`ARCHITECTURE.md` had been describing deleted code as current architecture since 5.44.0.** It listed *quota probes*, *command prefix detection* and *filepath extraction* by name, with their behaviour, as three of five live optimization rules. All three were removed three releases ago after firing **zero** times in 153,198 real requests.

The contract test written for that deletion pins `Settings`, the admin manifest, the handlers, the detectors and `.env.example` — so a partial revert fails — and says **nothing whatsoever about prose**. It passed the entire time.

**The RTK pinned version was stale in three separate places** after one bump — still `0.44.2` in the README feature table, `ARCHITECTURE.md` and `USAGE.md`.

**`FALLBACK_SKIP_KINDS` had never been documented in any user-facing doc, in any release.** Not stale — absent. Nothing looks for absence.

## Repo identity, on the owner's call

`CONTRIBUTING.md` told contributors to clone `Alishahryar1/free-claude-code`, and `RELEASE-CHECKLIST.md` called that the *"primary fork / development remote"*. Neither matches how the repo is run: all development and every release goes to `FiredMosquito831/my-claude-code`, and upstream is never pushed to. A contributor following the old instructions cloned a repo containing none of the work and built a package whose name didn't match their checkout.

Both now describe the real topology, with upstream kept for provenance and the `gh --repo` trap called out.

## Added for the arc

- **README** — Token Optimizer feature row and section, panel by panel against the real UI labels; a *Requests Answered Locally* subsection covering the two new log fields and the `answered locally · <rule>` display (which is also a **working filter value**); the `context_length` paragraph in failover.
- **USAGE** — the Token Optimizer page and its trimming subsection nested *under* the existing Analytics section, so **no anchor was renamed**; `context_length`; RTK `gain`, pin drift, and an explicit statement that MCC forces RTK's telemetry opt-out and suppresses its consent prompt, so enabling RTK through MCC cannot opt anyone in.

**Tool-result trimming is documented as off and probably best left off**, with the measured numbers rather than a caution: 10.9% more fresh input tokens at the shipped defaults, one near-total cache miss when enabled mid-conversation, break-even at a ~90.9% baseline hit rate. Numbers read from the module docstring and `.env.example`, **not retyped from the brief.**
