## Description

Caught by actually running the published Windows install command:

```
==> Ensuring uv 0.11.0 or newer is installed
The term 'Get-UvVersion' is not recognized as the name of a cmdlet...
```

Stripping the coding-agent code from `install.ps1` also removed `Get-UvVersion`, `Convert-UvVersionOutput`, `Test-UvVersionAtLeast`, and `Confirm-Uv` — they sat between the agent functions and `Ensure-Uv`. The same thing happened in `install.sh` and was caught by CI; the PowerShell equivalent was not, because **those tests don't run on the Linux runners**.

The script still *parsed* fine, so a parse check would not have caught it either. It only fails at the moment a user runs it.

Adds `test_installers_define_every_helper_they_call`, a static assertion that both scripts define the helpers they depend on. It runs on any platform, so the PowerShell path is now covered by Linux CI.

Verified: `install.ps1 -DryRun` now resolves v4.18.0 and its published SHA-256 correctly.
