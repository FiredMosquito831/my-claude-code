## Description

## Two confirmed defects

**1. Deferred-upgrade outcomes were unreadable on Windows.** The staged-update helper wrote its result receipt via `Set-Content -Encoding utf8` — under Windows PowerShell 5.1 (what `shutil.which("powershell")` resolves first) that emits a **UTF-8 BOM** — while `pending_upgrade_result()` parsed with `read_text(encoding="utf-8")` + `json.loads`, refusing a leading U+FEFF. Every deferred upgrade therefore reported `None`; the outcome surface could never fire.

**2. `Retry-After: 0` crashed failure classification.** The core parser accepts seconds >= 0 (a real upstream answer: *nothing to wait for*), but all four rate-limit mark sites fed values straight into `extend_reactive_block`, which raises <= 0 — turning a 429 carrying `retry-after: 0` into an exception out of error handling.

## The fix

Reader `encoding="utf-8-sig"`; helper emits BOM-less UTF-8 (`UTF8Encoding($false)` + `WriteAllText`) at both sites; new `_mark_rate_limited_when_positive` skips marks <= 0 at all four classification sites.
