## Description

Four defects, three reported as live failures against v5.60.0. Diagnosed from the request log across both databases (the WSL log holds everything before 2026-08-27; the live Windows log everything after).

## 1. NIM sent sampling parameters the client never asked for

`config/nim.py` declared `top_p`/`temperature` as **non-optional** floats defaulting to `1.0`:

```python
top_p: float = Field(1.0, ge=0.0, le=1.0)          # before
if body.get("top_p") is None and nim.top_p is not None:
    body["top_p"] = nim.top_p                       # guard is dead code
```

A non-optional `float` is never `None`, so the guard could never suppress it. Claude Code speaks the Anthropic protocol and sends no `top_p`, so **every** NIM request carried `top_p: 1.0`. NVIDIA now pins it per model:

> `400 Validation: top_p is immutable for this model and must be 0.95, got 1`

**This is long-standing, not a 5.5x regression.** `git diff v5.57.0..v5.60.0` over `config/nim.py`, `providers/nvidia_nim/` and `core/anthropic/conversion.py` is empty, and the injection line predates the 5.0 rebrand (`5a87c0b1`). NVIDIA's contract changed, not ours. `temperature` had the identical latent defect.

The same design made a deliberate `presence_penalty=0.0` indistinguishable from unset, because the builder tested "value equals the default". Every sampling field is now `| None = None` and every check is `is not None`.

## 2. max_tokens carried an invented ceiling

`nim.max_tokens` defaulted to `ANTHROPIC_DEFAULT_MAX_OUTPUT_TOKENS` and applied `min(client_value, 81920)`, truncating any model whose real limit is higher. models.dev `limit.output` is already parsed and already sizes the reasoning budget in `application/reasoning_gating.py`; the request body should not be clipped by an unrelated constant. Now unset by default, with a configured value acting as a deliberate operator cap.

## 3. Nous Portal rejected every API-key request

`/v1/chat/completions` requires a `tags` array with a `user=` entry. OAuth callers are identified by their bearer token, which is why it is undocumented. MCC has never sent it — `git log -S'user=' --all -- src/` returns nothing.

Enforcement began **2026-08-27**. `tencent/hy3:free` from the request log:

| day | ok | err |
|---|---|---|
| 2026-08-25 | 1870 | 0 |
| 2026-08-26 | 1390 | 0 |
| 2026-08-27 | 36 | **50** |

**Confirmed against the live API rather than inferred:**

```
no tags -> HTTP 400  {"status":400,...,"Additional info: missing tags"}
+tags   -> HTTP 200  {"model":"tencent/hy3:free","provider":"Tencent",...}
```

The tag goes in `extra_body`, not the top level: `body` is splatted as `**create_body` into an SDK whose `create()` has no `tags` parameter. `setdefault` throughout, so a caller-supplied value wins.

## 4. Route benching shipped switched off (the actual 5.58.0 regression)

`fallback_bench_enabled` defaulted to `False` and was **absent from `.env.example`**, while 16 other `FALLBACK_*` keys were documented there. Upgrading to 5.58.0 silently disabled ejection for every existing install:

- **v5.57.0:** `enabled = eject_after_failures > 0 and eject_seconds > 0` → True
- **v5.58.0+:** short-circuits on `bench_enabled` → False

`FALLBACK_EJECT_AFTER_FAILURES`, `FALLBACK_EJECT_SECONDS` and the whole rate-based block stayed set in user `.env` files and did nothing. A flapping model was re-tried at position 0 on every request instead of being parked for 30s — **12 `incomplete chunked read` failures on one `:free` model inside 50 minutes**, after four days at exactly zero.

Now defaults to `True`, is documented in `.env.example`, and the admin manifest default matches.

Two dead-code defects in the same PRs, both fixed:

- `execution.py` never passed `failure_kind`/`retry_after_seconds` to `record_failure`, so the kind-aware bench ladder in `route_health.py` never ran and every ejection used the full window.
- `_retried_positions` lived on `ProviderExecutor`, which is constructed once per handler and shared by every request, so retry-once fired **at most once per process lifetime**.

The retry-after lookup is deliberately total: it runs while a failure is already being recorded, where an exception would replace a real upstream error with an internal 500. That was not hypothetical — the first version of it turned eight API contract tests into 500s.

## Residual risks

- The Nous tag value is a constant (`user=my-claude-code`). Any `user=` value is accepted upstream; a configurable identity belongs with the per-provider parameter surface.
- Removing the 81920 clamp means a client asking for more now gets more. That is the intended correction, but it changes outbound `max_tokens` for NIM callers who were previously being clipped.
- The `incomplete chunked read` errors are genuinely upstream in origin — free-tier peers dropping bodies. This PR restores the guard that stops them being amplified; it cannot stop them occurring.
- Not done, deliberately: `parallel_tool_calls` is still written unconditionally, and a client's `top_k` is still dropped for every OpenAI-chat provider except NIM. Same class of defect, neither implicated in a reported failure, and changing tool-call behaviour deserves its own change.
