## What changed

Native **system tray app** (`mcc-desktop`) that controls the MCC server as a child process, with a persisted `~/.fcc/desktop.json` and optional startup-at-login.

- **Tray menu**: Open Admin · Check Server Status · Restart Server · Start at Login (toggle) · Tray Enabled (toggle) · Quit.
- **Config persistence**: `~/.fcc/desktop.json` (`tray_enabled`, `start_at_login`, `minimize_to_tray`, `server_auto_start`), atomic write, never raises on corrupt/missing.
- **Startup-at-login**: Windows HKCU Run key (`winreg`), macOS LaunchAgent plist, Linux `~/.config/autostart/*.desktop`.
- **Three surfaces**: the tray toggles, the CLI (`mcc-desktop --start-at-login/--no-start-at-login/--tray-enabled/--no-tray-enabled/--status/--export-icon`), and a minimal "Desktop" card on the dashboard (via `GET/POST /admin/api/desktop`).
- **Architecture**: the tray is a thin controller that spawns `mcc-server` as a child and drives it over the loopback admin API — no in-process supervisor (our fork has none).
- **Placeholder "MC" icon** at `assets/app-icon.png`, cleanly swappable when the real logo is provided.

Built with `/ui-ux-pro-max:ui-ux-pro-max` + `/ui-ux-pro-max:brand`.

## Residual risks

- `tray_enabled=false` only gates the *next* launch (a running tray can't remove its own icon portably).
- The server persists the JSON but never applies the OS autostart (headless-safe); the next tray/CLI launch reconciles.
- Wayland tray support is best-effort (pystray is X11-oriented).
