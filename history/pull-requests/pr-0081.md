## What changed

Introduce the native `my-claude-code` / `mcc-*` command family while keeping every
legacy `fcc-*` / `free-claude-code` command working as an alias for the same
implementation. This is the migration bridge: both command families are
interchangeable entry points into one shared codebase.

- Register `mcc-server`, `my-claude-code`, `mcc-init`, `mcc-claude`,
  `mcc-claude-old`, `mcc-codex`, `mcc-pi`, `mcc-chatgpt-oauth-login`, and
  `mcc-compact-log` in `[project.scripts]`, each pointing at the existing
  implementation.
- Add `core/identity.py` with a neutral `ToolOwner` model (`LEGACY_OWNER` /
  `NATIVE_OWNER`) that centralises the two command families, display names,
  stable launchers, and receipt/extras mapping.
- Make `core/version.py` owner-aware: `package_version()` and the new
  `distribution_name()` try the native distribution first and fall back to the
  legacy name.
- Derive the `--version` label from `owner_for_invocation()`.
