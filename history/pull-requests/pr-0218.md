## Description

The Limits page is now **Limits & Resilience**: six cards instead of one 37-field grid, and it finally shows the number that actually decides a handover — the per-model first-token allowance, computed for your own routes.

## What was wrong

Measured in Chrome against a clean v6.1.0 worktree, at 1600px:

| | v6.1.0 |
|---|---|
| Cards on the page | 3 |
| Fields in the largest card | **37**, one flat `.field-grid` |
| Advanced fields behind a single "Show advanced" | **13 of 37** |
| Words of help prose in that one card | **1,351** |
| Controls carrying `aria-describedby` | **0 of 54** |

Read top to bottom, that grid ran: output budgets → deadlines → shutdown → benching → eject mode → rate knobs → provider retries → stream retries → commit holdback → rate-limit cooldown → the auth lockout ladder → cooldown step-over → three retry backoffs → nine request-log storage fields → `LOG_LEVEL`. "Output tokens when unknown" sat in the same visual row as "First-token deadline", and nothing said which of the two the other depended on.

Eight settings that belong to the same decisions were on *other* pages. `FALLBACK_REASONING_ANSWER_TIMEOUT` is the deadline that silently pre-empts the first-token deadline once a model starts thinking — it was on Model Config. `HTTP_READ_TIMEOUT` is the transport ceiling underneath every deadline on the page — it was on Providers, with no description at all.

And the number that decides a handover was shown nowhere. `_attempt_deadline` divides the remaining budget by the attempts still to come, and `_chunk_timeout` then takes the smaller of that share and the first-token deadline. So the first model of a chain of N gets

```
min(FALLBACK_FIRST_TOKEN_TIMEOUT, FALLBACK_TOTAL_TIMEOUT / N)
```

On the shipped defaults and this machine's real ten-model Opus chain that is **60 s**, while the box on the page read 120 and was inert for that route. A healthy model that needs 70 s to think was ejected at 60, and the page said 120.

## What to expect now

Six cards behind a sticky in-page rail with scrollspy — Budgets, Deadlines, Chain benching, Retries & throughput, Credential health, Diagnostics — each stating what it decides in one line. `e-after-limits-top.png`, `e-after-limits-full.png`.

**The Deadlines card computes the real allowance for every route you have configured.** One row each, the arithmetic written out, and a warning naming the budget that *would* honour the number you asked for. On this machine's live config it reads:

```

to produce its first token.
= the smaller of the first-token deadline (120 s) and its share of the
  total budget (600 ÷ 10 = 60 s).

Warning: The first-token deadline never applies on this route -- the budget
share is smaller. A total budget of 1200 s would give every model the 120 s
you asked for.

Route     Models   First-token share
Default   4        120 s
Fable     8        75 s
Opus      10       60 s
Sonnet    7        86 s
Haiku     5        120 s
Vision    6        100 s
```

`e-after-deadlines-calculator.png`. A route with no model of its own is skipped — it falls back to `MODEL`, so counting it would double-count Default. The card's own caveat line says what it does not model: time already spent, a retried first model, benched models shortening the chain, or the reasoning path taking over.

**Chain benching is a master switch, a mode, and the mode's own knobs.** The unselected mode's controls stay on the page, dimmed and disabled, with the reason written beside them rather than implied by the dimming — so you can see what the other mode would cost without losing what you typed. `e-after-benching-rate.png`, `e-after-benching-inert.png`.

## Known and deliberate

- **`advanced=True` dropped from five fields** — the four output budgets and `CREDENTIAL_LOCKOUT_TIERS`. With the grid split, the card is the progressive disclosure. #216 shipped all five of its new keys advanced, which would have left Credential health rendering a heading, a description and nothing operable. Eight advanced fields remain, spread across four cards, and a static guard plus a jsdom assertion now make "a card with no control you can reach without a click" fail loudly.
- **The unselected mode's knobs are disabled, not removed or hidden.** `changedValues()` already skips a disabled control, so the unused mode is never submitted and the counter never counts it — no new code in the dirty machinery. Removing them would lose a value typed before the switch; `hidden` alone would leave them enabled and therefore *saved*.
- **`FALLBACK_SKIP_KINDS` stays on Model Config**, cross-linked rather than rendered twice. A setting on two pages is a setting that can show two answers, and `changedValues()` would submit whichever control it walked last.
- **Three existing screenshots are not re-captured** (`admin-model-config.png`, `admin-page.png`, `admin-analytics.png`), though their pages changed. `docs/RELEASE-CHECKLIST.md` now names them, adds the new `admin-limits.png`, and records for the first time that the in-dashboard Guide serves its **own** copies under `admin_static/img/` and that the two sets must move together.
- **`PROVIDER_RATE_LIMIT`, `PROVIDER_RATE_WINDOW` and the three HTTP timeouts keep manifest defaults that mirror `.env.example` rather than the code default.** Moving them onto this page put them under a default-matching test that had no escape hatch; the divergence is deliberate and already recorded with reasons in `DEFAULTS_THAT_DIFFER_FROM_THE_CODE`, so the narrower test excludes them and the generalised one still covers them. Not changed here — that is a defaults question, not a layout one.

## Residual risks

1. **Muscle memory breaks.** Eighteen fields are on a different page and the page changed name. Mitigated by the intro line naming where storage and desktop settings went, and by this note; not mitigated for anyone who bookmarked a scroll position.
2. **Switching eject mode silently drops a pending, unsaved edit to the other mode's knobs** from the Apply payload. The value stays in the box; it is simply not sent. The counter falls at the moment of the switch so it is visible, and the card says so — but a user who edits, switches, and Applies will not have saved the first edit. The alternative, submitting a knob the selected mode ignores, was judged worse.
3. **The calculator is a model of the executor, not the executor.** It reproduces `_attempt_deadline` + `_chunk_timeout` at position 0 with a fresh budget. It does not model time already spent, `FALLBACK_RETRY_FIRST` adding an attempt, benched models shortening the chain (which *raises* everyone's share), or the reasoning path taking over. The caveat line says so. A drift guard against `execution.py` is impossible without a shared Python↔JS formula; the jsdom tests pin the three arithmetic cases against hand-computed values, so a change to the JS is caught even though a change to `execution.py` is not.
4. **`_with_range` no longer appends the bound to the description.** Any consumer reading `field.description` and expecting the range loses it. Grepped: `field.description` has two readers in `config/admin/` — `_with_range` itself and `values.py`, which publishes it to the browser. `.env` rendering does not include descriptions. `tests/config/test_limit_bounds.py` asserted `"Accepts" in field.description` and now asserts `field.range_hint == describe_range(limit)` instead.
5. **Section-order churn in the managed `~/.fcc/.env`.** `render_env_file` groups by manifest section, so the next Save rewrites the file with six headings where there was one. Values untouched; the diff looks larger than it is.
6. **Six cards is still one long page** (5,835 px). The rail makes it navigable but nothing is collapsed by default. If that is still too long the next step is `<details>` per card with the open state persisted — deliberately not done here, because a settings page whose sections are shut by default is how the Models page got its "prose with nothing under it" problem.
7. **The rail costs a grid column** at 1600px (four columns to three). Field descriptions gained width each (281.5px → 294px), but the page is taller for it.
