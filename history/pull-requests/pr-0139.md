## Description

## ⚠️ Anthropic does not permit this

Adds `anthropic_oauth`, which routes requests using the OAuth credential from a Claude Pro/Max subscription — discovered from Claude Code's own `~/.claude/.credentials.json`, or obtained via `mcc-anthropic-oauth-login` (PKCE).

From [Claude Code → Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance):

> **OAuth authentication** is intended exclusively for purchasers of Claude Free, Pro, Max, Team, and Enterprise subscription plans… **Anthropic does not permit third-party developers to offer Claude.ai login or to route requests through Free, Pro, or Max plan credentials on behalf of their users.**
>
> Anthropic reserves the right to take measures to enforce these restrictions and may do so without prior notice.

This ships at the repo owner's explicit instruction, for their own account, after that policy was quoted to them. [`docs/ANTHROPIC-SUBSCRIPTION.md`](docs/ANTHROPIC-SUBSCRIPTION.md) is the disclaimer and states this plainly — it does **not** claim an "inside Claude Code" exemption, because there isn't one.

## The gate — the part worth reviewing

Claude Code stamps an attribution line at the head of the **system prompt**, inside the request body:

```
x-anthropic-billing-header: cc_version=2.1.235.2db; cc_entrypoint=cli;
```

Measured on real traffic through this proxy:

| Source | `cc_entrypoint` |
| --- | --- |
| Claude Code terminal CLI | `cli` |
| Python Agent SDK | `sdk-py` |

Because the marker travels in the body, a proxy can neither forge it for traffic it didn't receive nor strip it from traffic it did.

**So the provider refuses, by default, any request not reporting `cli`**, with an error pointing at the `anthropic` (Console API key) provider instead. That turns "only within Claude Code" from a README promise into something the router enforces — and specifically stops Agent SDK traffic, the case the policy names explicitly, from silently borrowing the subscription.

Controlled by `ANTHROPIC_OAUTH_REQUIRE_CLAUDE_CODE` (default `true`).

## Credential handling

- MCC's store: `~/.fcc/anthropic_oauth.json`, mode `0600`, atomic write.
- **Claude Code's file is read-only to MCC and never refreshed in place** — rotating it would log out the user's real client.
- Claude Code stores `expiresAt` in **milliseconds**; the token endpoint returns **seconds**. Both normalise, with a test.

## Two of my own mistakes, caught by the contract tests

Both fixed properly rather than worked around:

1. `cli/` may not import a provider **submodule** — registered a documented `IMPORT_EXCEPTIONS` edge matching the existing `chatgpt_oauth` precedent.
2. My first smoke-config check called `detect_available_sources()`, which reads the real filesystem — making the suite depend on whether the machine running it happens to be logged in to Claude Code. Now an explicit-setting check only.

## Residual risks

- **No live request has been made against `api.anthropic.com` with a subscription credential.** The gate, headers, tool prefixing, credential loading and refresh are tested against fakes. Whether Anthropic accepts, refuses, or flags this traffic is **unknown**.
- The `claude-cli` User-Agent asserts the request came from Anthropic's official CLI. The gate is what keeps that assertion true — but the assertion is made by MCC, not Claude Code.
- MCC's retry layers have no shared deadline (Part IX); a pathological case can produce more upstream attempts than a real client would.
- The enforcement risk is to the **Claude account whose credential is used**.
