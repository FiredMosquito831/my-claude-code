## Description

## What was missing

Fallback chains shipped in 4.31.0 with **no way to tell they had fired**. A request served by the second model in a chain looked identical to one served by a healthy primary — the row named the model that answered, which is correct, but nothing said it was not the one the route picked.

So a primary could be failing every single request, silently, and the dashboard would look fine.

## The data

Two new columns, both migrated with `ALTER TABLE` for existing databases:

- `route_attempt` — 0 for the route's own model, 1+ for a fallback
- `route_primary_model` — recorded only when a later attempt answered, because otherwise it just repeats `resolved_model`

The executor already called back on every attempt so analytics could name the model that answered; it now passes the attempt index with it, and the capture remembers the first model it saw.

## Surfaced three ways

"Did failover happen" and "what is failing" are different questions:

- a **Served by fallback** stat card, as count and share
- a **Failover** panel listing `primary → what covered for it` by volume, so a consistently failing primary is obvious
- a **badge on the affected row**, plus the full route in the detail panel

## Old rows say nothing, not zero

Rows written before this version have no route data at all, which is **not** the same as "no fallback was used". The store counts non-null `route_attempt` separately and the card renders an em dash rather than a reassuring `0.0%` for traffic it knows nothing about — the same distinction the cache columns already make, and for the same reason.

## Residual risks

- **No browser in this environment**, so the badge and the Failover panel are not observed rendering.
- `route_primary_model` stores the ref the route resolved to first. If a chain falls back twice, the panel attributes the save to the original primary rather than the intermediate that also failed — deliberate, since the question people ask is "what did my configured model fall back from", but it does mean a middle link failing is not separately visible.
- Backfill is impossible: rows before this version never stored the information, so any share over a window spanning the upgrade is computed only over rows that report it.
