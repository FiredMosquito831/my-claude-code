## Description

## What was broken

Every \`install.sh --version <pin>\` died at the checksum step. The pinned path intentionally ships no digest ("No release feed is read for an explicit version"), but the downloader compared unconditionally — guaranteed \`checksum mismatch\`. Two audit-probe-confirmed secondary defects rode along: the digest extractor never reset its asset scope, so a target asset published without a digest borrowed the NEXT asset's digest; and the comment describing GitHub's body/assets position was inverted.

## The fix

- Pinned installs now fetch the **tag-scoped feed** (\`releases/tags/v<version>\`) so they stay **verified**; only an unreachable feed downgrades to an explicitly-warned unverified download; a readable feed that omits the wheel's own digest refuses loudly rather than trusting anything.
- \`extract_wheel_digest\` hard-scopes awk to the matched asset object: name-match opens the scope, the asset's own \`browser_download_url\` closes it, and release-body prose can never satisfy it.
- Corrected the inverted comments (script + fixture); four new scenarios cover pinned-verified / unreachable-feed-proceeds-unverified / missing-digest-refused-despite-sibling / latest-path regression.
