## Description

Audited all 14 adapters against their providers' current API references. MINOR `4.19.0` → `4.20.0`.

## Bugs

**Linkup never sent `maxResults`.** Every call returned the provider's default set and paid for results the client-side slice then discarded. Its catalog also omitted the documented `fast` depth — the cheapest tier was unreachable — and the full extracted page text Linkup returns in `content` was dropped rather than carried as item content. Added the documented `fromDate`/`toDate` range.

**Parallel targeted a beta endpoint with the wrong vocabulary.** The adapter posted to `/v1beta/search`, whose `mode` enum is `fast|one-shot|agentic`, while the catalog exposed v1's `turbo|basic|advanced` — so *every* configured mode was invalid for the endpoint actually called.

Migrated to `/v1/search`, which is what the catalog already described:
- `mode` and `max_chars_total` stay top level
- `max_results` and `excerpt_settings` move under `advanced_settings`
- `source_policy` makes domain filtering real — `SUPPORTS_DOMAINS` was `False` despite `include_domains`/`exclude_domains` being documented, so `base.py` zeroed the filters before the adapter ever saw them

**Firecrawl's `limit` is per source type.** Requesting `max_results` from each of N sources fetched and billed N times what the caller could use. Now divided across configured sources.

**Tavily didn't clamp `max_results`** to the documented 0-20, leaving the provider to reject oversized requests.

## Every option now documents itself

37 of 53 options had no `cost_note`, so the admin UI rendered the literal string `"Dotenv-only advanced option."` — which tells an operator nothing about what leaving the field blank does. All 66 now state their empty behaviour ("Empty = us", "Empty uses Brave's own default (moderate)", "Empty = provider default (3)"), with a contract test so it can't regress.

## Deliberately not done

**Credits are not dollars.** Firecrawl's `creditsUsed`, Tavily's `include_usage` and Parallel's `usage` report credits and SKU counts. Converting them into `cost_usd` needs a hardcoded price table that goes stale silently and misreports spend — so cost stays populated only where a provider reports actual currency (Exa's `costDollars`). Flagging this because "wire up cost for more providers" looks like an obvious win until you see what it would require.

## Verification

New tests assert `maxResults` is sent, Linkup's date range, Parallel's `source_policy` nesting and v1 endpoint, Tavily's clamp, Firecrawl's per-source division, and safe search reaching three providers. The catalog contract table was regenerated, and it caught the Parallel descriptor still declaring `supports_domains=False` — exactly what it exists for.

`ruff format`, `ruff check`, `ty check` clean; no suppressions.

Full suite passes except **14 failures that also fail on unmodified `main`** — 8 from real API keys in the local environment defeating `Settings()` isolation, 6 PowerShell installer tests.

## Residual risks

Parallel's v1 migration is the highest-risk change here: I verified the request shape against the published v1 schema and the beta→v1 migration guide, but could not exercise it against the live API without a key. If Parallel is in use, worth a single real search to confirm before relying on it.
