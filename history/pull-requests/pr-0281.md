## Description

Follow-up to #280. The `macos-universal (dmg)` job on the v6.45.2 release
**built and imaged correctly** and then failed in the smoke, on its second
line, before a single assertion ran:

```
== My Claude Code: macOS .dmg smoke ==
  ok: image present: 4926308 bytes, 26ed2309536cefa44cc64422d583634e769d17a11d809b27646f909d690545a8
##[error]Process completed with exit code 1.
```

## Cause

`smoke/macos-dmg.sh` runs under `set -euo pipefail`. Its snapshot helper lists
both application directories:

```bash
{
    ls -1a /Applications 2>/dev/null | sed 's|^|/Applications/|'
    ls -1a "$HOME/Applications" 2>/dev/null | sed 's|^|~/Applications/|'
} | LC_ALL=C sort
```

A runner has no `~/Applications`. `ls` exits 2; `2>/dev/null` hides the
message but not the status; `pipefail` makes the whole pipeline non-zero; and
`snapshot > "$before"` under `set -e` ends the script. Reproduced locally in
Git Bash — the old form exits 2 with `HOME` pointed at a directory with no
`Applications`, the guarded form exits 0 with zero lines.

## Two more of the same class, found while fixing it

- `read_key` is `defaults read … 2>/dev/null`, which exits non-zero for an
  absent key — and an assignment whose command substitution fails ends the
  script under `set -e`. A missing plist key would have produced a silent exit
  instead of the named assertion two lines below.
- The `Authority=` extraction piped `sed` into `head -n 1`, which can close
  the pipe early and make the substitution non-zero. `sed` already prints
  nothing when there is no authority — which is exactly the case being
  asserted — so `head` was never needed.

## Guard

`tests/contracts/test_uninstaller_parity.py::test_the_dmg_smokes_snapshot_survives_a_missing_applications_directory`
parses the snapshot helper out of the script and asserts both listings carry
`|| true`, plus the `read_key` guard. This is not a bug anyone re-reads a
script and spots; it is one you only see on a machine that lacks the
directory.

## Not a release

No version bump. The wheel is unaffected — v6.45.2 is published and correct,
and this touches one shell script and one test. The shell build gets
re-dispatched against that tag with `-f ref=main`, which is the documented
backfill shape.

## Consequence of the failure, stated plainly

Because `release` needs `macos-dmg`, the failed job meant **no** shell assets
were attached to v6.45.2 — not just the `.dmg`. That is the workflow's
existing and deliberate semantics (`release` already needs every build leg:
"a failed leg means no upload happens at all"), so it is not changed here; the
re-dispatch attaches all eight.
