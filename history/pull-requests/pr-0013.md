## Description

Three changes. 4.17.0 -> 4.18.0.

## 1. The daily budget is gone

I added a per-key daily quota in 4.17.0. It was the wrong idea: any number FCC picks for a provider is a guess, and a wrong guess throttles a key that was fine. NVIDIA NIM publishes an RPM limit and **no daily cap at all**, so a daily budget there is pure invention.

Removed: `DailyQuotaTracker`, `{ENV}_DAILY_LIMIT`, `{ENV}_QUOTA_RESET_UTC_OFFSET`, their config readers, tests, and docs.

**What stays** is the part that reads real signals:
- the 429's own `Retry-After` / `X-RateLimit-Reset` window
- skipping a credential whose limiter says it cannot serve yet

Both come from the upstream response. No ceiling is invented anywhere.

## 2. The installers install only the proxy

They no longer install Claude Code, Codex, or Pi. Those are separate third-party tools the proxy doesn't need, and bundling them turned an unrelated npm/PATH problem into a failed **Free Claude Code** install. The script now does uv + the proxy, and points out which `fcc-*` launchers exist for agents already present.

## 3. The installers always install the latest release

No more pinned version or checksum. Both scripts read the latest release, take the **SHA-256 GitHub publishes for that asset**, and verify the download against it. So the published command always installs the newest release rather than whatever was current when the docs were written — and cutting a release no longer means updating pins in three files.

`--version 4.16.0` / `-Version 4.16.0` pins an exact release when reproducibility matters.

README install URLs now point at `main` instead of a tag, for the same reason.

**Trade-off worth naming:** the digest and the wheel now come from the same source (GitHub), where before the checksum was pinned in the script. The wheel was always fetched from GitHub, so this mainly protects against a corrupted or truncated download rather than a compromised release. `--version` plus a manual hash check remains available for anyone who wants the stricter posture.

## Test changes

`FCC_VERSION` in the contract tests is now `9.9.9` — a deliberately fake value served by a stubbed release feed, which **proves the installer reads the feed rather than a pin**. Both harnesses stub the API (POSIX via the fake `curl`, PowerShell via the `Invoke-RestMethod` override). I verified the fixture JSON against the real `resolve_release()` extraction in a WSL shell: it yields `9.9.9` and the digest.

13 agent-related tests and their fixtures removed. The fresh-install test now asserts the feed was read and that **claude.ai / chatgpt.com / pi.dev are never contacted**.

## Docs

Claude Desktop gateway setup now uses real screenshots of the Developer menu and the third-party inference dialog, with the fields that dialog actually has (Credential kind, Model discovery, Apply Changes) rather than borrowed third-party images.
