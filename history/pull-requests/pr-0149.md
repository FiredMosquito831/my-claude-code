## Description

## The gap

v5.25.0 shipped `anthropic_oauth` with everything it needs in Python — credential discovery, PKCE login, refresh — and wired **only a CLI command**. `admin.js` contained **zero** references to it, so from the dashboard the provider was unreachable: no way to see whether a Claude Code credential existed, no way to import it, no way to sign in.

`chatgpt_oauth` already solves exactly this, so the shape is **mirrored rather than invented** — a manifest pseudo-field renders the controls, the endpoints sit beside their ChatGPT counterparts, and the paste-code flow behaves the same.

## What the card does now

- **Use Claude Code credentials** — enabled only when `~/.claude/.credentials.json` is actually present, and shows a masked summary before you commit.
- **Sign in with Anthropic** — the PKCE flow, opening the authorize URL and taking the pasted code.
- A status line for the real state: none / imported / signed in / expired.

## Three things this had to get right

Each has a test that was broken on purpose and confirmed to fail **by name**:

| | Guard |
| --- | --- |
| **`~/.claude/.credentials.json` is read-only to MCC** | snapshots the file's bytes and mtime under a redirected `HOME`, runs the import, asserts neither moved |
| **No raw token in a response body** | asserts the secret appears *nowhere* in the response — not just in the field someone remembered to mask |
| **The disclaimer is on the card, before either button** | asserts the warning renders as a warning |

Import means *read, then write into MCC's own store*. Claude Code's file is never written and never refreshed in place.

The disclaimer matters because this provider uses a subscription credential in a way Anthropic's published policy forbids for third-party tools, and the only thing between a user and an account-level consequence is that the product says so:

> Anthropic does not permit routing requests through Free, Pro, or Max plan credentials in third-party tools, and this provider additionally refuses any request that does not report `cc_entrypoint=cli`.

It reuses the existing `guide-note-warn` class rather than inventing one — which the asset-wiring guard added earlier this week would otherwise have failed.

## Import boundary

`api` may not import a provider package directly, so the edge is registered in `IMPORT_EXCEPTIONS` with the same `Owner:`/`Reason:` annotations `chatgpt_oauth` uses — the documented mechanism, not a bypass.
