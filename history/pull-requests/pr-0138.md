## Description

## What

Adds `anthropic` — MCC's first first-party Claude provider, speaking Anthropic's native Messages API at `api.anthropic.com` with a **Claude Console API key**, billed per token.

MCC had **54 providers and none was Anthropic**. Claude was only reachable second-hand (resold via Kilo/Nous/Cline, or through Bedrock/Vertex). This closes that gap.

This is the authentication method Anthropic documents for software calling Claude on a user's behalf — see [Claude Code → Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance):

> Developers building products or services that interact with Claude's capabilities … should use API key authentication through Claude Console or a supported cloud provider.

## Mechanism

The neutral Messages transport already existed from the Command Code work, but hardcoded `Authorization: Bearer` — Command Code's contract. Anthropic's own API needs `x-api-key` plus a required `anthropic-version` header.

So `AnthropicMessagesProvider` now takes an **injected auth strategy** rather than growing a second copy of the streaming loop. `BearerTokenAuth` remains the default, so Command Code's wire behaviour is unchanged and pinned by a regression test.

## One real bug caught before it shipped

The upstream base URL is bound to **`ANTHROPIC_UPSTREAM_BASE_URL`**, deliberately *not* `ANTHROPIC_BASE_URL`.

`ANTHROPIC_BASE_URL` is the variable that points Claude Code **at** MCC. Had the provider read it, every user who followed our own setup docs would have had the proxy dial its own listener and loop forever. A test pins the binding and carries the reason.

## No invented metadata

Anthropic's `/v1/models` publishes no context length, pricing, or capability flags. Every optional field is left `None` — "not reported", not "absent" — so models.dev enrichment can fill it and vision routing won't divert on merely-unknown image support (Part IV.1).
