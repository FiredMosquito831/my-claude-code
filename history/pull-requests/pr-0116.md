## Description

Turns **Configure Claude Code** from a two-key connect screen into a real settings editor, on top of the API from #115. The existing "Choose how you connect" section is unchanged above it.

## What it looks like

Rendered from the generated catalog, so the controls track upstream: **504 editable settings**, each drawn as what it actually is — a dropdown with the documented options for an enum, a number field for a number, a masked field for a credential, a JSON textarea for an array or object.

Volume is handled with **search + a curated default**, not accordions:

| | |
| --- | --- |
| Default view | **101 settings** people actually reach for |
| `Show all` | the remaining 400 |
| Search | always covers **everything**, including entries the view filters would hide — typing a variable name in full always finds it |
| `Configured only` | narrows to what the file sets |

Edits collect as pending changes and are written only from a **review dialog** showing a real diff — key, before, after — plus any warning the backend attached, and a note that the file is backed up first.

## Two bugs the browser found that the API tests could not

- **`permissions.defaultMode` rendered as a text box, not a dropdown.** The enum table is keyed by the name the docs use in their own table (`defaultMode`) while nested entries are catalogued with their parent prefix (`permissions.defaultMode`), so the lookup missed and **every nested enum silently degraded to free text**. The API test *"every enum entry has values"* still passed — because the entries were no longer enums. Lookup now tries the full key then the bare leaf.
- **A value the editor had just written read back as unset.** `read_values` returned the `permissions` object but not the dotted leaf the UI addresses, so writing `permissions.defaultMode` and reloading showed "Not set". Nested groups are now flattened to dotted leaves, parent included, with 4 regression tests.

## And a visual bug this page already had

The 5.7.2 redesign used `var(--space-N)` tokens that were **never defined**, so every rule using them was invalid and dropped — the connect cards shipped with **no padding and no gap**. Defining the scale fixes them (measured 0px → 16px).

## The three traps, surfaced not just handled

- A presence-read variable carries a **`presence` badge**, and turning it off shows in the diff as *"1 → removed"* with a line explaining that writing `0` would have left it enabled.
- A masked secret is **never echoed back as a write**: the field starts empty with a *"Set — type to replace"* placeholder, so applying without touching it can't overwrite the real key with asterisks.
- A **managed policy** that outranks the file is called out above the list, naming the file and the keys it pins.
