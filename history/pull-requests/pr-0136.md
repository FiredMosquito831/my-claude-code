## Description

## What was wrong

Claude Code did receive `ENABLE_WEB_SERVER_TOOLS=true`, and the dashboard/proxy setting was enabled. The failing `WebSearch` utility call nevertheless returned:

```text
MCC cannot pass listed Anthropic server tools (web_search / web_fetch) to OpenAI Chat upstreams
```

The dedicated Claude Code utility request contains exactly one server-tool definition with `tool_choice={"type":"auto"}`. MCC's selector recognized only explicit `tool_choice={"type":"tool","name":"web_search"}` requests. Because unsupported-tool validation runs before local interception, the enabled request was rejected before the local web-search handler could run.

## What changed

- Treat a singleton canonical `web_search` or `web_fetch` definition with `tool_choice:auto` as an unambiguous local server-tool request.
- Keep absent `tool_choice`, mixed custom/server lists, and `web_search`+`web_fetch` auto lists ambiguous and rejected rather than guessing what the upstream model would choose.
- Share the same selector between validation and streaming so the guard and handler cannot disagree.
- Improve the error text for genuinely ambiguous lists.
- Bump `5.23.2` to `5.23.3` and refresh `uv.lock`.
