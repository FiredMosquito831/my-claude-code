## Description

Two bugs in the release smokes, both found by the first real four-platform dispatch ([run 33870226408](https://github.com/FiredMosquito831/my-claude-code/actions/runs/33870226408)), neither findable from the Windows-only local run that preceded #273.

**Windows passed end to end on that dispatch. Linux, macOS arm64 and macOS x86_64 all failed in the smoke step.**

## 1. A relative binary path did not survive the `cd`

The POSIX smokes launch the shell from inside the scratch directory. The workflow passes the binary as a path relative to `desktop-shell/`, which resolves to nothing there:

```
_posix.sh: line 162: src-tauri/target/.../release/MyClaudeCode: No such file or directory
SMOKE FAIL: the shell died after reading its status
```

The message named neither the cause nor the fix. The path is now made absolute immediately after the existence check, before the scratch directory exists. Windows was unaffected because `Resolve-Path` already did this — which is precisely why a local Windows run could not find it.

## 2. The "the shell ran the stub" assertion was vacuous — on all four platforms

Step 2 calls the stub twice itself (once for `--print-status`, once to assert the exit code for an unknown flag), so the call log was already non-empty when step 3 began waiting for it. The wait returned immediately.

That is how three legs printed `ok: the shell ran the stub` and *then* failed on the next assertion: the binary had never started at all. The log is now emptied immediately before the launch, so the wait means "the **shell** ran it" rather than "somebody ran it at some point". Windows gets the same fix.

This is the more serious of the two. Bug 1 made three legs fail loudly; bug 2 would have let a leg pass while proving less than it claimed.

## 3. A cosmetic one, found while fixing 2

`Get-Content` on a one-line file returns a string, not an array, so `$calls[0]` was its first character and the Windows smoke reported `ok: the shell ran the stub: -`. Forced into an array.

## Verified

`smoke/windows.ps1` re-run locally against the real release binary: passes, exit 0, and now reports `ok: the shell ran the stub: --print-status` from the shell's own call rather than from step 2's. The POSIX fixes are verified by syntax check and by the path expression itself; their real proof is the re-dispatch after this merges.

No Python change, so no version bump and no release.
