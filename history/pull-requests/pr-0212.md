## Description

Twenty-one profiles carried the `NoReasoning` encoder, whose `encode()` body is
literally `return`. One of them -- Command Code -- turned out in 5.69.0 to be
silently miswired rather than deliberately quiet, so every other one had to be
re-examined on evidence rather than assumed correct. This is that audit, and the
two defects it found.

The trap is that `NO_REASONING` does not imply "broken". Many models reason by
default and hand it back unasked: OpenCode shows 25.6% of requests carrying
thinking while this proxy sent no reasoning field at all. So the question is
empirical per gateway, and the decisive evidence is not documentation but a
deliberately invalid value -- an unknown `reasoning_effort` makes a gateway name
its own accepted enum in the 400, which is the only statement of dialect that
cannot be out of date.

## What changed

**OpenCode Zen** now sends `reasoning_effort`. Its gateway parses that field and
nothing else: a top-level `reasoning` object, a `thinking` object and
`chat_template_kwargs` all return 200 and are silently discarded, even with a
deliberately invalid value inside. An invalid `reasoning_effort`, by contrast,
400s with the enum spelled out -- and the same enum came back from five models
across two different upstream stacks, one Console-hosted and one
pydantic-validated. That enum is FCC's own effort ladder plus a `none` rung, so
the mapping is the identity and reasoning OFF finally has a wire value instead
of being dropped on the floor. This is the same class of defect as Command
Code's, hidden behind a healthy-looking thinking rate that was the upstream's
default, not the client's request.

The return path was wrong too, in the way 5.69.0 warned about. OpenCode streams
`reasoning_content` deltas, never `<think>` tags in `content`, but the profile
replayed assistant history as THINK_TAGS -- inlining prior thinking into the
visible content of the conversation. Replay is now REASONING_CONTENT, the field
it arrives on; an assistant turn carrying that field was probed and accepted.

**DeepSeek** was a false positive on the encoder and a real defect on the
vocabulary. Its `NO_REASONING` is dead configuration -- `DeepSeekProvider`
overrides `_build_request_body` and never reaches the profile postprocessors --
because reasoning is encoded in `_apply_deepseek_chat_extras`. That encoder
collapsed six requested efforts onto two wire values, `max` for XHIGH/MAX and
`high` for everything else, so a request for MINIMAL bought HIGH's latency and
tokens and MEDIUM was indistinguishable from HIGH. DeepSeek's own
deserialization error names `none, minimal, low, medium, high, xhigh, max` --
FCC's ladder exactly, value for value -- so the translation is now the identity.
The OFF and no-effort shapes are unchanged.

Everything else is comments. Each remaining `NO_REASONING` now carries a dated
note saying what was checked, what the evidence was, and why nothing is sent, so
the next person does not repeat this. A profile that is correctly quiet is
recorded as a verdict, not left ambiguous.

## Verification

DeepSeek names its enum (HTTP 400, validation runs before billing):

    reasoning_effort=bogus -> HTTP 400 "Failed to deserialize the JSON body into
      the target type: reasoning_effort: unknown variant `bogus_value`, expected
      one of `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`"
    thinking.type=bogus    -> HTTP 400 "thinking.type: unknown variant
      `bogus_value`, expected one of `adaptive`, `enabled`, `disabled`"
    reasoning{effort=bogus}-> HTTP 402 (unparsed: reached billing, so discarded)

OpenCode, same enum from four models on two upstream stacks:

    hy3-free                   -> 400 "reasoning_effort must be one of: no_think,
                                   none, off, minimal, low, medium, high, xhigh, max"
    ling-3.0-flash-fin-free    -> 400 "reasoning_effort: Invalid option: expected
                                   one of max|xhigh|high|medium|low|minimal|none"
    nemotron-3-ultra-free      -> 400 (same)
    nemotron-3.5-lightning-free-> 400 (same)
    big-pickle                 -> 400 "Input should be 'none', 'minimal', 'low',
                                   'medium', 'high', 'xhigh' or 'max'"

OpenCode discards the other three dialects (all HTTP 200, reasoning still
returned, invalid values included), and accepts `reasoning_content` on an
assistant turn (HTTP 200).

(default-on, hence the disguise); nvidia_nim 18,744/24,620 (its own builder,
working); commandcode 0/16,875 on rows predating the 5.69.0 fix.

## Not done

`opencode_go`, `cline` and `kimi_coding` are all suspected to be wired wrong and
are all left alone, because a wrong encoder 400s a provider that works today and
none of the three could be probed -- no credit, no credential, and a dead
endpoint respectively. `siliconflow`'s numeric `thinking_budget` has no existing
encoder and inventing one is outside an audit. `ReasoningControl.ADAPTIVE` has
no encoder anywhere, though DeepSeek's `thinking.type` accepts `adaptive`; noted,
not built. The echo-susceptible substring matching in `mistral/reasoning.py` and
`deepseek/tool_choice.py` (PR #210) is untouched.

## Residual risks

- **OpenCode's frontier models could not be probed.** The `claude-*`, `gemini-*`,
  `gpt-5.6-*`, `grok-*`, `minimax-m3` and `kimi-k3` rosters return HTTP 401
  CreditsError before body validation, so the enum is proven on the free tier
  and on `big-pickle` only. Two independent validators agreeing, plus 89 of 94
  models.dev rows reporting reasoning, is the basis for extending it to the
  whole gateway. If a paid model rejects `reasoning_effort`, that request 400s
  where it previously succeeded.
- **DeepSeek's low rungs are newly reachable.** `minimal`, `low` and `medium`
  were never sent before this change; they are in the enum the API itself
  publishes, but they have not been exercised against a billed request (the
  audit credential has no balance, and DeepSeek validates before it bills).
- **OpenCode replay changed shape.** Assistant history now carries
  `reasoning_content` instead of an inlined `<think>` block. Probed as accepted,
  but it is a different body than yesterday's for every multi-turn conversation.
- The three SUSPECTED providers are deliberately left broken-if-broken. That is
  the conservative side of the trade, and it is recorded in each profile.
