## Description

# Every OpenAI-compatible host now asks for reasoning, and a host that says no is believed once

Twenty hosts were wired to send **nothing at all**. They now speak the standard `reasoning_effort` field, the per-model capability gate decides which models actually get it, and a host that refuses it says so with a 400 — which is stripped, retried once, and remembered per model instead of being paid again on every request.

## What was wrong

`providers/openai_chat/profiles.py` carried ~20 hand-written `NO_REASONING` verdicts from the 5.70.0 audit. `NoReasoning.dialect` is a bare `ReasoningDialect()` — "this host has no reasoning field of any kind" — so `provider_manager.model_reasoning_dialect` handed gating a flat no and `application/routing.py` correctly emitted nothing. Whatever the model could do, whatever the client asked for, twenty hosts were answered with silence. **The #219 pipeline was not broken for them; it was starved.**

Reading all twenty comments back, **not one records a host that rejected `reasoning_effort`.** The evidence divides into exactly three kinds:

- **"Mixed roster, one encoder cannot be right"** — `huggingface`, `xai`, `together`, `chutes`, `bedrock`, `github_models`, `azure_openai`, `alibaba` ×4, and the generic profile. This is a *model*-level objection, and per-model capability gating is its answer. Stale, not wrong-at-the-time.
- **"The probe was blocked by the account, not the API"** — `opencode_go` (401 before validation), `kimi_coding` (500 to everything), `novita` (403 before validation), and five where no credential was checked.
- **"A different control is documented"** — DashScope's `enable_thinking`, SiliconFlow's numeric `thinking_budget`. These say the host has *another* knob; none says it refuses the standard one.

And there was no safety net anywhere. A host that genuinely refuses the field could only fail, every request, forever.

**Zero hosts named an enum.** Four had a credential and all four answered *before* validating the body — which is itself the 5.70.0 finding, reconfirmed. `opencode`'s 400 on a valid `"medium"` as well as on garbage is the per-model upstream refusal its own comment already documents (`mimo-v2.5-free` then, `deepseek-v4-flash-free` now), and the 400 names no enum.

**Correction to the spec's premise.** The spec asserted the `*_API_KEY_ROTATION` variables were non-empty key lists, making ~30 hosts probeable. They are not: `{CREDENTIAL_ENV}_ROTATION` holds a rotation **policy name** — `single` / `round_robin` / `least_used` / `failover` (`providers/runtime/config.py:62-85`). A first probe run that read them sent the literal string `single` as a bearer token and collected meaningless 401s. The 5.70.0 "no credential to probe with" verdicts were correct after all.

So, with fewer than five hosts responding, the conservative **four-rung classic ladder** stands: `minimal | low | medium | high`. `xhigh` and `max` clamp down to `high` — which is what an effort scale is for — and `none` is never sent. The full table is recorded beside the declaration in `profiles.py` with its date.

## Known and deliberate

- **No declared encoder for DashScope's `enable_thinking` or SiliconFlow's numeric `thinking_budget`.** Both carry a `TODO(probe)` naming the control. The standard field is a strictly better starting point than nothing; a declared encoder for each is the right end state and needs a credential.
- **No `rejected` markers seeded.** Nothing in the tree measured a host-level rejection, and seeding one would reintroduce exactly the hand-written verdict this PR removes.
- **Learned rejections do not persist across a config reload.** Matches the output cap exactly.
- **No new `ReasoningAdaptationKind`.** `SUPPRESSED` already means "nothing reached the wire" and already renders correctly.
- **The generic strip is the last retry rung, not the second.** The spec placed it ahead of `stream_usage`; Mistral's own reasoning recovery proved that wrong — it strips the rejected field *and* the replayed thinking blocks its models refuse alongside it, and NIM removes the chat-template pair that is its actual control. Firing the generic rung first would answer the 400 by removing one field, fix nothing, and burn the budget the complete recovery needed.

## Residual risks

1. **A host that 200-ignores `reasoning_effort` costs nothing** — the field is accepted and discarded. #220's requested-vs-returned measurement makes that *visible*, which is strictly better than today, where the same host was sent nothing and looked identical.
2. **A host or model that 400s costs exactly one request, once per provider generation per model.** The table is instance-scoped like `_model_output_caps`, so a config reload rebuilds the provider and the learning is lost — deliberate, and it means a rejection learned from a transient upstream bug self-heals.
3. **`GENERIC_OPENAI_PROFILE` is the largest exposure.** It backs every custom and dynamically configured provider, so the endpoint is unknown by construction. A private vLLM or corporate gateway that 400s on the field pays one 400 per model, once. Three mitigations, all live: the safety net; the per-model gate (a non-reasoning model is never sent the field at all); and the user model-parameter override, applied last, which can pin or remove `reasoning_effort` per model.
4. **The default is not the SDK's full enum.** `xhigh` and `max` clamp to `high`, `none` is never sent. A host that genuinely takes the wider enum gets less resolution than it could until someone probes it and declares an override. The conservative side of a trade-off, taken because the probe settled nothing.
5. **`_next_create_retry_body` now returns a tuple.** Private, no external callers, no test references — but an in-flight branch that overrode it will conflict.
6. **`ReasoningDialect` gained two defaulted fields.** Every existing construction is unaffected; a test comparing against a hand-built *learned* dialect would now see them.
7. **`anthropic` gained a dialect it never had.** Gating sees `adaptive=True` and a budget channel where it previously saw `None` (= unknown = no restriction). Unknown never restricted and the new dialect is a superset of what the adapter emits, so no control should be lost — and `reasoning_request_baseline.json` was checked rather than assumed: **no `anthropic_messages` cell moved.**
