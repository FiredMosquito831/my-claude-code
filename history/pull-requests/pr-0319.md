## Description

7.114.0 (#318) made a model's known doors a set, ordered by the inbound
client family. That covers every model whose registry entry names a package
this build can map. It does not cover the other half of the OpenCode rosters: a
model with no `provider.npm` at all -- or one this build cannot map, like
`@ai-sdk/mistral` -- publishes no surface, so the resolver falls through every
rung to the profile's floor and the model is served on Chat Completions for
ever, whatever protocol the client spoke.

7.115.0 adds one rung below the floor, on the two OpenCode profiles only
(`optimistic_first_try`):

- a model whose surface is unknown is tried once on the door its client family
  prefers, with 7.114.0's existing ~16-token surface probe -- never with the
  client's request -- and the floor carries the request inside the same attempt
  when the guess answers wrong;
- the answer is the same learned fact 7.114.0 already writes
  (`response_surface`, a list, `source=probe`, seven-day TTL, *Forget* on the
  Models page), so later requests go straight to the door that worked;
- a caller with no request in flight is `UNKNOWN`, prefers nothing, and gets
  the floor exactly as before -- which is why the equality baseline does not
  move for the first time in this arc.

`provider.py` gains no behaviour: the guessed-candidate walk and the
404-on-a-guess widening shipped in 7.114.0 and are reused verbatim. The
production change is one branch in the resolver's floor rung.

re-verified equal to it at freeze.
