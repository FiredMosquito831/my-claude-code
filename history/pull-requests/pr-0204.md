## Description

## What was missing

Since 5.61.0 the proxy invents no sampling parameters at all. `NimSettings`
fields are all `| None = None` and every other provider is pure passthrough, so
an upstream body carries only what the client asked for. That was the right
fix — an unconditional `top_p: 1.0` was what produced NVIDIA's live
`top_p is immutable` 400 on `moonshotai/kimi-k3` — but it left no way to say
the opposite either. A user who *wants* `top_p: 0.95` on exactly that model,
because the model pins it, had to edit the code.

## Mechanism

A new store at `~/.fcc/model_overrides.json`:

```json
{
  "providers": { "nvidia_nim": { "top_p": 0.95 } },
  "models": {
    "nvidia_nim/moonshotai/kimi-k3": { "top_p": 0.95, "temperature": null }
  }
}
```

Three states per parameter, and the middle one is the point of the file:

| state | meaning |
| --- | --- |
| key absent | inherit — provider level, then nothing; the body is left exactly as the provider built it |
| value `null` | **force unset** — remove the key even if a provider postprocessor set it |
| a value | force that value |

Precedence is **model > provider > untouched**, resolved *per parameter* rather
than per level, so a `null` on the model beats a value on the provider. Keys are
matched case-folded, so `NVIDIA_NIM/MoonshotAI/Kimi-K3` finds the same entry.

## Where it is applied

`build_openai_chat_request_body` applies the table **last** — after the caller's
postprocessor chain, before tool-name encoding. The user's setting has to win
over every provider default, and a "force unset" can only remove a key once
everything that might set it has run. That function is the single funnel the
whole OpenAI-chat family goes through, so one hook covers all ~52
OpenAI-compatible providers instead of 52 edits.

`provider_id` is threaded explicitly rather than derived from the policy's
`provider_name`, which is a log label (`NIM`, `COMMANDCODE`) and not a catalogue
id. `OpenAIChatProvider` now carries the id, `create_openai_chat_provider`
already had it, and the subclasses built by special factories name their own. A
caller that passes nothing gets no overrides — guessing an id would apply
somebody else's settings.

### Covered / not covered

**Covered:** every profile-driven provider through `create_openai_chat_provider`,
plus the OpenRouter-dialect gateways (`open_router`, `nous_portal`, `kilo`),
`nvidia_nim`, `deepseek`, `mistral`, `gemini`, `vertex`, `github_models`,
`lmstudio`, `cloudflare`, and Command Code's OpenAI-protocol half.

**Not covered, by construction:** `anthropic`, `anthropic_oauth`,
`chatgpt_oauth`/`openai`, and Command Code's Anthropic-protocol half. None of
them build a body through the OpenAI-chat postprocessor chain — verified, they
import neither `build_openai_chat_request_body` nor `OpenAIChatProvider`.
`chatgpt_oauth` in particular deliberately sends no `max_tokens` and is
untouched here.

## `max_tokens`: deliberately not overridable

`application/output_tokens.py` (5.63.0) owns the output budget in four separate
steps — clamp to the model's published limit, fall back when nothing published
one, apply the operator ceiling, leave context headroom. A value forced into the
body afterwards would skip all four, and asking a 16,384-output model
(`nvidia_nim/minimaxai/minimax-m3`) for 100k is a guaranteed upstream 400 —
exactly what that module exists to prevent.

Entering it correctly means feeding the override in as the **requested** value
at `apply_output_token_budget`, so it is still clamped. That needs a lookup
threaded through `ModelRouter` and `RoutedMessagesRequest`, which is a routing
change rather than this one. So `max_tokens` (and `max_completion_tokens`) are
named in `OWNED_ELSEWHERE_PARAMETERS`: setting one logs *why* it did nothing
instead of being silently swallowed with the typos. Reasoning and thinking
fields are excluded on the same grounds — the reasoning pipeline resolves effort
and budget against the model's declared capability and its answer allowance, and
a raw override would silently defeat that whole chain.

## Safety

The allow-list is a security boundary, not a convenience: whatever lands in
these dicts is written straight into an upstream request body, so only nine real
request fields are honoured — `temperature`, `top_p`, `top_k`, `min_p`,
`presence_penalty`, `frequency_penalty`, `repetition_penalty`, `seed`, `stop` —
and anything else is dropped with a log line. A typo cannot inject an arbitrary
key.

Malformed input never reaches a request or the boot path. A missing file, an
empty file, unparseable JSON, a non-object document, a non-object section or
entry, an unknown parameter and an object-valued parameter each degrade to "no
override" with a warning.

Writes go through a new `config/atomic_json.py`, which is
`claude_settings._write_document_atomically` moved out and made public rather
than a second copy of the same `.fcc-tmp`-and-`os.replace` dance; the staged
file is unlinked if the rename fails. The table is cached on the file's own
`(path, mtime_ns, size)`, because it is read on the request path — an edit is
still picked up without a restart.

## Residual risks

- **Overrides are not validated against the model's `supported_parameters`.**
  #200 made that data available; the user did not ask for it, so a user who sets
  `top_k` on a model that rejects it will get the provider's 400, not a local
  error. Deliberate and out of scope.
- **There is no UI yet.** The file has to be written by hand until the Admin
  Models page (PR C) lands. `save_model_overrides` exists for that page to call.
- **The mtime cache has one-second-granularity exposure on filesystems that do
  not report nanoseconds.** Two writes of identical size inside the same
  timestamp tick would keep the first parse. Not reachable through
  `save_model_overrides`, which drops the cache itself; only through an external
  editor writing twice in the same tick.
- **`provider_id` is a literal in each special-factory subclass.** If a
  provider is ever renamed in `PROVIDER_CATALOG` without updating its client,
  its overrides stop matching silently. Nothing asserts the two agree.

## Deliberately not done

The Admin Models page UI (PR C), `supported_parameters` validation, and anything
in the reasoning pipeline.
