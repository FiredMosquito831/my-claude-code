## What changed

Three units, one message from the user: (1) improve websearch analytics with ui-ux-pro-max, (2) make websearch request input/output readable, (3) stop pruning websearch content.

**Measured problem:** the websearch analytics store capped each stored input/output JSON at 50k chars and replaced oversized payloads with a truncation envelope. On the live DB, **251 of 252 rows had truncated output** (avg 175k chars) — the dashboard detail view could not show what searches actually returned.

### 1. Stop pruning websearch output (backend)
`WEBSEARCH_LOG_CONTENT_MAX_CHARS` default raised **50,000 → 2,000,000** (~2 MB) across `settings.py`, `config/admin/websearch_manifest.py` (default `"2000000"`), and `.env.example`. The cap stays configurable as a safety valve; real provider output now always round-trips. Legacy truncated rows stay truncated (unrecoverable) but render the stored preview.

### 2. Readable request input/output (frontend)
The websearch detail modal is reworked (flat+dense aesthetic preserved):
- **Tool input** renders as a key/value summary (query, max results, domains) instead of raw JSON.
- **Provider output** renders as readable per-result cards (title/url/published/snippet) with a **"Show full content"** toggle on long page text.
- **Raw output JSON** moves to a collapsed `<details>` block with a **Copy** button — provider-specific fields stay inspectable without dumping 175k chars.
- **Legacy truncated rows** show a notice + the stored preview + hash.
- Reuses the existing `.turn-pane` / `.guide-copy-button` patterns.

### 3. Fixed a pre-existing websearch export bug (found while verifying)
The websearch detail export mapped the `input`/`output`/`provider_config` fields to columns named literally `output` etc., which **do not exist** in `search_log` (the JSON lives in `input_json`/`output_json`/`provider_config_json`). Every websearch export selecting those fields failed with `no such column` and returned empty. `iter_export_rows` now aliases the `*_json` columns to the decoded names and `_attempt_dict` decodes either shape.
