## Description

**PR 2 of 3.** v5.32.0 shipped the capability data; this consumes it. This is the behaviour change.

## What was broken

A tier set to **High** was sent verbatim to a model whose vocabulary stops at `medium`, and a numeric budget went to models with no budget parameter at all. Reasoning was translated per **provider**, and `ReasoningEncoder.encode` received **no model information whatsoever**, so it fired unconditionally.

## The shape of the fix

The whole feature is a `ReasoningPolicy -> ReasoningPolicy` transform at the routing boundary. **No provider adapter and no encoder changed.**

That is what makes the safety property provable rather than argued: an unknown capability returns the **same object**, so the encoder receives literally the input it received before this existed.

| Situation | Sent |
| --- | --- |
| Unknown model | **unchanged, by identity** |
| Policy OFF | unchanged — every encoder already has a disabled path |
| Known not to reason | no reasoning fields at all |
| Effort supported | as-is |
| Effort too high | highest supported `<=` requested |
| Effort below the model's range | clamped **up** to its lowest — never drop what was asked for |
| Toggle-only model | thinking on, level discarded |
| Budget-only model | `clamp(effective_max * ratio, 1024, limit)` |
| Explicit client budget | clamped to `[1024, limit]` |

Ratios — minimal `.10`, low `.20`, medium `.50`, high `.80`, xhigh/max `.95` — are the **published industry values**, in one named constant with the source URL. [OpenRouter documents](https://openrouter.ai/docs/use-cases/reasoning-tokens) `budget_tokens = max(min(max_tokens * ratio, 128000), 1024)`; Vercel's AI Gateway publishes the same table. `1024` is Anthropic's documented floor; `.95` rather than `1.0` because Anthropic requires the budget to stay strictly under `max_tokens`.

**Capability never names a wire field.** It changes the value and whether to send at all; the encoder keeps sole ownership of the shape, so no provider can be handed a field its API does not know. A generic invariant test asserts emitted field paths stay a **subset** of what each encoder already emitted, across 6 capability shapes × 12 policies × 3 limit combos × 8 profiles.

## An architecture correction worth noting

The first wiring attempt put the models.dev lookups directly in `api/routes.py` and broke `tests/contracts/test_import_boundaries.py` — `api` may not import `providers`. Rather than register an exception, the lookups moved behind `RequestRuntimePort`, implemented in `runtime/provider_manager.py`, which already owns the model cache. The contract test passes **unmodified**, the application layer does no disk IO, and the shape is now the `vision_lookup` precedent byte for byte.

Both lookups are optional constructor arguments, so every other `ModelRouter` construction (messaging, CLI, handler defaults) gates nothing at all.

## Known and recorded, not hidden

**Deriving an effort from an explicit client budget** uses this project's own compressed budget table (512/512/1024/2048/4096/8192), so any client budget at or above 8192 — most real Claude Code requests — resolves to `max` before clamping. Defensible (a large budget *is* a request for maximum thinking) but coarse. A proportional inverse of the ratio table would preserve gradation and be symmetric with the forward direction; that is the obvious follow-up, deliberately not slipped in here.

**The minimax split-reasoning flag stays unconditional.** It ignores the policy entirely today, including OFF. It is an output-format flag rather than a compute request, and honouring suppression there would mean bypassing the encoder — breaking the invariant above.

**No live upstream call.** Every assertion is against the resolved policy and the emitted body, not a real provider response.
