# An empty wallet is not a malformed request

`req_df6a8ed49c6a46bb81765ba8039b8703` (2026-09-02 11:52Z) asked for `commandcode/z-ai/glm-5.3-flash` and met:

```json
{"message": "You have insufficient credits to make this request. Please purchase more credits to continue using the service.",
 "type": "invalid_request_error",
 "code": "BAD_REQUEST"}
```

HTTP 400. It classified as `FailureKind.INVALID_REQUEST`; `FALLBACK_SKIP_KINDS` defaults to `invalid_request`; the six remaining entries on the chain were recorded as *not tried: a invalid_request failure ends the route*, and the caller got a 400.

The request was fine. The **account** was out of credits, and every one of those six entries could have answered.

| --- | --- | --- | --- | --- |
| `402` | any of the list below | `quota` | yes | `RATE_LIMIT_COOLDOWN_SECONDS`, whole key |
| `402` | none | `quota` | yes | **no** |
| `400` | one of the list below | `quota` | yes | `RATE_LIMIT_COOLDOWN_SECONDS`, whole key |
| `400` | none | `invalid_request` (unchanged) | no | no |
| `400` | context-overflow wording | `context_length` (unchanged) | no | no |
| `403` | one of the list below | `quota` | yes | `RATE_LIMIT_COOLDOWN_SECONDS`, whole key |
| `403` | none | `authentication` (unchanged) | yes | lockout ladder, unchanged |
| `401` | — | `authentication` (unchanged) | yes | lockout ladder, unchanged |
| `429` | — | `rate_limit` (unchanged) | yes | (key, model) bench, unchanged |

**The phrase list, as shipped** (`QUOTA_PHRASES` in `providers/failure_policy.py`, matched case-insensitively as substrings):

```
insufficient credits        purchase more credits
insufficient balance        not enough balance
not_enough_balance          quota exceeded
insufficient_quota          payment required
billing                     out of credits
credit balance is too low   creditserror
```

Command Code and the OpenAI-compatible gateways behind it; Novita (`NOT_ENOUGH_BALANCE`, "Insufficient balance."); the OpenAI machine codes; Anthropic's own "Your credit balance is too low"; OpenCode Go's `CreditsError`.

**Matcher rules.** The words are read through `providers/recovery/complaint.upstream_complaint` and through nothing else. That reader prefers the **structured** error body and prunes `input` / `body` / `request` / `payload` / `data` / `ctx` / `value` / `received` — the keys under which a pydantic-style validation error echoes the submitted request back. A prompt containing the words "insufficient credits" therefore cannot bench a key. A **phrase**, never a bare token: `credit` alone is not in the list. If the classifier is unsure it produces no `QUOTA` at all and the failure keeps the kind it has today.

## What the kind does

- **Key-shaped, not model-shaped.** `error_justifies_rotation` → `True` (`ROTATING_KINDS`), so the pool tries another key first; the executor reaches the next model only once the pool is exhausted.
- **Never ends the route.** Absent from `RouteExecutionPolicy.skip_kinds` and from `FALLBACK_SKIP_KINDS_DEFAULT`. An operator can still list `quota` explicitly; the validator and the field help name it.
- **Never counts toward the chain bench.** `BENCH_COUNTING_KINDS` is unchanged — an empty wallet says nothing about the model that was asked.
- **Benches the credential only on an exact phrase**, for the operator's existing `RATE_LIMIT_COOLDOWN_SECONDS`, through the same fixed window a header-less 429 uses (`RotationEngine.note_rate_limit`). Whole-key, not scoped to a model: a wallet is not per-model. **No new number.** A bare 402 rotates and falls through and charges nothing.

`§12`'s rule text ("health changes on 401/403 and 429 only") is extended to three signals by the user's explicit decision, and every docstring, README, USAGE, ARCHITECTURE, `.env.example` and in-app Guide sentence that stated the old rule now states the new one.

## Residual risks

- **`billing` is the loosest token on the list.** It is a word, not a phrase, and it ships because the user named it explicitly. A gateway that says "see our billing docs" in an unrelated 400 would now classify as `quota` — which rotates and falls through rather than ending the route, so the blast radius is one wasted key rotation and one 55-second key bench, never a lost request. Every other entry is a full statement about the account.
- **A 403 with a billing phrase no longer walks the auth lockout ladder.** That is the intended trade (an unpaid account is not a revoked key), but an upstream that answers a genuinely revoked key with the word "billing" would be benched for `RATE_LIMIT_COOLDOWN_SECONDS` instead of 5 minutes. None was measured.
- **The per-try ladder row records `BadRequestError`, not `quota`.** The retry frame runs *before* the provider's classifier, which is documented existing behaviour (`LadderTry.error_kind`); the attempt row and the credential decision both say `quota`. Unchanged by this PR, noted because the modal shows both.
- **A fully-benched credits pool still records `error_kind=unavailable`** on the request row, because it raises the pre-existing `ApplicationUnavailableError`. Its *message* names the credits plainly and points at Providers, but grouping by kind puts it with other pool-exhaustion rows.
- **`core/anthropic/errors.py`, `core/openai_common/errors.py` and `core/gemini_api/errors.py` were touched** although the brief said not to touch the inbound adapters. Their `_FAILURE_ERROR_TYPES` / `_FAILURE_STATUSES` tables are indexed **totally** (`table[kind]`), so a new kind without an entry is a `KeyError` at the wire boundary. Each gained exactly one line, reusing wire types that already existed (`billing_error`, `RESOURCE_EXHAUSTED`); no adapter logic changed. `core/gemini_api` also gained `402: "RESOURCE_EXHAUSTED"` to its status map.
- **The pool sentence and the credits bench need a real pool.** A single-credential provider is not wrapped in `RotatingProvider`, so a one-key install gets the kind, the rotation-free fall-through and the ladder row, but no bench and no key-health badge. That is the pre-existing pool boundary, not new.
