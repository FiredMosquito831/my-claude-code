## What changed (Part 1 of 2)

RTK (Rust Token Killer) integration core — a single source of truth plus a reconciler.

- `config/rtk.py` — `RtkState {claude, codex, pi}` in `~/.fcc/rtk.json` (atomic, corrupt-tolerant); `apply_rtk_state()` runs `rtk init -g --auto-patch|--codex|--agent pi` / `rtk init --uninstall ...` to reconcile; `_ensure_rtk_binary()` downloads the pinned 0.44.2 release, SHA-256 verifies, extracts to `~/.local/bin/rtk`. All calls set `RTK_TELEMETRY_DISABLED=1`.
- `cli/rtk_commands.py` — `mcc-rtk`/`fcc-rtk` with `status`/`enable`/`disable`/`uninstall`/`apply`.
- Installers gain `--rtk`/`-Rtk` → enables all three agents after install.

## Why not a straight upstream port

Our installers are wheel-only (the agent-install/select subsystem was removed), so upstream's "configure RTK per selected agent" had nothing to hang on. This instead gives RTK a persistent state + reconciler, with management surfaces coming in Part 2.
