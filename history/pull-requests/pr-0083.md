## Description

## What changed

v5.0.0 renamed the distribution to `my-claude-code` and the wheel to `my_claude_code-<ver>-py3-none-any.whl`, but the published installers and the self-updater still referenced `free-claude-code`/`free_claude_code`. Every fresh install 404'd on the release wheel (`Page not found` → `WebException`), and the self-updater could no longer find its own installed package or receipt.

### 1. Installers + self-updater point at the renamed package

`scripts/install.sh`, `scripts/install.ps1`, and `release_updates.PACKAGE_NAME` now use `my-claude-code` / `my_claude_code`. The legacy `fcc-*` commands still exist as aliases (pyproject ships both families), so the existing `fcc-server --version` verification is unchanged.

### 2. install.sh digest extraction read the release BODY, not the asset

GitHub places `body` before `assets` in the payload, and the v5.0.0 notes repeat the wheel's sha256 as prose. `grep -m1 '"digest"'` landed on that prose, producing a **checksum mismatch on every install**. The awk now grabs the digest only from the asset whose name matches the wheel we download. The PS installer already read `$wheelAsset[0].digest` and was correct.

### 3. Restart rebind could fail on a lingering socket (WSL)

The new process's startup wait was a fixed 5s; if the old listener had not released, the new process gave up and died, leaving the service unavailable. The startup wait now scales to the configured graceful-shutdown budget, and the POSIX handoff waits for the port to free before `execv`.
