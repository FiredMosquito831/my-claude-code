## Description

The fallback docs described a chain that fires when a model "fails" — true, and incomplete. A model that accepted a request and then went silent was not a failure by any test FCC applied, so the chain fired minutes late or not at all. That is precisely what the deadlines exist for, and none of the three docs mentioned it.

- **README** — a `Limits` row in the features table, and the three settings that bound a silent model, next to the existing commit-boundary explanation.
- **docs/USAGE.md** — the same beside its failure table ("a model that goes quiet is a failure too"), plus `REQUEST_LOG_TEXT_MAX_CHARS` / `REQUEST_LOG_COMPRESSION_LEVEL` and the blank-means-default rule.
- **In-dashboard Guide** — a new *Set the limits* section: when to stop waiting, what to keep, and why clearing a field is safe. TOC entry included.
