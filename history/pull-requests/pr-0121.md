## Description

Follow-up to #120, from two questions: **is a fallback inside the vision chain tracked**, and **does the request say which vision model was used**.

## The vision chain was already tracked

Verified against the real router and in the dashboard. A request whose vision model fails and whose *vision fallback* answers records:

```
route_chain          chatgpt_oauth/gpt-5.6-luna,nous_portal/stepfun/step-3.7-flash:free,nvidia_nim/...
route_attempt        1
route_primary_model  chatgpt_oauth/gpt-5.6-luna
route_diverted_from  nous_portal/tencent/hy3:free
route_diversion      vision
```

and renders as **both** a `vision` badge and a `fallback 1, after chatgpt_oauth/gpt-5.6-luna` badge, with the trace marking which hop served. The failover panel shows the vision model's own failover; the diverted panel shows what each diversion was ultimately served by. No change needed.

## Two real gaps, now closed

**The vision model was only implied.** It is the head of the chain on a diverted request — readable only if you already know how diversion works. The detail now names it: `gpt-5.6-luna — answered`, or `gpt-5.6-luna — failed, answered by <model>`.

**An image with nowhere to go recorded nothing.** When a request carries an image and no model on the route is known to accept one, the policy logs `VISION ROUTE UNAVAILABLE` and sends it anyway. The plan recorded no diversion — nothing was replaced — so the case an operator most needs to see looked like an ordinary request. `RouteDiversion` gains `VISION_UNAVAILABLE`, recorded with `route_diverted_from` NULL because nothing was in fact replaced.

That makes `route_diversion` no longer mean "a diversion happened", so both the window and lifetime counters now key on `route_diverted_from` — the field that actually means the head was replaced — and the window stats gain `vision_unavailable` beside it. The safety net working and the safety net having nowhere to put the request are different facts and must not be summed.

Dashboard: a `no vision route` badge, a bordered note naming the fix (`MODEL_VISION`), an "Image, no vision route" figure, and the "Vision model" row.
