## Description

## What was wrong

The five deadline defaults — 180 s first token, 600 s total budget, 180 s share floor, 180 s stall, 450 s thinking — were measured off 21 days of this project's own traffic and were correct for that traffic. They were wrong for a reasoning model that legitimately thinks for half an hour, and the failure they caused was the expensive one: a model doing real work killed mid-thought.

The error the client then received said `Provider 'x' produced only reasoning for 450s without answering.` True, and useless. The reader's next question is always "where do I change that?", and the answer was three files and a search away — which in practice meant the number stayed as it was.

## What changed

**All five deadlines ship at `0` — no limit.** With the shipped zeros MCC never ends a silent or stalled upstream on its own; the fallback chain moves only on an error the provider returns. That is the deliberate position: this is a server its operator configures, so the shipped value is the one that decides nothing. It is now stated plainly in one place each in `README.md`, `docs/USAGE.md`, the Deadlines card blurb and the in-dashboard Guide, together with what each limit measures and how to get time-based failover back (`FALLBACK_FIRST_TOKEN_TIMEOUT` is the only one that produces a *failover*; the others end the request). **An install that already sets any of the five keys keeps its own value.**

**Every limit now names its own knob in the error.** New `application/deadline_hints.py` appends ` (<ENV_VAR> -- change it on the dashboard under Limits & Resilience -> <Card>)`. The card label is read out of the admin manifest's own `SECTIONS`, and a contract test pins the page name against the nav label in `admin.js`, so the words cannot drift from the page they point at. Applied at the five deadline messages, the stepped-over cooldown verdict, and the one `All API keys for this provider are in cooldown` string in `providers/runtime/rotating.py`.

The hint names the limit that **actually** ended the attempt: a silent model cut short by its slice of the request budget names `FALLBACK_ATTEMPT_SHARE_FLOOR`, not the first-token box that never fired. ASCII throughout, because this text crosses an SSE frame, a JSON body, a request-log row and a terminal.

## Scope

Constants, strings, docs and tests. **No deadline, retry, rotation or fallback logic changed.** Every `> 0` guard in `_chunk_timeout` / `_attempt_deadline` already treated 0 as disabled and `LIMIT_RANGES` already admitted 0, so a zero default needed no code path of its own. `_timeout_env_var` reads the decision `_deadline_reached` had already made; `share_bound` is a boolean that picks a string. `providers/credential_rotation.py`, `core/credential_rotation.py` and `providers/rate_limit.py` are untouched, and `rotating.py` changed by exactly one error string plus its import.

The 6.15.0 committed-stream truncation path records the same `ExecutionFailure` rather than raising it, so the hint on `stopped producing output for Ns` reaches the attempt row there too — one helper, both paths.

## Residual risks

- **The zeros are the whole risk, and they are the point.** A misbehaving upstream that accepts a request and never speaks now holds it until `HTTP_READ_TIMEOUT` (300 s, applied per read) or the client disconnects. Anyone who wants the old behaviour sets the three keys; anyone upgrading who already set them is unaffected.
- The share-floor arithmetic and its calculator warnings are now dormant by default, so they are exercised only by tests until an operator sets a total budget. The jsdom suite drives both states.
- `fallback_reasoning_answer_timeout` has no `LIMIT_RANGES` entry, so it never joined the blank-coercion validator: clearing that box on the dashboard writes `KEY=` and fails validation at startup. **Pre-existing and unchanged** — equally true when it shipped at 450 — and pinned by a test that says so rather than skipping silently.

## Not done

- **`FALLBACK_HONOUR_CLIENT_TIMEOUT`** (honour the client's `x-stainless-timeout` as the total budget when the budget is 0) is deliberately left out. It cannot be built without touching the deadline path in `execution.py`, which this change is explicitly scoped out of, and it is well past the ~40-line budget it was offered under. The docs describe the zeros honestly instead, which was the non-negotiable half.
- **`.env.example` still quotes 180/600/450.** Reads and edits of that path are denied to agents in this environment; the attempt was made and refused, and not routed around. The manifest, README and USAGE carry the real defaults. One manual edit.
