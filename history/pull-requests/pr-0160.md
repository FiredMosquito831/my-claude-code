## Description

## The README has been factually wrong since v5.33.0

It still told readers that numeric-budget providers map **Low=512, Medium=1,024, High=2,048, X-High=4,096, Max=8,192** — a fixed table that no longer governs that path. It listed **no Adaptive option** after v5.35.0 added one. And it never mentioned **per-model clamping** at all.

Five releases changed how reasoning is sent and **none touched the prose describing it.** Every structured guard passed the whole time — which is exactly how documentation goes stale in this repo, and why it costs more than a code error.

Found by a review pass rather than by a test, which is itself the finding.

## What it says now

The option list including **Adaptive**; the ratio formula for models that take a numeric budget —

```
budget = clamp(effective_max × ratio, 1024, model output limit)
Minimal .10 · Low .20 · Medium .50 · High .80 · X-High .95 · Max .95
```

— with the reason the top two stop at `0.95` (the budget must stay strictly under `max_tokens`) and that `1,024` is Anthropic's documented floor; and the narrowing rules: clamp **down** above a model's vocabulary, clamp **up** below it, thinking on for toggle-only models, nothing for a model known not to reason, and **byte-identical** behaviour for a model with no capability data. It also notes both the requested and applied policies are now recorded.

**Deliberately NOT claimed: that the old fixed table is gone.** It isn't. `_EFFORT_BUDGET_TOKENS` still backs `ReasoningPolicy.numeric_budget_tokens`, consumed by the `anthropic_messages`, `google_openai`, `nvidia_nim` and `openai_chat` encoders, plus the inverse budget→effort mapping. Verified before writing the prose; the new text scopes its claim to the gating path that *synthesises* a budget. Fixing one doc error by introducing another would be worse than leaving it.

`docs/USAGE.md` is unchanged — it carries no option list and no budget numbers, so nothing in it was falsified, and adding a second copy of the table would create the dual-maintenance drift this PR exists to fix. `.env.example` was already correct.

## Two smaller items

**Widened the strippable tag allow-list** with `online`, `extended`, `discounted` — pricing/routing/capability tags that don't alter thinking, safe by the same logic as `:free`. The original list was chosen from memory; this one is checked against a census of every tag in the upstream index. Exclusions unchanged, and the comment now names them with counts: `:thinking` (69 upstream), numeric budget tags and effort tags are never stripped, **because for those the tag IS the reasoning difference**.

**`mistral_codestral` → `mistral` upgraded from "deferred" to an investigated rejection:**
