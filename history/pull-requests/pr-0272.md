## Description

## What this is

Spec **S2** of `specs/PR-DESKTOP-WEBVIEW-SPEC.md`: the Tauri v2 binary that puts the admin dashboard in its own window, with its own tray icon, on Windows and Linux.

It renders one URL over real HTTP in the OS webview. There is no product surface in it — everything the user sees inside the window is `admin.js`, served by `mcc-server` — which is what keeps it at **3.34 MB** (Windows release, `--no-bundle`) and what means it does not change when the dashboard does.

Built and smoke-tested locally on Windows. **Not released**: S3 adds the CI matrix and attaches artifacts.

## The ladder

| `server_presence` | What the shell does | What the user sees |
|---|---|---|
| `mcc-desktop` not on `PATH` | Runs the project's own install script (Q4) — never bundles Python or the server | "Installing My Claude Code", the exact command, its output streamed line by line; then the ladder runs again |
| `healthy` | Attaches. Starts nothing. | The dashboard |
| `free` + `spawn` | Starts `mcc-server` via the installed shim, polls `health_url` every `health_check_interval_seconds` up to `start_timeout_seconds` | "Starting the server… (4s of 15s)", then the dashboard |
| `free` + `attach`/`off` | Starts nothing | *"The server is not running. Server mode is attach; start mcc-server yourself, or switch to spawn."* + Retry |
| `foreign` | Starts nothing | The `port_conflict` sentence Python wrote, **verbatim** — it names the holding pid — + Retry |
| healthy → failing, under `health_failure_threshold` | Nothing at all | The dashboard, untouched |
| … over the threshold, inside `reconnect_timeout_seconds` | Reconnect banner; reloads the dashboard the moment health returns | "The server stopped answering — it is probably restarting." |
| … past the budget, or a start that timed out | Stops | Error page naming `server_log`, + Retry |
| `schema` is not 1, or an unknown `server_presence` | Refuses | "Update the desktop window" — never a guess |

| **C4** | Nothing under the configuration directory is written and `desktop.lock` is never taken — Python stays the owner of that file, and the shell has its own guard in `tauri-plugin-single-instance`. The one file this binary writes is `window.json`, in the OS application-data directory. |

| **C8** | Every page the shell serves itself is a single bundled document that makes no network request. State is pushed in by `eval`; the page talks back through exactly one command, `shell_retry`. The remote dashboard is granted no capability at all — it is rendered, never talked to. |

## The Windows smoke

Run against a **scratch** MCC only — `PORT=8199 HOST=127.0.0.1` and a scratch config directory, with a scratch `mcc-desktop` shim, via the three test-only overrides (`MCC_SHELL_DESKTOP_COMMAND`, `MCC_SHELL_SERVER_COMMAND`, `MCC_SHELL_DATA_DIR`) that exist for exactly this. Every process was stopped by its exact pid afterwards. Screenshots were captured with `PrintWindow` on the shell's own window handle and read; none contains key material.

| | Proven |
|---|---|
| **Splash** | The bundled page paints instantly; no "control channel unavailable" line, so the one IPC round trip the page makes on load succeeded. |
| **`free` + `spawn`** | With nothing on the port, the shell started the scratch server, polled `/health`, and loaded the dashboard. The dashboard footer reads the **scratch** `.env` path, which is how the smoke proves the shell used what Python told it and not what this machine happens to have. |
| **`healthy`** | Relaunched against the running server: straight to the dashboard, nothing spawned. |
| **`foreign`** | A foreign listener on the port: the port-conflict page, carrying Python's sentence verbatim ("Port 8199 is held by pid 44200, which is not the MCC server..."). |
| **`free` + `attach`** | After `mcc-desktop --server-mode attach`: the attach message, and — checked with `netstat` — nothing started. |
| **Retry** | The port squatter was stopped and the Retry button clicked: the ladder re-ran, spawned the server, polled and attached. That is the IPC path proven end to end. |
| **Single instance** | A second launch exited on its own; one process, one window. |
| **Window state** | Geometry round-trips through the scratch app-data dir and is byte-identical across two launches. |

One bug the smoke caught and this PR fixes: the local page's URL cannot be read at window-build time — it is `about:blank` then, and the platform's real asset URL is `http://tauri.localhost/` on Windows. Navigating "back" to the build-time value blanked the window. It is now read in `on_page_load`, from the first page that actually finishes loading.
