## What changed

Three user-reported issues after the 5.0.1 release:

### 1. Windows install failed with `os error 32` mid-uv

`uv tool install --force` overwrites every launcher shim in `~/.local/bin`; Windows cannot overwrite a running `.exe`. A live launcher (the proxy or an `fcc-claude`/`fcc-codex`/`fcc-pi` child) made uv fail partway with a cryptic error, leaving the tool env half-replaced. Both installers now detect running launchers **up front** (`Get-Process` in PS, `pgrep`/`ps` in sh), covering both command families, and abort **before** uv mutates anything, naming every running process. Reuses the uninstaller's `Assert-NoFccProcessesRunning` pattern.

### 2. Post-install message led with legacy `fcc` commands

Now leads with the native `mcc` family and short usage (`mcc-server`, `mcc-claude`, `mcc-codex`, `mcc-pi`, `mcc-claude --discover-models`), and no longer advertises `fcc` names.

### 3. Dashboard showed "Current vunknown"

`current_version()` read only the native distribution (`my-claude-code`), so a migration install still running the legacy `free-claude-code` tool reported nothing. It now tries native then legacy, so a mid-migration server always reports its real version. The uv receipt and extras lookup are owner-aware too, so extras and the Python pin are carried from whichever owner is installed.
