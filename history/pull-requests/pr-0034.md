## Description

## What this adds

A **Providers → Claude Code settings file** card that reads and patches `~/.claude/settings.json`, plus a launcher split.

Claude Code's settings file takes precedence over environment variables, so a stale `env` entry silently defeats an exported `ANTHROPIC_BASE_URL` — and the failure presents as "the proxy is broken". The card makes that file a first-class, inspectable surface.

**Four states**, because the interesting one is the third:

| State | Rendering |
| --- | --- |
| not configured | neutral |
| configured | positive |
| **points elsewhere** | warning, **shows the current base URL and whether the token differs** before overwriting |
| unreadable | error, and Configure refuses rather than overwriting |

**The path is editable and pre-filled.** Under WSL the server's home is not the home Claude Code reads on Windows; writing the wrong file silently is the failure mode that matters most on this setup. When WSL is detected the Windows-side path is offered as a second suggestion.

A sibling `settings.local.json` holding `ANTHROPIC_*` is flagged, since it overrides whatever we write.

## Safety

- Every other key preserved, top-level and inside `env`.
- Backed up once to `<path>.fcc-backup`, then written via temp file + `os.replace`.
- A file that does not parse as a JSON object is **refused, not overwritten** — and so is one whose `env` is present but is not an object, since replacing that would destroy it.
- Values come from `local_proxy_root_url()` / `proxy_auth_token()`, never literals, so a non-default port writes a config that works.
- The raw auth token never reaches a response body, an error detail or a status field.

## Launcher split

`fcc-claude` now sets **only** `ANTHROPIC_BASE_URL` and `ANTHROPIC_AUTH_TOKEN` over the inherited environment. The previous behaviour — gateway model discovery, auto-compact window, telemetry disabled, inherited `ANTHROPIC_*` cleared — is preserved verbatim as **`fcc-claude-old`**, and both are propagated through the installers, uninstallers, README, USAGE and ARCHITECTURE.

## Architecture

`proxy_auth` moves `cli/` → `config/`: the admin API needs it and the declared package policy does not allow `api -> cli`. `tests/contracts/test_import_boundaries.py` caught this. Callers updated, no shim left behind.

**Drove the real dashboard in Chrome** against a throwaway path — Configure → `Configured — pointing at this proxy`, Remove → `Not configured`, buttons disable in flight, every render comes from the server's returned status. The warning states render as intended:

```
Points elsewhere — current base URL is http://127.0.0.1:9999, and the token
differs. Configure will overwrite this.
C:\tmp\claude\uitest\settings.local.json also sets ANTHROPIC_* variables and
takes precedence over the file above.
```

Clicking Configure on a malformed file through the UI left it byte-identical on disk and surfaced the parse error.

**HTTP layer**, all three routes:

```
APPLY 200 -> state: configured | expected_base_url: http://127.0.0.1:8082
UNSET 200 -> state: unset      | expected_base_url: 'http://127.0.0.1:8082'
token leaked in any body: False
reject 'relative/settings.json' -> 400 Path must be absolute
malformed apply -> 409 | token in detail: False | file untouched: True
non-loopback GET -> 403
```

**Both launchers** run Claude Code 2.1.223 and route real prompts through the proxy. The `claude.ai connectors are disabled` notice appears identically on both, so it is caused by setting `ANTHROPIC_AUTH_TOKEN` at all — not by the minimal environment.

**Full suite: 3155 passed, 14 failed** — the documented pre-existing baseline (8 defeated by real API keys in the shell environment, 6 PowerShell installer tests), unchanged on unmodified `main`.

## Residual risks

- **Unverified:** whether dropping `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` empties the interactive model picker. It is an interactive-only signal and could not be observed headlessly; the proxy does serve `GET /v1/models`. `fcc-claude-old` is the escape hatch if it does.
- Unset removes only the two keys rather than restoring prior values. The `.fcc-backup` file covers recovery; a restore-on-unset would need a separate sidecar.
- `json.dump` normalises formatting and would drop comments. Claude Code's settings file is strict JSON, and the card says so.
- The installers now require `fcc-claude-old` to exist, so a partial install fails verification rather than silently shipping one launcher.
