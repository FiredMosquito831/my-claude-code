## Description

Both the in-dashboard Guide and `docs/USAGE.md` still told the reader to *"paste a key, press **Validate**, then **Apply** and select it as active"*. After 4.39.0–4.40.1 none of that is the flow — and one clause was **never** true: there is no "active provider" to select, the model ref on Model Config decides who serves a request.

A walkthrough that names a button which does not exist is worse than no walkthrough, because its reader cannot tell "I misread this" from "this lies".

## What they say now

Search for the provider — the box matches name, id **and** variable name, so `GROQ_API_KEY` finds Groq. Press **Configure** to open its key pool. Paste into **Add key**, several comma-separated if you like. **Keys save immediately and do not need Apply.** Rotation *does* need Apply, and restarts the server. **Refresh models** is the real API call, so a model count is the confirmation that a key works. Local backends offer **Test connection** instead.

The "reading validation failures" table is now "reading a failed **Refresh models**" — the control that actually produces those status codes.

**README:** two stale routes fixed. `Providers → Manage keys` is no longer the path, and the per-provider button is Refresh models, not Test.

## The guard, not just the fix

Part IX has carried *"docs drift is unguarded"* as a known gap for a long time, and it finally cost something. `tests/contracts/test_docs_ui_labels.py` now pins every control name the docs instruct the reader to press, and fails if the dashboard stops defining it.

**That guard took three attempts to be worth having, and both faults were found only by breaking it deliberately:**

1. It searched `index.html` wholesale — but **the Guide lives in `index.html`**, so it matched the Guide's own prose and passed regardless of whether the control existed. The Guide view is now cut out of the surface it searches.
2. It substring-matched, so after renaming *both* real "Refresh models" buttons it still found the hint string `"No discovered models. Refresh models or enter a custom slug."` and passed. It now requires the label as a fully quoted JS string, or as element text in the markup.
