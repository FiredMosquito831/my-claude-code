## Description

The README, the in-dashboard Guide and `docs/USAGE.md` all still described routing as it was before 4.41.0. Three releases of behaviour were undocumented — including two things a reader would otherwise only discover by accident.

## README

- **The commit boundary now says what it actually is.** "Failover stops at the first streamed chunk" was true only for streaming clients; a non-streaming request commits at the *end* and can fall back from anywhere. Both are in a table now.
- **`MODEL_VISION_FALLBACKS`** documented, including the rule that a model known to reject images is skipped inside a vision chain.
- **A new "Route Tracing" section** — the five columns, why the chain is stored even when the primary answers, and what the Failover and Vision adapter panels show. Linked from the fallback section.
- **ChatGPT OAuth models are discovered, not hardcoded.** Plus the thing that will otherwise cost someone an afternoon: `gpt-5.6` is a family name whose bare id 404s — only `-luna`, `-sol` and `-terra` are callable.
- Vision adapter added to the feature table.

## In-dashboard Guide

Under **Map model tiers**, in the Guide's task-first voice:

- How to add a fallback chain, and the failover boundary framed as the thing people get wrong — *a chain rescues failures before the first word, not at word five hundred*.
- Why images route separately, that only a **known** refusal diverts (silence is not a refusal), and that the tier's own card tells you when it applies so you don't have to work it out.
