## Description

Three defects found auditing the web search stack against `main`. Bug fixes only — PATCH `4.18.2` → `4.18.3`.

## 1. Rate-limit cooldown ignored what the provider said

`KeyPool.report_rate_limit` benched every 429 for a fixed 60s, and `adapters/http.py` never inspected response headers. A key that resets in one second sat idle for a minute; one needing an hour got hammered — an artificial ceiling instead of the provider's own signal.

The parser for these headers already existed for the LLM provider path. Rather than have `websearch/` import from `providers/`, it moved to the neutral `core/rate_limit.py` and both callers now share it (`retry_after_seconds`, `parse_rate_limit_duration`). `failure_policy.py` drops its duplicate.

Covers `retry-after`, `retry-after-ms`, `x-ratelimit-reset-*`, `ratelimit-reset`, suffixed durations (`6m0s`, `250ms`), and HTTP-dates. Capped at 1h so a bad header can't bench a key indefinitely; falls back to the existing default when the provider stays silent.

## 2. Retention desynced the two analytics tables

One logical route writes one row to `search_route_log` but ≥1 to `search_log` (an extra per fallback hop), so the attempt table reaches `max_rows` first. Both were pruned to the same row count, leaving routes summarizing a window whose attempt detail was already gone — while the dashboard renders "Terminal route outcomes" and "Provider attempt performance" side by side as if they covered the same period.

Routes are now trimmed to the window surviving attempts still cover, so the two tables reconcile.

## 3. `WEBSEARCH_LOG_CAPTURE_CONTENT` did not cover the query

The setting exists so operators can stop persisting search content — its own comment says *"Disable for hashes/lengths only when searches may contain sensitive content."* But the `query` column was written verbatim to **both** tables regardless, leaving the most readable part on disk after opting out. Payload JSON already honored the flag; the query now does too.

## Verification

New tests reproduce each defect and fail without the fix:
- retention window alignment across routes and attempts
- query withholding in both tables when capture is off
- `Retry-After` parsing across all four header families
- cooldown cap and silent-provider fallback

`ruff format`, `ruff check`, `ty check` all clean; no suppressions added.

Full suite passes except 14 failures that **also fail on unmodified `main`**: 8 caused by real API keys in the local environment leaking past test isolation (`Settings()` reads process env, not just `env_file`), and 6 PowerShell installer tests. Neither group is touched by this change.

## Residual risks

The retention change means route rows are now discarded earlier than before when fallback is frequent — that is the intended trade for making the two tables describe the same window, but it does reduce how far back the route summary reaches on busy installs.
