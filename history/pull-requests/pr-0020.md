## Description

MINOR `4.20.0` → `4.21.0`.

## Problem

The update banner said *"Update available: v4.20.0"* and linked out. A version number alone doesn't tell you whether an update matters to you — so the part that actually decides it (what changed) sat one click away and mostly unread.

This landed badly in practice: v4.20.0 shipped three releases' worth of web search work, including a change that alters what the model sees and your token cost. Nothing in the dashboard conveyed that.

## Change

The GitHub release feed already returns the notes in `body`; we simply never read them. `ReleaseStatus` now carries `release_notes`, and the banner renders a collapsed **What changed** section beneath the title.

Bounded at 4,000 characters with a trailing ellipsis — the feed is remote, so the banner shows an excerpt and keeps the existing link for the rest rather than rendering an unbounded blob into the dashboard.

## Verification

`ruff format`, `ruff check`, `ty check` clean; no suppressions. Full suite passes except the 14 failures that also fail on unmodified `main`.

## Residual risks

Notes render as pre-formatted text, not Markdown — headings and tables show their source characters. That's deliberate: rendering remote Markdown into the admin DOM is a larger call than this change should make on its own.
