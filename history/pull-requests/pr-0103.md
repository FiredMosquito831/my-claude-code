## Description

## What

Adds a session-scoped autouse fixture to `tests/conftest.py` that:
1. Resets both shared-store registries (`request_log.reset_request_log_stores()` + `analytics.reset_analytics_state()`) at session **start and end**.
2. Fails loudly if any FCC-owned background writer thread survives the whole session (`fcc-request-log-writer`, `websearch-log-writer`, `chatgpt-oauth-callback`, `fcc-open-admin-browser`).

## Why

The request-log and web-search stores each start a daemon writer thread. A store a test constructs and never closes keeps its queue, sqlite connection and held records alive for the rest of the process — under xdist that accumulates per-worker and reads as a memory leak with "processes that won't die". The user reported the test suite filling 64 GB RAM.

## Verification

- **Guard proven to catch a leak:** a directly-constructed `WebSearchLogStore(Path(...))` left unclosed makes session teardown fail with `assert not ['websearch-log-writer']`.
- **Full suite with the guard active:** 3704 passed, 26 known environmental failures (identical to unmodified main), 26 skipped — zero leaked threads, zero leftover processes.
- The suite does **not** leak from a clean checkout (verified across 3 separate runs with `-n auto` = 16 workers); the 64 GB report appears to have been the unrelated `autonomous-agent-sdk` MCP project on the same machine (~20 python processes at ~79 MB each), plus `fcc-claude` launchers.

## Residual risks

- The known broken local xdist worker (`OSError: [Errno 22]`, WORKING-NOTES §122) is intermittent and did not trigger this session; this guard does not fix that, but it makes any future thread leak loud.
- The 26 failures are the documented environmental baseline (16 PowerShell installer + ~10 websearch/env-key), not a regression.
