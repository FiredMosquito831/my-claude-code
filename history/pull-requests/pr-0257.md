## Description

## The headline

**The Claude subscription provider had never served a request.** Not "failed
sometimes" — **0 rows** out of 267,619 in the retained request log
(2026-08-01 → 2026-09-02), and no `request_attempts` row either. This PR is not
fixing failing traffic; it is turning on a provider that has been dormant since
it was written, and fixing the four independent reasons it could not have worked.

The root cause is one line. `providers/anthropic_oauth/auth.py` presented the
OAuth token in `x-api-key` and never set `Authorization` at all. Claude Code
2.1.258 puts an OAuth credential in `Authorization: Bearer` and explicitly nulls
`X-Api-Key` (binary offsets `187124317`, `181109007`, and its own in-bundle curl
example at `96384881`); `opencode-anthropic-auth@0.0.13` arrives at the same
shape independently and calls `requestHeaders.delete("x-api-key")`. The one test
covering the header set asserted the bug, and is rewritten here deliberately.

**This PR makes a dormant provider live.** That is the risk, and it is the point.

## The header table, as shipped

Inbound Claude Code request → upstream `api.anthropic.com`. Every value is either
mirrored from what the client itself sent or a documented fallback; nothing is
manufactured. `providers/anthropic_oauth/auth.py` carries this table with the
byte offsets.

| Header | MCC sends | Evidence |
| --- | --- | --- |
| `Authorization` | `Bearer <access token>` | offsets 187124317 / 181109007 / 96384881; `opencode-anthropic-auth@0.0.13` |
| `x-api-key` | **never sent** | same — Claude Code nulls it whenever an OAuth credential is in play |
| `anthropic-version` | the client's value, else `2023-06-01` | offset 181109007 (`buildHeaders`) |
| `anthropic-beta` | floor `oauth-2025-04-20,claude-code-20250219` ∪ (client's list ∩ closed allow-list) | registry at offset 183023150 + 120,969 measured inbound requests |
| `user-agent` | the client's value, else `claude-cli/2.1.258 (external, cli)` | shape at offset 183634762; the old constant was `claude-cli/2.1.235.2db (external, cli)`, a `cc_version` build suffix spliced into a UA |
| `x-app` | the client's value, else `cli` | offset 187124946 — `cli-bg` is real traffic and used to be flattened to `cli` |
| `anthropic-dangerous-direct-browser-access` | `true` | present in real inbound Claude Code traffic |
| tool names | **verbatim** | 0 hits for any `cc_` tool name in the 218 MB binary, against 137 for the real `mcp__` |

Unknown inbound betas are dropped and their names logged, never forwarded: an
unrecognised beta is the likeliest cause of a 400 that looks like a model problem.

The `cc_` prefix machinery (`tool_names.py`, `apply_tool_prefix`,
`strip_tool_prefix_from_frame`) is deleted. It was OpenCode's `mcp_` disguise
with the string swapped, and its reverse pass was a blind
`frame.replace('"name":"cc_', '"name":"')` over each SSE frame — so any *content*
containing that literal was corrupted too. A test now asserts both halves.

## The gate

**Rule (admission):** the request body's `cc_entrypoint` marker, and nothing
else. It travels in the body, so MCC can neither forge it for traffic it did not
receive nor strip it from traffic it did.

**Admitted:** `cli`, `cli-bg`, `sdk-cli`, `sdk-py`, `sdk-ts` — the Claude Code
CLI and the Claude Agent SDK, which drives the Claude Code binary. Everything
else is refused. Before this PR the gate admitted `cli` alone, which refused
**64%** of this operator's genuine Claude Code traffic (77,064 of 120,969 measured
requests are `sdk-py`) — the client Anthropic's own policy names *alongside*
Claude Code, not against it. Note also that `claude -p` reports `sdk-cli`, so
even the plain CLI in print mode was refused.

**Corroborants, recorded and never used to refuse:** the inbound
`user-agent`'s entrypoint, its version, and `x-app`, plus an `agreed` flag, are
logged on every gated request. Making them a second admission test would add a
thing to keep in sync with an upstream nobody here controls.

**Default: on.** The docs now say plainly that the marker is a *good-faith
attribution field, not an authenticator* — its value is
`process.env.CLAUDE_CODE_ENTRYPOINT`.

**The refusal message, verbatim from a live run:**

```
The Anthropic subscription provider only serves requests that come from Anthropic's
own clients -- the Claude Code CLI or the Claude Agent SDK. This request reports
cc_entrypoint=opencode, so it was refused rather than billed to your Claude
subscription. Route it to the `anthropic` provider (Claude Console API key)
instead, or set ANTHROPIC_OAUTH_REQUIRE_CLAUDE_CODE=false if you have read
docs/ANTHROPIC-SUBSCRIPTION.md and accept what it says. Admitted entrypoints:
cli, cli-bg, sdk-cli, sdk-py, sdk-ts.
```

## Token lifecycle, as implemented

- **Proactive and non-blocking.** Inside the 120 s leeway the credential is
  refreshed on a background task and the request in hand goes out on the token it
  already has, which is still valid. Only a genuinely expired token blocks.
- **Single-flight per credential *file*,** not per provider instance — a hot
  reload builds a second provider, and two instance-local locks let both spend the
  refresh token and clobber each other. Double-checked inside the lock: the loser
  finds a fresh credential already stored and returns it.
- **401 → refresh once, retry once,** inside the attempt the rotating loop had
  already budgeted. A second 401 is an authentication failure. Asserted at exactly
  two upstream calls, never three.
- **Refresh POST** carries `anthropic-beta: oauth-2025-04-20` (offset 180990503),
  which MCC sent on no request before.
- **Endpoints** moved to Claude Code 2.1.258's (`platform.claude.com`), with the
  `console.anthropic.com` hosts kept as a documented fallback on 301/308/404.
  Login asks for the full six-scope set instead of three.
- **`refreshTokenExpiresAt` and `rateLimitTier`** survive load → store → load
  instead of being parsed away; `expiresAt` is written in milliseconds like the
  Claude Code file it mirrors, and both units still load.
- **Atomic 0600 write kept.** `~/.claude/.credentials.json` is still read-only to
  MCC and never refreshed in place.
- **Raw `ANTHROPIC_OAUTH_ACCESS_TOKEN` stays non-refreshing, and is documented as
  such** — there is nothing to refresh it *with*. A comma-separated list now fails
  construction: several non-refreshing tokens are not a rotation pool, and
  rotating subscription credentials is the "unusual traffic pattern" the policy
  names.
- **No token, and no token-endpoint response body, can reach an exception
  message.** `oauth_login.py` used to put `response.text[:200]` in one.

## Deviations from the spec

- **No new `params` keys in the request log.** R17's corroboration is a
  structured log line rather than a `params` field, to keep the request-log
  schema out of a wire-shape PR.
- **`x-claude-code-session-id` / `-agent-id` / `-parent-agent-id` are not
  mirrored** and `ALLOWED_HEADERS` is unchanged. They are correlation ids for a
  session MCC is not, and mirroring them would put a client-side identifier into
  durable storage for no diagnostic gain.
- **`key_label` is `"<plan> · <source>"`** (`max · mcc`), per Q7 — MCC never
  fetches the profile, so there is no email to use and adding a `user:profile`
  call per credential for a log label would be a new upstream request.
- **No `JOURNAL.md` entry**: the file the spec's §7 names does not exist on this
  base.
- Version is **6.36.0** (MINOR) from 6.35.1, not the spec's 6.33.0 → 6.34.0.

## Residual risks

- **A dormant provider is now live.** With the gate on and widened, the Agent SDK
  traffic that used to be refused will now reach the subscription credential. That
  is the requested behaviour and it is a real increase in volume against the
  account.
- **Merging the client's betas can surface an entitlement 429/400.** Live request
  #1 hit exactly that: the client sent `context-1m-2025-08-07` and the account
  answered "Usage credits are required for long context requests." The alternative
  — dropping the beta — would silently cap a 1M-context session at 200k, so the
  merge stands and the upstream body is surfaced in the error.
- **SUSPECTED, still:** that `x-api-key` is *what* 401s. Nothing proves it,
  because nothing ever ran; what is now CONFIRMED is that the Bearer shape is
  accepted. **UNVERIFIED:** whether the `console.anthropic.com` fallback path is
  ever exercised — both hosts answered 429 throughout.
- **The refresh path is untested against a live 200.** It is covered by fixture
  tests only; every real attempt was rate-limited.
- **The gate is not an authenticator.** Anything that sets
  `CLAUDE_CODE_ENTRYPOINT` and reuses Claude Code's system-prompt shape can claim
  an admitted entrypoint. The docs say so now.
- **It cannot protect an already-flagged account,** and this PR does not change
  Anthropic's position that none of this is permitted.
