## What changed

The 5.1.0 defer logic broke when **exactly one** launcher was running. On Windows, `uv tool install --force` cannot replace the tool environment while a process runs from it, so the installer defers the update to a detached helper. But `Get-RunningLaunchers` used `return $running`, and PowerShell unwraps a single-element array on return — a lone running launcher came back as a scalar `Process` object, and the caller's `$running.Count -gt 0` threw:

```
The property 'Count' cannot be found on this object. Verify that the property exists.
```

under `Set-StrictMode`. The whole install aborted instead of staging the update.

**Fix:** `Get-RunningLaunchers` now emits matches to the pipeline (no bare return), and the caller wraps the call in `@(...)`, so 0, 1, or many launchers always arrive as an array and `.Count` is always valid.
