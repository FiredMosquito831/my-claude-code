## Description

## What changed

Replaces the two "Export JSON" buttons (which only fetched the first 500 rows) with a single **Export** window covering both Model requests and Web Search.

- **Formats**: JSON, CSV, XLSX, TXT
- **Scope**: Model requests | Web Search
- **Period**: last hour / 24h / 7d / 30d / custom from–to
- **Fields**: the exact requested checklist (input, output, tool calls, thinking, providers, models, error rate, cache hit, total input, input cached, input uncached, tokens out, turns with tools) — plus a web-search field set
- **Categorization**: group by provider / period / model / key, with selectable order (e.g. Provider → Period → Model)
- **Full DB**: the 500-row page cap is bypassed; exports stream the entire matching set via keyset pagination (no OOM)

Plus **site persistence**: the active view, the Analytics auto-refresh toggle + interval, and the Web Search period are saved to `localStorage` and restored on refresh. The onboarding "Get Started" force still wins on a fresh install.

## Backend

- `GET /admin/api/export` (loopback-guarded), `StreamingResponse` fed by a sync generator (Starlette threadpool keeps SQLite off the event loop)
- `core/export.py`: field registry + per-format renderers (CSV with BOM, XLSX via openpyxl `write_only` + spool, TXT readable report, JSON array-wrapped stream)
- `RequestLogStore.iter_export_rows` / `iter_export_aggregates` + websearch equivalents: keyset pagination over `(ts_epoch, id)`, single connection closed in `finally`, bodies decompressed only when selected
- `openpyxl` added as a dependency; version bumped 5.1.2 → 5.2.0

## Residual risks

- `format=json` detail is an array-wrapped streamed document; the client downloads the Blob with zero parsing. Very large exports with bodies can produce tens-of-MB files — acceptable locally.
- Aggregate mode rejects raw-text-only fields (web-search query/input/output) with a 400; the UI's default field set avoids them.
- `openpyxl` is a new dependency; it is locked in `uv.lock` with the version bump.
