## Description

## What was wrong

Opening a request in the dashboard showed `(not captured)` for the output of most turns. The read path was never at fault — the detail route selects the row whole and the UI renders `output_text` as given. Nothing was ever written.

`_parse_frame` handled exactly one delta type:

```python
if isinstance(delta, dict) and delta.get("type") == "text_delta":
```

An assistant turn streams three. `thinking_delta` and `input_json_delta` were dropped, so a turn that only called tools — the ordinary shape under Claude Code — stored an empty string.

Measured on a live 17,825-row log, last 24h:

```
(has_tools, has_output) -> n
(False, True)      5      no tools: captured every time
(True,  False)  4728      tools, no prose: nothing stored
(True,  True)    453      tools plus prose: the prose was stored
```

Not one zero-output row lacked tools, and they are not empty responses: `tokens_out` averages 148 and peaks at 6,725. The frames were parsed correctly all along — `tokens_out` comes from the same parser — only the delta types were filtered out.

**This is not a recent regression.** `git log -L` over `_parse_frame` shows the `text_delta`-only condition has been there since the original analytics commit. What changed is that traffic shifted to tool-heavy sessions, taking the captured share from 55% in July to under 10%.

## What changed

**Capture.** Tracks `content_block_start` to learn each block's type and tool name, then routes deltas to prose, reasoning, or per-index tool argument buffers. Reasoning and tool arguments are request bodies, so they follow `REQUEST_LOG_CAPTURE_BODIES`; the character and call counts persist either way so list views can show the shape of a turn without loading its transcript. A stream cut mid-arguments keeps the fragment rather than discarding the call.

**Request detail.** Renders the three kinds as three kinds instead of one undifferentiated `<pre>`: reasoning in a collapsed pane, tool calls as name chips with pretty-printed arguments, prose on its own. Empty is no longer one condition — "this turn called tools without writing a reply" and "bodies are not being stored" now say so. The table gains a Turn column.

**Guide.** `.guide-body` capped the whole column at 78ch and `.guide-shot` was `width:100%` of that cap, so screenshots of a full dashboard rendered at ~600px and were illegible while two thirds of the page sat empty. Prose and figures now get different widths: the column runs to 1180px, only running text is held at 74ch. Screenshots open at full size on click, keyboard reachable, captioned from their alt text. Body text to 15px/1.7, callouts no longer dimmed, section rules, and the contents list marks the section being read.

**Analytics.** Denser, not sparser. New aggregates for tool calls, turns using tools and turns with reasoning, each with its share of the window. The detail header goes from 8 fields to 19, adding cache read/write, per-request cache hit rate, and output rate in tokens/sec measured after first token. Charts were drawn in hardcoded blue and red against an emerald UI and stretched to a fixed 640x180 bitmap; they now read design tokens, scale to `devicePixelRatio`, and carry a value scale.

The reasoning pane uses the `--info` blue already in the token set, so the palette stays exactly as wide as it was.

## Residual risks

- **Historical rows keep their empty output.** Only new requests carry reasoning and tool calls. Rows logged before this change will still show the empty-reply message, which is accurate for what was stored.
- **The migration adds four columns to a large table.** It ran in well under a second on the 503 MB production log, but it is a one-time `ALTER TABLE` on first open.
- **Bundled guide screenshots still show v4.15.0.** They predate both the emerald charts and the new request detail. Refreshing them needs a live server with real data.
- Reasoning text is now persisted when body capture is on. It is the most sensitive content in the stream, and it is stored locally under the same switch as every other body.
