## The design, in one table

| | Decision | Why |
| --- | --- | --- |
| Scope | The shell binary, its icon, a Start Menu shortcut. **Nothing else.** | Decision Q4 moved the bootstrap into the app (PR #272): on launch with no `mcc-desktop` the window prints the exact install command and runs it. An installer that carried the server would be a second, divergent copy of `install.ps1`, and would want admin rights the moment it wanted to place a Python. This one is 3.2 MB and needs none. |
| Privileges | `PrivilegesRequired=lowest`, `PrivilegesRequiredOverridesAllowed=dialog` | Per-user, no UAC. The uninstall key lands in `HKCU\...\Uninstall\{AppId}_is1` — the shape winget's `Scope: user` + `AppsAndFeaturesEntries.ProductCode` expects (S8). |
| Location | `{localappdata}\Programs\My Claude Code` | Equals `{userpf}` in non-administrative install mode, which is what the Inno docs say. |
| Identity | `AppId={{5FC8D5C3-33F7-4366-AD8D-C844D21BC089}`, fixed forever | It is the upgrade key, the uninstall key name and the winget ProductCode. A contract test pins it. |
| Arch | `ArchitecturesInstallIn64BitMode=x64compatible` | True on x64 *and* on Arm64 running x64 code, which is what an x86_64 binary actually needs. |
| Registry | **No `[Registry]` section at all** | Start-at-login has exactly one writer — `_reconcile_start_at_login`, from `desktop.json`. A second writer would make "remove the window" silently disable the server tray's autostart. |
| Desktop icon | An unchecked `[Tasks]` entry | An unasked-for desktop icon is the commonest complaint about Windows installers. |
| Post-install | "Launch My Claude Code" checkbox, `skipifsilent` | |
| Version | `/DAppVersion=<tag without v>` at compile time | CI stamps the release tag; a non-numeric dispatch tag falls back to `0.0.0` with a warning, because `VersionInfoVersion` must be numeric. |

### WebView2

Detected through the key Microsoft documents — the EdgeUpdate client `{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}` and its `pv`, in `HKLM` (32- **and** 64-bit views) and `HKCU`, treating absent/empty/`0.0.0.0` alike. Windows 11 ships the runtime and Windows 10 has had it pushed since December 2022, so on nearly every machine nothing is downloaded.

Only when it is genuinely absent is the ~2 MB Evergreen Bootstrapper fetched from `https://go.microsoft.com/fwlink/p/?LinkId=2124703` and run with `/silent /install`.

**Its SHA-256 is deliberately not pinned, and cannot be.** It is a *rolling* download whose bytes change every time Microsoft ships a runtime; a pinned digest would break every install the day a runtime shipped. What *is* pinnable is the URL — the permanent fwlink Microsoft documents for this exact purpose, over HTTPS to a Microsoft host — so that is what is pinned, with the reasoning in the script header. Fixed Version is 250+ MB and would need hand-updating per CVE. A failed download warns and continues rather than aborting: a briefly offline machine should still end up with the app, and `SuppressibleMsgBox` means `/VERYSILENT` never hangs on that dialog.

## What it does *not* do

- Does not install Python, `uv`, `mcc-server`, or any of the 40 entry points.
- Does not write the `HKCU\...\Run` autostart value.
- Does not touch `~/.local/bin`, `~/.mcc` or `~/.fcc` — on install or on uninstall.
- Does not appear in the Path A pin table. `config/desktop_shell.py` fetches the **zip**; a `setup.exe` would have to be *run*, per-user, with a Start Menu shortcut and an Apps & Features entry as side effects, to place a file that module already knows how to place itself. Two installers writing the same binary is how you get two of them. The extra checksum line is simply ignored, and a comment there says so.

## The uninstall split

| Uninstaller | Removes |
| --- | --- |
| **"My Claude Code (desktop app)"** (Apps & Features) | The exe, the icon, both shortcuts, the `HKCU` uninstall key, the WebView2 user-data directory. Asks — defaulting to **no** — about the app's remembered window geometry (`%APPDATA%\com.myclaudecode.desktop`). |
| `scripts/uninstall.ps1` | Everything else: the shims, the config directory, the shortcut `install.ps1 -Desktop` made, the start-at-login value. |

The Apps & Features entry says "(desktop app)" out loud so that nobody has to guess.

The opt-in deletion lives in `[Code]` and not `[UninstallDelete]` on purpose: `[UninstallDelete]` entries are recorded into the log at *install* time, so a `Check:` on one would ask the question months before the answer matters.

## The parity contract

`tests/contracts/test_uninstaller_parity.py` gains a third section (9 tests). It parses the `.iss` into sections and asserts:

- nothing in `[Files]`/`[Icons]`/`[Dirs]` carries `uninsneveruninstall` — Inno removes those automatically, and that flag is the only way out of it;
- every `[Files]` entry lands under `{app}` and every `[Icons]` entry under `{autoprograms}`/`{autodesktop}`;
- there is **no `[Registry]` section**, and the file never names `CurrentVersion\Run` or `MyClaudeCodeDesktop`;
- no entry names `.local`, `.mcc`, `.fcc`, `{userprofile}` or `uninstall.ps1`;
- the shell data directory is removed only from `[Code]`, through `SuppressibleMsgBox` defaulting to `IDNO`;
- `AppId`, `PrivilegesRequired=lowest`, `Uninstallable`, the `(desktop app)` display name and the display icon are all pinned;
- the WebView2 fwlink and client GUID are present;
- the smoke passes the winget switch set, and the workflow runs and uploads it.

## Autostart safety override (required by an incident)

`MCC_DESKTOP_SKIP_AUTOSTART=1` makes `_reconcile_start_at_login` a no-op with one log line, and `--print-status` reports `autostart_reconcile: bool`.

The OS registration is **machine-global** (one `HKCU\...\Run` value, one LaunchAgent, one XDG entry) while `start_at_login` lives *inside a config directory*. Those two facts do not compose: a `mcc-desktop` launched against a scratch `MCC_CONFIG_DIR` loads a fresh `desktop.json`, sees the default `false`, and dutifully deletes the registration belonging to the user's **real** install. That is not hypothetical — it happened during this work, to a real `MyClaudeCodeDesktop` value. Only the exact value `1` disables it, so a mistyped variable fails safe in the direction that matters. 10 new tests, plus one in `test_desktop_print_status.py`.

## Local proof, on a machine with a live 6.44.0 install

Compiled locally with Inno Setup 6.7.3 installed **per-user into the scratchpad** (there is no winget on this box; the pinned `innosetup-6.7.3.exe` was downloaded and run with `/VERYSILENT /CURRENTUSER /DIR=…`). Setup exe: **3,313,312 bytes**, `77c88b9eb6efc35f91be9783eb8419d135e7e71b767c92adf084cb2e62927ccd`.

Snapshotted `HKCU\...\Uninstall`, `HKCU\...\Run`, the whole Start Menu Programs tree and `~/.local/bin` **before**; installed `/VERYSILENT /DIR=<scratch>`; ran the proofs; ran `unins000.exe /VERYSILENT`; snapshotted **after**:

[installed] uninstall=37 run=16 startmenu=183 localbin=50
[after]     uninstall=36 run=16 startmenu=182 localbin=50

All four diffs empty. The real `MyClaudeCodeDesktop` value survived. `uninstall.ps1` was never run and the live server (PID 48392) was never touched.

Two behavioural proofs on the **installed** binary:

1. `smoke/windows.ps1` against a foreign-status stub — the window launches, reads `--print-status`, shows the port-conflict page and **starts nothing**.
2. The Q4 bootstrap: with `MCC_SHELL_DESKTOP_COMMAND` pointed at a non-existent path, the shell ran the install command. A stub `powershell.exe` at the front of `PATH` recorded the argv and refused to execute it, so nothing was downloaded and the real `install.ps1` never ran:

```
ARGV: -NoProfile -ExecutionPolicy Bypass -Command & ([scriptblock]::Create((irm "https://raw.githubusercontent.com/FiredMosquito831/my-claude-code/main/scripts/install.ps1")))
```
