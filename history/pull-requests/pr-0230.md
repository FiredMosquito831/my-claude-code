## Description

## What was wrong

The Analytics tab counted every request MCC answered itself alongside the ones that actually reached a provider. On this machine that is **1,336 of 14,662 rows (9%)** — 1,028 `probe_auto_response`, 278 `title_generation_skip`, 30 `suggestion_mode_skip`. They took most of the table's first page, sat in the provider breakdown as `answered locally · <rule>`, and were inside every card, chart and rate, so "how is my proxy doing upstream" could not be read off the tab without subtracting them by hand.

Second complaint, mechanical: a changed filter did nothing until **Apply** was clicked, so the numbers on screen routinely answered a question the controls no longer asked.

## Mechanism

Locally answered rows are exactly `provider IS NULL AND optimization IS NOT NULL`. `provider IS NULL AND optimization IS NULL` is the `(unknown)` case — a different claim — and stays visible. One `_where()` serves `list_requests`, `stats` and `pulse`, so a single predicate there covers the table, the cards, the series and model charts, the provider/key breakdowns, top errors, and the fallback/diverted routes at once.

## What the fix does

- New `local` filter: `all` / `hide` / `only`, on `_where`, `list_requests`, `stats`, `pulse` and the three admin routes (`/admin/api/requests`, `/stats`, `/pulse`). A fourth value is a **422**, matching how `status` is refused.
- **The API default stays `all`.** Absent means unfiltered, so exports, curl users, and the Guide's examples are unchanged. Only the dashboard prefers `hide`.
- `local` joins the stats cache-key tuple. Without it a `hide` call inside the 5 s TTL would be served the `all` numbers it had just cached, and the cards would contradict the table.
- New **Local answers** select (Hide / Show / Only) in the filter row, persisted in dashboard state and reset to Hide by **Clear filters**.
- **Filters apply themselves**: selects on `change`, text boxes 400 ms after the last keystroke, Enter still immediate, each from `offset = 0` and each persisted. **Apply** stays for people who would rather press it. `loadId` already discards stale responses, so overlapping loads from fast typing settle on the last one.
- One paragraph each in the in-dashboard Guide and `docs/USAGE.md`.

## Residual risks

- **Exports are unfiltered, deliberately.** The export window forwards the analytics filters, so `local` now rides along in the export query and is ignored server-side (verified: `/admin/api/export?...&local=hide` returns 200 and includes locally answered rows). An export therefore still contains everything. Stated in the Guide and `docs/USAGE.md` rather than widening this change into `api/export.py`.
- **All time / lifetime totals are unfiltered**, as they are for every other filter. The tab's own wording now says the cards and charts follow this filter and the rollup does not.
- The dashboard default is a behaviour change a returning user will notice: the cards drop from 14,662 to 13,326 on this install. Switching **Local answers** to **Show** restores the old totals, and the release notes lead with that.
- `provider=local:<rule>` combined with `local=hide` returns nothing — both predicates are ANDed. That is the honest answer to a contradictory question rather than silently dropping one; covered by a test.
- jsdom has no layout engine, so the new select's placement in the filter row was checked in Chrome by eye and by the a11y snapshot, not by an automated layout assertion.
