## Description

The follow-up flagged in #67. Content addressing keyed on the **whole body** deduplicated 1.4% of a real log, because a retry re-sends the same context and gets a *different* answer back — so bodies rarely match even when prompts do.

## Measured across the whole corpus, not a sample

```

distinct prompts       : 35,445
repeat rate            : 29.7% of requests
prompt bytes           : 1.64 GB   (98% of all body bytes)
duplicate bytes        : 0.58 GB   (35.3%)
```

I had predicted ~62.7% from a sample of recent traffic. Corpus-wide it is 35.3% of bytes — worth doing, but not what I said, so I measured before building rather than after.

## Design

- Prompt in one content-addressed blob; reply, reasoning and tool calls in another.
- **Both layouts coexist without a version flag.** A blob written before the split still carries its prompt inside it, and the *absence* of that key is what identifies a reply-only blob. Reads merge the two.
- **Search considers both blobs together** — `proxy 8082` can have one word in the prompt and the other in the reasoning, and requiring every word within a single blob would have silently stopped finding it. Covered by a test.
- Compaction splits existing combined blobs in a second pass.
- `NOT NULL` relaxed on the reply reference, which a prompt-only request now legitimately leaves empty. SQLite cannot drop that in place, so the table is rebuilt — found by running against the real database, not by reading.
