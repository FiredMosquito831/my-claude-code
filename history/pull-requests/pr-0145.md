## Description

## Why

The dashboard has repeatedly shipped defects that **every automated check was blind to**, because nothing verified that the three assets agree:

- A control built its `<input>`, wrote every edit into it, and **never appended it to the DOM**. Saving was impossible for four releases, and a user found it, not CI.
- A settings section was registered with 18 fields, served correctly by the API, and claimed by no view — so it **rendered nowhere**.
- Six classes were emitted with no CSS rule after a bad conflict resolution dropped a stylesheet block. The page loaded, every test passed.
- Spacing tokens were used that were **never defined**, so those declarations were dropped and elements shipped with `padding: 0` for five versions.

No Node, no jsdom, no new dependency — pure Python parsing the shipped assets.

## The five guards

| Guard | Measured |
| --- | --- |
| every `byId()` / `getElementById()` id exists in `index.html` | 149 lookups, **all resolve** |
| every class `admin.js` applies has a rule in `admin.css` | 233 emitted, 376 rules |
| every fallback-free `var(--token)` is defined | 48 refs, 50 tokens, **none undefined** |
| every `VIEW_GROUPS` id has a `data-view` section | both directions |
| every `data-view` section has a `VIEW_GROUPS` id | |

Each parses the shipped asset rather than a Python mirror — **a mirror agrees with itself while the page stays blank**.

## The class scan had to be built carefully

A naive quoted-string capture stops at the first quote inside a template interpolation, and a nested template literal leaves an unterminated `${`. Both emit fragments that were never class names — and a noisy guard is one somebody deletes in six months.

This splits template literals on brace-depth-matched interpolations and drops words glued to an interpolation boundary. Without that filter the scan reported **five false positives** (`cc-diff-`, `claude-origin-`, `claude-state-`, `key-health-`, `req-status-`), every one a prefix concatenated with `${var}`. With it: **zero false positives** across all three assets.

## Three genuine defects found

Recorded rather than silently patched, each with the measurement that says which fix it wants:

- **`cc-section` — a missing rule.** Its children `.cc-section-title` and `.cc-section-count` are styled while the parent is not.
- **`cc-row-body` and `cc-rule-add` — dead class names.** Zero references anywhere: no CSS, no selector, no test. Deleting them from `admin.js` is the fix, not styling them.

Closing any of these by guessing at spacing risks a visual regression these guards cannot see, and this is a test-only change — so they are allow-listed with reasons rather than patched here.
