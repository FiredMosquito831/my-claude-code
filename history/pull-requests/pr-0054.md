## Description

The Alibaba field descriptions shipped in 4.38.0 said a Coding Plan key is *"rejected by the Token Plan endpoints"*. Alibaba's own documentation describes the real failure mode differently, and worse: pairing a plan with the wrong endpoint **bills pay-as-you-go rather than drawing on the subscription**, under a doc heading literally titled "Unexpected charges with a Coding Plan".

**"Rejected" is a failure you notice immediately. Silent billing is one you notice on an invoice.** Someone holding a Coding Plan subscription who configures the Token Plan provider — an easy mistake, since both are labelled Alibaba and both take an Alibaba key — gets charged per token for work their subscription already covers.

## What changed

Copy only, no behaviour change:

- Both **Token Plan** descriptions now state they bill per token and point a subscriber at the Coding Plan provider instead.
- Both **Coding Plan** descriptions warn against using the key anywhere else.
- `.env.example` carries the same correction, replacing the inaccurate "rejected by the Token Plan endpoints" line.

The four-provider split already makes the correct pairing the default. This makes the incorrect one legible.
