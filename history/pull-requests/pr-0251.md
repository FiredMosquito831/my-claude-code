## Description

# A third inbound protocol, and the one CLI that speaks nothing else

Gemini CLI cannot be pointed at an OpenAI-shaped endpoint at any price, and neither can anything built on the `google-genai` SDKs. They speak Google's protocol and no other. So this PR serves that protocol.

## What is served

| Route | |
| --- | --- |
| `POST /v1beta/models/{model}:generateContent` | one `GenerateContentResponse` |
| `POST /v1beta/models/{model}:streamGenerateContent` | Google's `alt=sse` stream — bare `data:` frames, **no `[DONE]`** (that is OpenAI's convention and `@google/genai` would try to `JSON.parse` it) |
| `POST /v1beta/models/{model}:countTokens` | `{"totalTokens": N}` |
| `GET /v1beta/models` / `GET /v1beta/models/{model}` | Google's `Model` resource shape, built from the resolution ladder |
| `HEAD` / `OPTIONS` | probes on both |

`{model}` carries MCC's routable ids with their slashes intact — `models/anthropic/openrouter/qwen/qwen3-coder:generateContent`. That is legal and survives the wire: the bundled `@google/genai` joins the path as a plain string and hands it to `new URL()`, which percent-encodes neither `/` nor `:` in a path (`constructUrl`/`tModel`, Gemini CLI 0.49.0). The route matches the tail greedily and splits it from the **right**.

`core/gemini_api/` only translates. A request becomes one `MessagesRequest` and runs through the same `ProviderExecutor`, router, fallback chain, reasoning gating, wire capture, upstream ladder and request log as `/v1/messages`. Rows arrive with `protocol=gemini` and an endpoint carrying the model and the method — the path *is* the model on this surface, and collapsing it to a constant would hide which model a row was for.

## Request translation

| Gemini | MessagesRequest |
| --- | --- |
| `contents[].role: "model"` | `assistant` (absent → `user`) |
| `parts[].text` | `{"type": "text"}` |
| `parts[].text` + `thought: true` | **dropped** — Anthropic rejects a `thinking` block with no signature, so replaying one would fail the whole request |
| `parts[].inlineData` | `image` (base64) for `image/*`, `document` for `application/pdf`, a named 400 otherwise |
| `parts[].fileData` | `image`/`document` with a URL source; a `files/` resource name is a named 400 (there is no Files API here) |
| `parts[].functionCall` | `tool_use`, with a **minted id** — Gemini's parts carry none and Anthropic pairs a result to its call by id |
| `parts[].functionResponse` | `tool_result`, matched to the most recent call of that name; consecutive ones fold into one user turn |
| `systemInstruction` | `system` |
| `generationConfig.maxOutputTokens` / `temperature` / `topP` / `topK` / `stopSequences` | `max_tokens` / `temperature` / `top_p` / `top_k` / `stop_sequences` |
| `generationConfig.candidateCount != 1` | 400 naming the field |
| `thinkingConfig.thinkingBudget: 0` | `thinking: {type: disabled}` |
| `thinkingConfig.thinkingBudget: -1` | `thinking: {type: adaptive}` |
| `thinkingConfig.thinkingBudget: N` | `thinking: {type: enabled, budget_tokens: N}` |
| `thinkingConfig.thinkingLevel` | `output_config.effort` (Gemini 3's rung — the name travels, routing decides the budget) |
| `thinkingConfig.includeThoughts` | carried to the assembler, not upstream |
| `responseMimeType` / `responseSchema` | a system-prompt instruction, the same mechanism Chat Completions uses; Google's upper-case `Schema` types are lowered to JSON Schema |
| `tools[].functionDeclarations` | `tools` (`parameters` or `parametersJsonSchema`) |
| `tools[].googleSearch` etc. | **dropped and traced** — refusing would break Gemini CLI the moment its user enables search |
| `toolConfig` `AUTO`/`VALIDATED` → none, `ANY` → `{type: any}` or `{type: tool}`, `NONE` → tools withheld |
| `safetySettings`, `cachedContent` | dropped and traced |

Both camelCase and snake_case spellings are accepted, because the two SDK families disagree.

## Response translation

| Anthropic SSE | Gemini chunk |
| --- | --- |
| `content_block_delta` `text_delta` | `candidates[0].content.parts[{text}]` |
| `thinking_delta` | `parts[{text, thought: true}]` — **only when `includeThoughts` was true**; Google defaults it false and a client that did not ask renders a thought as answer text |
| `tool_use` start + `input_json_delta`… + `content_block_stop` | one whole `parts[{functionCall:{name,args}}]` — **Gemini does not stream arguments**; every client `JSON.parse`s `args` on arrival, so a call is buffered and emitted once. Two interleaved calls appear in the order they *finished*. |
| `message_delta.stop_reason` | `finishReason`: `end_turn`/`stop_sequence`/`tool_use`/`pause_turn` → `STOP`, `max_tokens` → `MAX_TOKENS`, `refusal` → `SAFETY` (`tool_use` is `STOP` because Gemini has no tool finish reason and clients dispatch on the parts) |
| `usage` | `usageMetadata{promptTokenCount, candidatesTokenCount, totalTokenCount, cachedContentTokenCount, thoughtsTokenCount}` — **`promptTokenCount` includes the cache** where Anthropic's `input_tokens` excludes it; a straight rename would under-report the prompt of every cached request, which is most of them, and Gemini CLI renders that number as its context gauge |
| mid-stream failure | one frame carrying **both** the `error` envelope and a candidate with `finishReason: OTHER` — Google publishes no in-band error convention, and a stream that just stopped would read as a successful empty answer |

Non-streaming assembles the same internal stream at the boundary, exactly as `/v1/messages` does, so flipping the method cannot change the answer.

## Errors and auth

`{"error": {"code", "message", "status"}}`, where `status` is a `google.rpc.Code` name derived from MCC's neutral `FailureKind` — never from an upstream SDK's vocabulary. Gemini CLI branches on that *string* when it decides whether to retry, so a body missing it does not merely read badly.

`api/app.py` also reshapes `HTTPException` bodies **on this surface alone**: `@google/genai` parses a non-2xx body as that envelope and reports "unknown error" for anything else, so a rejected proxy token would tell a user nothing. The other three surfaces keep the `{"detail": ...}` body their clients have always received, pinned by a test.

`require_proxy_auth` gains two forms, both behind the existing ones and using the same constant-time compare:

| Form | Who sends it |
| --- | --- |
| `Authorization: Bearer` | still wins when several are present |
| `x-api-key` | unchanged |
| `x-goog-api-key` | `@google/genai` (`NodeAuth.addKeyHeader`) — a header, never `?key=` |
| `?key=` | Google's REST docs and every curl example; read last, because a token on a URL lands in access logs |

## `mcc-gemini`

**The obvious configuration fails, loudly and confusingly.** `getAuthTypeFromEnv` returns `"gateway"` the moment it sees `GOOGLE_GEMINI_BASE_URL`, and non-interactive startup then runs `validateAuthMethod`, which knows four auth types and refuses that one with "Invalid auth method selected." before a request leaves the machine. So one settings key is unavoidable.

It goes in a document MCC owns at `~/.fcc/gemini-cli-settings.json`, handed over through the CLI's own `GEMINI_CLI_SYSTEM_SETTINGS_PATH`:

```json
{
  "security": {"auth": {"selectedType": "gemini-api-key"}},
  "privacy": {"usageStatisticsEnabled": false},
  "model": {"name": "<primary routed id>"},
  "modelConfigs": {"customAliases": {"<id>": {"extends": "chat-base", "modelConfig": {...}}}}
}
```

`mergeSettings(system, systemDefaults, user, workspace, isTrusted)` calls `customDeepMerge(strategy, schemaDefaults, systemDefaults, user, safeWorkspace, system)` — **system is merged last and wins**. So MCC's three keys apply while `~/.gemini/settings.json` still supplies everything MCC does not name (theme, MCP servers, memory). **It is never written and never read for auth**, and the OAuth tokens beside it are never read at all: the API-key path returns before `createCodeAssistContentGenerator`.

`privacy.usageStatisticsEnabled: false` because `ClearcutLogger` posts to `play.googleapis.com` every 60 s by default and there is **no environment variable** for it. A session routed through a local proxy has no business reporting itself to Google.

`GEMINI_API_KEY` and `GOOGLE_GEMINI_BASE_URL` are set in the launched process only, so neither lands on disk. The base URL is the proxy **root**, with neither `/v1` nor `/v1beta`: `constructUrl` joins `httpOptions.baseUrl` with the API version, whose default is `v1beta`. Nine inherited variables are stripped so a stale `GOOGLE_GENAI_USE_VERTEXAI` cannot outrank this launch.

`customAliases`, not `aliases`: the latter's schema default *is* the built-in preset chain, so naming it would replace it. `getResolvedConfig({model, ...})` is called unconditionally on the main chat path, so an alias keyed by MCC's gateway id really does supply that model's `generateContentConfig`.

**Gemini CLI has no context-window field.** `tokenLimit(model)` is a hardcoded switch over Google's own ids returning a hardcoded 1,048,576 default, and no settings key overrides it. That is now named in `FORMATS_WITHOUT_A_CONTEXT_FIELD` in the serialiser contract test rather than silently skipped.

**Trusted folders:** Gemini CLI refuses a headless run in an untrusted directory and names `--skip-trust` itself. MCC does not set it for you — that is the user's security decision — and the flag is a documented invocation on the card.

## Antigravity: checked, and not possible

The registry's first `available=False` entry. Verified 2026-09-02 against `agy` 1.0.14, read out of the binary and confirmed with a live run under a redirected home. Two independent blockers:

- **Every credential path ends in a Google OAuth token.** `auth.ChainedAuth` composes keyring, browser OAuth, ADC and a corporate login; `CLIAuthProvider` exposes `GetTokenSource`/`GetEntitlement`/`GetCAICProject` and no API-key entry point. The binary contains **no** `GEMINI_API_KEY`, `GOOGLE_API_KEY` or `GOOGLE_GEMINI_BASE_URL`. Without a login: "You are currently not signed in."
- **It does not speak the public Gemini API.** `/v1internal:generateContent`, `:loadCodeAssist`, `:onboardUser`, `:fetchAvailableModels` on `cloudcode-pa.googleapis.com` — proto package `google.internal.cloud.code.v1internal.CloudCode` — never `/v1beta/models/{model}:generateContent`. Its model list is server-supplied, so `--model` cannot name an MCC route either.

`CLOUD_CODE_URL` does redirect the backend host, so a proxy in front of an already-signed-in session is technically reachable. That is a different product and it is not what the card promises. It is **listed rather than omitted** so the question has a dated answer, renders as **Not servable** with the reason on the card, and publishes no console script, launcher or catalogue.

## Residual risks

- **`resolveModel` has two rewrite traps.** A model id containing `flash` can be rewritten when the `useGemini3_5Flash` experiment flag is on, and the literal `none` always is. On the API-key path `getExperiments` returns no flags, so neither fires today — but an MCC route whose id contains `flash` (e.g. `anthropic/gemini/gemini-2.5-flash`) would be at risk if that changes. Not guarded, because guarding it would mean rewriting user model ids.
- **`modelConfigs.customAliases` as a model *name*** works only under `experimentalDynamicModelConfiguration`. The alias's `generateContentConfig` applies unconditionally (verified), but naming an alias in `-m` instead of the full id does not. Documented as "`-m <full id>`".
- **Gemini CLI's picker cannot list MCC's models** — `buildAvailableModels` reads a constant. The launcher prints the list to stderr instead.
- **The functionCall id map matches by name.** Two unanswered calls to the same function in one turn resolve the response to the later one. Google's own ordering makes this the right pairing in practice, and the parts carry no id to do better with.
- **`allowedFunctionNames` with more than one entry** loses the restriction (Anthropic has no equivalent); it becomes `{type: any}`.
- **`refusal` → `SAFETY`** is the closest member of Google's enum, but a client may treat it as a content block rather than a model declining.
- **Antigravity's verdict is a point measurement** of `agy` 1.0.14 on 2026-09-02. A BYOK feature would change it; the card carries the date so the claim can be re-checked.
- The Gemini CLI harness was proven against a **fake** upstream. Nothing in the path is model-specific, but a real provider's stream was not driven through `gemini` itself.
