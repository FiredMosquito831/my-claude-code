## Description

## What was wrong

The routing cards clipped the thing they exist to show. Measured on a 1500px window: four cards fitted the row at 365px each, leaving **169px** for the model ref and truncating **16 of 18** of them mid-name — `nous_portal/meit`, `chatgpt_oauth/gp`. The reorder arrows shipped in 5.37.0 made it slightly worse, since the primary field now carries a button cluster too.

## What changed

**1. Fewer, wider cards.** `.route-grid` asks for 460px rather than 360px, so three rails fit that window instead of four and each card gets 491px.

**2. The chrome around the text is trimmed to what it needs** — this is where the rest came from, and it's the half that doesn't cost density:

| | before | after |
| --- | --- | --- |
| row buttons | 30px wide | 26px (height untouched, target stays 30px tall) |
| marker column | 26px | 24px |
| row gaps | 6px | 4px |
| card side padding | 20px | 14px |
| chevron gutter | 44px | 28px |
| field inset | 14px | 10px |

At the same window: **337px of field, 0 of 18 clipped**, including `nvidia_nim/nvidia/nemotron-3-super-120b-a12b` — the longest a default install can produce.

**The one non-obvious part:** the button rules had to be written against the `.route-rail`-scoped overrides, not the generic `.model-chain-*` ones. The generic rules are shadowed on this page, so editing them changes nothing here. A first pass did exactly that and measured as a **no-op** — the numbers only moved once the probe used `!important`, which is what gave it away.

**3. A `title` on every model field**, equal to its value. A ref longer than the field is now recoverable by hovering rather than only by clicking in and scrolling. That is what covers a user whose provider names run longer than mine — the alternative was tuning the pixel budget to my own longest model name, which is fitting to the sample. Reorders assign `.value` directly and fire no event, so they now dispatch `change`; otherwise the title and the dirty state would go stale after a swap.

## Residual risks

- **Three columns instead of four is a density trade** on a wide window. It was the explicit choice: at four columns nothing fits, and cards stretch to fill the row so there is no way to have four columns *and* readable refs.
- **Verified at one width.** 1506px of grid, which is the reported one. Narrower windows fall to two columns then one, which is the same behaviour as before with a higher breakpoint.
- **No new guard test.** The existing class guard already fails if these rules are lost in a merge, and a test asserting pixel values would encode my window rather than an invariant.
