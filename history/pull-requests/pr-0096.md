## Description

## The bug (caught by the live test)

The rename-then-reinstall path wrapped its success in `try/catch` and returned the version. The caller's `catch {}` swallowed any post-success noise and fell through to `Start-DeferredInstall`, which re-staged the already-consumed wheel and failed with `Copy-Item`. The live test showed the install actually succeeded (5.3.2 live with launchers open) but the run ended in a noisy fallback error.

## The fix

- `Invoke-RenameThenReinstall` now returns a **boolean** (`$true` on success; `$false` only when the rename itself is refused).
- The caller **short-circuits on `$true`** instead of falling through.
- Wheel temp cleanup moved to a `finally` around the whole running-launcher branch so every path (rename success, deferral fallback) cleans up once.

Version stays 5.3.2 (installer-only correction within the same release).

## Verification

- Live: the original run proved the rename-then-reinstall mechanism works (5.3.2 installed immediately with launchers open). This fixes the trailing fallback noise.
- All 7 rename + deferred tests pass; ruff/ty clean.
