## Description

# The Models page learns to manage a thousand models

Provider-level **Show all / Hide all / Invert**, per-row selection with range
picking (Shift+click, Shift+Arrow, drag), state facets, a bulk action bar and
Undo — one request per gesture instead of one per model.

## What was wrong (measured, on the real install)

1021 models across 10 providers; `nous_portal` alone has 317.

| Task | Before |
|---|---|
| Hide every `nous_portal` model | 1 open + 7 "Show more" + **317 ticks = 325 interactions** |
| …requests | **634** |
| …bytes | **≈ 1.07 GB** (the whole 3.4 MB catalogue re-fetched after every tick) |
| …wall clock, network alone | **≈ 5–9 minutes** |
| Patterns written into `MODEL_VISIBILITY_DENY` | **317** |
| Invert a provider | **no path existed** |
| Hide the 38 models matching `opus` across 4 providers | **43 interactions**, and you had to find the 4 providers by eye |
| Undo a mis-aimed bulk hide | **N re-ticks** |
| Sticky elements in the view | **0** — the provider name sat 15,655 px above the last row |

And it was not merely slow: the toggle route read the pattern lists and
computed their replacement **outside** the config lock, so two toggles racing
each other each wrote a full pair derived from the same base. Last writer wins;
the first pattern vanished. Firing N toggles from the client was a *lossy*
implementation of "hide all", not just a slow one.

## What to expect now

| Task | Before | After |
|---|---|---|
| Hide a 317-model provider | 325 interactions | **2** (the second is an inline confirm for ≥200 models) |
| …requests / bytes / time | 634 / ~1.07 GB / 5–9 min | **1 / 41 KB / 7 ms** |
| …patterns written | 317 | **1** (`nous_portal/*`) |
| Hide the 38 `opus` matches | 43 | **3** — type, `Select all 38`, `Hide` |
| Invert a provider | impossible | **1** |
| Undo | N re-ticks | **1 click**, restores both lists exactly |
| Sticky provider headers | 0 | **1 per rendered provider** |
| Repaint 317 rows after a bulk result | — | **12 ms**, one DOM pass |
| View nodes, all collapsed / one provider paged to 317 | 98 / 2645 | 175 / 3358 |

- **Selection.** A box in a ruled left gutter on every row, beside the
  visibility tick. Click one and Shift+click another for a range; **Shift+Space**
  and **Shift+ArrowDown / ArrowUp** do the same from the keyboard (walking back
  towards the anchor shrinks the range); **press and drag down the gutter** to
  sweep rows, with every row taking the anchor's new state so a drag never
  leaves a mixed run. A drag that starts anywhere but the gutter selects
  nothing. The provider header's box is tri-state, and the bar counts live.
- **Facets** — All / Visible / Hidden / Configured / Overridden — plus
  `Select all N` on the result-count line that already existed.
- **Feedback.** A persistent `role="status"` panel: what happened, what pattern
  was written or removed, and the un-honoured breakdown grouped so one
  offending glob is named **once**, not 317 times — with `Undo`, `Show the N`
  and `Dismiss`.

## Action required

**None.** Existing exact patterns and existing globs are preserved. `Hide all`
on a provider that already carries `nous_portal/*` is idempotent and reports
that nothing was written. `Show all` removes only `provider/*` and the
wildcard-free refs under it; a glob you typed yourself is never deleted — when
one of them still hides a model, the panel names it rather than quietly
removing it. Hiding remains display-only: a configured-but-hidden ref still
resolves, still serves, and still shows in the pickers.

## Known and deliberate

- **"Hide all" writes one glob, not 317 exact refs.** That is a standing
  statement about the provider, so models it publishes next week are hidden on
  arrival. 317 exact refs encode a snapshot that silently stops applying, and
  they turn a text field you are invited to hand-edit into a 10 KB blob. A
  partial selection, a filtered provider and every `invert` write exact refs
  instead.
- **No confirmation modal.** Visibility is reversible and display-only, and a
  dialog on every "Hide all" is the friction being removed. Actions over 200
  models get one inline confirm step in the button itself.
- **Not a toast.** The toast rule says auto-dismiss in 3–5 s; a report carrying
  a per-pattern breakdown and the only Undo must not vanish on a timer.
- **Two checkboxes per row, always visible.** Selection-mode-on-demand would
  hide the affordance.
- The provider disclosure is now a `<button aria-expanded>` rather than
  `<details>`, because a `<summary>` must be its parent's first child and a
  control inside a `<summary>` is the a11y violation Chrome reported 1,021
  times on the model rows.
- Not done: virtualising the list; merging (rather than clobbering) the pattern
  textareas on `Save patterns`; the hardcoded `of 11` tier denominator; the
  override editor, which is reviewed and deliberately kept.

## Residual risks

1. **The whole-provider glob is a policy the user may not realise they wrote.**
   After `Hide all`, next week's models are hidden on arrival. Named in the
   result panel, the Guide, USAGE and the pattern textarea — not mitigated for
   someone who reads none of them.
2. **`Show all` cannot undo a glob you wrote, and says so instead.** Some users
   will read "nothing changed, your pattern `nous*` still hides these" as the
   button being broken. Deleting patterns we did not write is worse.
3. **The selection is client-side and unversioned.** Between picking 300 refs
   and pressing Hide, another client can change what those refs are. The server
   reports per-ref truth, so nothing is silently wrong, but a stale selection
   can produce a surprising report.
4. **`apply_admin_config_with` is a new lock ordering** — it takes
   `_config_lock` before reading settings, where `apply_admin_config` takes it
   after. Same lock, no other lock involved, so no deadlock is possible, but it
   is a change in the shared config path and deserves a careful read. Both the
   bulk and the single-toggle route use it.
5. **The models bar stacks on the global action bar.** Its offset is now
   measured from `.action-bar` at render time rather than hardcoded (a fixed
   56 px left it half-hidden in the browser drive), but the two bars still have
   no shared token.
6. **The tests for this page are largely string matches on `admin.js`.** The
   new static guards are written so the redesign satisfies them; the only
   existing assertion changed was adding the new path to the endpoint tuple.
7. **Two checkboxes per row is a legibility bet** validated by the author's
   judgement and one browser drive. The cheap fallback is
   selection-mode-on-demand.
8. **jsdom can silently skip.** Here it **ran**: 95 passed in
   `test_admin_static_jsdom.py`, 21 of them new and models-scoped.
