## Description

6.40.0 renamed the config directory to `~/.mcc` and shipped the migration around it half-finished: the Get Started button could never render, `--force` was dead code, one transient `sqlite3` error could silently start an existing user on an empty `~/.mcc`, a test ran `mcc-migrate` against the developer's real home, and 19 code spans in README/USAGE were corrupted by the mechanical rename while the three new names it introduced were documented nowhere.

This is the follow-up. The organising rule is the one the user set:

> **The only way `~/.fcc` becomes `~/.mcc` is running `mcc-migrate`.** Nothing else — no auto-switch, no auto-create, no demotion, no button, no route.

Version **6.41.1** (PATCH). Removing the dead migrate route and button is a fix — the button could not render and the route could not succeed on Windows — so no observable behaviour a user could have relied on changes. The one deliberate behaviour change beyond a fix is `DELETE /admin/api/requests` now requiring a confirmation parameter and a local `Origin` (item 14); that is a hardening of a route whose only guard was a dismissable browser dialog, and the dashboard's Clear log button sends both.
