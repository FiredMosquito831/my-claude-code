## Description

## What was wrong

A single 429 could hold a request for ~100 seconds before the fallback chain was ever consulted, and four env vars could only be changed by hand-editing `~/.fcc/.env`.

`providers/rate_limit.py` computes `delay = min(base * 2^attempt, max) + jitter` and sleeps before retrying the **same credential**. With the shipped `PROVIDER_RETRY_BACKOFF_MAX_SECONDS=60` the ladder runs 2 → 4 → 8 → 16 (+1 s jitter) ≈ 32 s per key; a three-key pool spends ~100 s on those sleeps before another model is tried, while the 120 s first-token deadline keeps ticking through them.

Measured live on `nvidia_nim/moonshotai/kimi-k3`: NIM answered every attempt in 0.1 s (12×429, 3×502) and the request still took **107 s** to fall back.

Separately, a diff of `Settings.model_fields` aliases against the admin manifest keys found **4 of 263** env vars with no dashboard field at all.

## Mechanism

The ceiling is a **latency budget, not a rate-limit-recovery estimate**. Every wait on the ladder is spent against one credential before routing gets a turn, so the number bounds how long a caller sits on a single key — it belongs at the scale of a request, not of an upstream window.

## What this does

- `PROVIDER_RETRY_BACKOFF_MAX_SECONDS` default **60 → 10** at every site that states it (`config/constants.py`, the admin manifest, README, `docs/USAGE.md`). Ladder is now 2/4/8/10, so a three-key pool reaches its chain in **≈75 s instead of ≈100 s**. Base (`2`) and jitter (`1`) unchanged; the `(0.0, HOUR)` range in `config/limits.py` unchanged; an install that already set the key is unaffected.
- Four settings gained an admin field on the page they belong to:
  | Env var | Page | Restart |
  | --- | --- | --- |
  | `WEBSEARCH_DIGEST_CHARS` | Web Search | no |
  | `WEBSEARCH_DIGEST_CONTENT_CHARS` | Web Search | no |
  | `WEBSEARCH_DIGEST_ANSWER` | Web Search | no |
  | `ANTHROPIC_OAUTH_REQUIRE_CLAUDE_CODE` | Providers → Claude subscription card | **yes** |
- `restart_required` is set from what the code does, not from a guess: the digest fields are read off a fresh `Settings()` **per request** in `api/web_tools/streaming.py` (`settings = Settings()` at the `web_search` branch), so they are not restart-gated. The OAuth gate is read **once** in `providers/runtime/factory.py` when `AnthropicOAuthProvider` is constructed, and `ProviderRuntime` caches the instance in `self._providers`, so it is.
- The OAuth field's help text warns that turning it off routes Agent-SDK and other-harness traffic onto the subscription credential, and points at `docs/ANTHROPIC-SUBSCRIPTION.md`.
- New `tests/contracts/test_every_setting_has_an_admin_field.py` turns the diff into a contract: every `Settings` alias must appear in `manifest.env_keys()`, with `NIM` allow-listed as a nested group (exposed as `NIM_*`), a second test naming the four recovered keys, and a third asserting the allow-list still describes a real nested model. The failure message names the missing key and the manifest file to add it to.

## Residual risks

- Lowering the ceiling means a genuinely slow upstream limit is retried sooner and the pool moves to the fallback chain earlier. That is the intended trade — the chain exists for exactly this — but an operator who wants the old behaviour sets `PROVIDER_RETRY_BACKOFF_MAX_SECONDS=60` and gets it back with no code change.
- The four new fields are wired through the generic manifest renderer and covered by the section/contract tests, but the pages were **not driven in a browser** for this change.
- `.env.example` still names `60` in its comment: the Edit tool denies that path in this environment. No test reads the value from it, and the shipped default now comes from `config/constants.py`.

## Known and deliberate (not done)

The ladder still retries the same credential before rotating, and its sleeps still count against the first-token deadline. Both are real and both are a separate change.
