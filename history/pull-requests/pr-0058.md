## Description

Four defects, each reproduced before it was fixed. Diagnosis came from the live 1.7 GB request log, not from reading code.

## 1. Adding a custom provider returned HTTP 500, always

`admin_custom_routes` was written against an imagined registry contract while the real `ProviderRegistry` landed in a parallel worktree. They drifted:

```
$ curl -X POST /admin/api/custom-providers -d '{"display_name":"My Test Gateway",...}'
{"error":{"message":"ProviderRegistry.add() missing 2 required positional
 arguments: 'base_url' and 'api_keys'"}}
HTTP 500
```

The tests were green because they injected a fake registry shaped like the guess. **That fake is why this shipped.** It is gone — the suite now drives the real `ProviderRegistry` against `tmp_path`, so the contract cannot drift again. The module's duck-typed mirror, its `importlib` indirection and its second copy of the slug rule are deleted; `custom_provider_id()` on the registry is the one implementation.

## 2. No request has *ever* been served by a fallback

```sql
SELECT COUNT(*) FROM requests WHERE route_attempt > 0;   -- 0
```

Routing was never at fault — the sonnet route resolves to three attempts correctly. Two things upstream made the chain unreachable.

**The holdback window never protected anything.** `RecoveryHoldbackBuffer` retains the first 0.75 s of SSE so an early cutoff can be retried invisibly. Its clock started on the locally-built `message_start` frame, pushed *before* the upstream request goes out. Measured time-to-first-token on this traffic is 9–184 s, so the window was always already expired and every stream committed on its first upstream byte. It now starts when the upstream stream opens.

**Non-streaming requests committed on the first chunk** although the client sees nothing until the end — the handler aggregates the whole SSE into one JSON message. Nothing is on the wire, so nothing is committed. Those chunks are now held and dropped with the failed attempt, and the chain continues. 24 of the 62 mid-stream failures in the log were non-streaming and could all have been rescued.

Unchanged and deliberate: a streaming client past its first chunk does not fall back, because swapping models mid-answer would splice two completions.

## 3. An exhausted chain reported as a primary failure

`on_attempt` only fired for the attempt that streamed, so a request that walked three models and failed logged `route_attempt=0`. It now fires before each attempt, which is what makes the Served-by-fallback card and the Failover panel honest.

## 4. Images went to models known to be blind

The vision policy only diverted when `MODEL_VISION` was set. With it unset, an image went to a primary whose own metadata says it rejects images, then to the next blind model in the chain. A chain member known to accept images now leads instead, and known-blind entries are dropped from an image request either way. When nothing is known to see, the route is left intact rather than emptied.

## 5. ChatGPT OAuth exposed 4 models and hid the whole 5.6 family

The backend's models endpoint answers 401 for an OAuth session, so the catalog cannot come from the gateway (probed; the endpoint is not usable this way). It now comes from the models.dev `openai` catalog FCC already fetches and caches, filtered by the same allowlist rule, falling back to the static ids when the cache is absent. An explicit `gpt-5.6` exclusion contradicted the provider's own `>5.4` heuristic and is removed.

```
before: gpt-5.3-codex-spark, gpt-5.4, gpt-5.4-mini, gpt-5.5
after:  + gpt-5.6, gpt-5.6-luna, gpt-5.6-sol, gpt-5.6-terra
```

**A real fallback, end to end, real provider and credentials.** Primary set to `nvidia_nim/deliberately/not-a-real-model`, chain to `opencode/deepseek-v4-flash-free`:

                      "served_by": "opencode/deepseek-v4-flash-free", "count": 1}]

This is the first time a request has gone through a fallback chain in this project.

**Custom provider create against a real server** on a throwaway home: HTTP 200, persisted to `custom_providers.json`, listed, key masked in every response, duplicate name 409.

**Nous `/models`** confirms `tencent/hy3:free` publishes `input_modalities: ["text"]`, so the vision diversion is live for this configuration.

**Suite:** 3337 passed, 6 failed — the documented PowerShell installer baseline, identical on unmodified `main`. `ruff format`, `ruff check` and `ty` clean.

## Residual risks

- A streaming client still cannot fall back once its first chunk is out. Recovering that means putting the chain inside the provider's midstream recovery, which is an architecture change rather than a fix.
- No live image request was made: the stored ChatGPT OAuth token is expired, so the vision diversion is proven by provider metadata and unit tests, not a round trip.
- Non-streaming requests now report `ttft_ms` close to `duration_ms`, since the client genuinely receives nothing earlier. 144 of the last 20 000 requests were non-streaming.
- models.dev is a third-party catalog. If it lists an `openai` model the OAuth backend does not serve, that model appears in the picker and fails on use. The static fallback list bounds the damage when the cache is missing, not when it is wrong.
