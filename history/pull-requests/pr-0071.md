## Description

## The bug that was eating configuration

Saving anything in the admin Configuration page rewrote `~/.fcc/.env` from the manifest, so **every key the manifest did not know about was silently deleted**:

```
key                            kept   written back
MODEL                          yes    yes
REQUEST_LOG_MAX_ROWS           NO     NO
FALLBACK_FIRST_TOKEN_TIMEOUT   yes    NO
LOG_LEVEL                      yes    NO
```

A raised `REQUEST_LOG_MAX_ROWS` reverted to the default on the next unrelated save — which is why a retention cap that had been raised to 500k kept behaving like 50k.

Saving now writes back any key `Settings` still reads, under its own heading. A key that configures nothing is still dropped, so a retired provider option retires rather than being preserved forever (this keeps the existing stale-key behaviour that `test_admin_apply_omits_stale_zai_base_url` covers).

## Promoted from module constants to settings

Tuning these previously meant editing installed source:

| Setting | Was | What it costs |
| --- | --- | --- |
| `PROVIDER_RETRY_ATTEMPTS` | `UPSTREAM_TRANSIENT_TOTAL_ATTEMPTS=5` | ~30s of backoff before a healthy fallback is tried |
| `STREAM_MIDSTREAM_RECOVERY_ATTEMPTS` | `=5` | bounds how long a dying stream holds a request |
| `STREAM_COMMIT_HOLDBACK_SECONDS` | `EARLY_HOLDBACK_SECONDS=0.75` | width of the invisible-recovery window |
| `STREAM_EARLY_RETRY_ATTEMPTS` | `EARLY_TRANSPARENT_TOTAL_ATTEMPTS=5` | retries before routing sees a failure |
| `RATE_LIMIT_COOLDOWN_SECONDS` | `=60` | pause when a 429 carries no `Retry-After` |
| `CREDENTIAL_CIRCUIT_THRESHOLD` | `=3` | failures before one key is benched |
| `REQUEST_LOG_TEXT_MAX_CHARS` | `MAX_TEXT_CHARS=50000` | also bounds what content search can find |
| `REQUEST_LOG_COMPRESSION_LEVEL` | `=9` | level 19 measured 4.9% smaller at 1/9 the speed |
| `REQUEST_LOG_QUEUE_MAX_SIZE` | `=10000` | pending writes before records are dropped |

A holdback of `0` now commits the first event immediately rather than buffering it until some later push happens to check the clock.

## New "Limits" section

18 fields: the four fallback deadlines, the nine above, and request-log retention/capture/compression. Each carries a description saying what the value costs, not just what it is.

A test asserts **every field's default equals the code's own default** — a form that shows a different number than the server uses is a lie, and that class of drift is exactly what made the retention cap confusing.
