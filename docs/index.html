What it is

MCC is a local LLM gateway, proxy and model router for AI coding agents. Instead of configuring providers, API keys, models, fallbacks, reasoning effort and spend tracking separately inside every coding tool you use, you point those tools at one address on your own machine and manage the routing layer once.

It runs entirely on your machine. It has no telemetry and phones home to nothing; its only outbound traffic goes to the providers you configure. Your keys stay in one .env you own.

Why it exists

A coding agent is a client. It speaks one protocol, expects one model name, and has no idea which provider answered. MCC makes that separation real: the agent keeps its own interface, while the model behind it can be a cloud API, a subscription, a gateway or a local server, with a fallback chain behind every route.

That separation is what makes the rest possible. A request can be re-routed when a model rate-limits. A key can be rotated without touching the agent's configuration. Reasoning effort can be translated once into each provider's own dialect. Every request can be priced at the moment it is logged, with the source of each number recorded beside it.

Who it is for

It is for the developer who runs more than one agent and more than one provider: Claude Code on one project, Codex on another, a local model for a private repository, and a paid API for the work that needs it. Each of those tools has its own configuration file, its own key store and its own idea of what a model is called. MCC gives them one address and one place to change the answer.

It is also for the person who wants to know what a routing decision actually did. A fallback that fired, a key that was benched, a price that no source could state: each is a row in the log, not a story reconstructed from a terminal. That is why the analytics pages are as detailed as the settings pages.

It is not a managed service. MCC runs on your machine, with your keys, and there is no account to create and no dashboard outside your own address.

The request path

Four protocol doors reach the same router. Claude Code, Pi, OpenCode, Crush, Kimi Code and Qwen Code speak Anthropic Messages; Codex speaks OpenAI Responses; Cline, Goose, Aider and every OpenAI-shaped SDK speak Chat Completions; Gemini CLI and Antigravity speak Google's Gemini API. The router resolves the requested tier to a real model, applies your reasoning and output-budget settings, picks a healthy credential and walks the fallback chain when a provider fails. The reply is translated back into the protocol the agent asked in, and the whole exchange is priced and logged once on its way out.

A control plane, not a wrapper

The dashboard is the part you can see. It opens on a Get Started checklist and then gets out of the way. The Providers page is one searchable card per provider. Model Config is one rail per tier with its real fallback chain. Analytics is a request log and everything computed from it. Each of those pages reads and writes the same .env the server reads, so the dashboard and the file never disagree.

The request log is the other half of the control plane. Every completed request is logged, priced and searchable across prompt, reply, reasoning and tool calls. A fallback that fired, a key that was benched, a reasoning field a host refused: each is a row with its reason, not a story you have to reconstruct from a terminal.

Install it in one line

Every install route ends at the same server, the same dashboard and the same configuration directory. The one-liners install uv and a managed Python 3.14 if they are missing, verify the release wheel's SHA-256 and put every mcc-* command on your PATH.

Linux, macOS or WSL
curl -fsSL "https://raw.githubusercontent.com/FiredMosquito831/my-claude-code/main/scripts/install.sh" | sh

Windows Command Prompt and PowerShell have their own one-liners, and there is a native desktop app for each platform. After any install, close and reopen your terminal: the installer adds ~/.local/bin to your PATH, and a shell that was already open cannot see it.

Then: run mcc-server, open http://127.0.0.1:8082/admin, add one provider key on Providers, set your tiers on Model Config, and launch an agent with mcc-claude.
