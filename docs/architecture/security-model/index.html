The principles the boundary is built on

This page states what MCC does to keep a local proxy local, and what it refuses to do. It is a description of the design, not a security audit, and it makes no claim that a deployment is safe without the operator's own choices. It is the LLM gateway security model: local by default, a token once it leaves the machine, owner-only stores, redacted logs and narrow egress.

The threat model starts from one fact: the proxy holds the keys to providers that bill. A local service with those keys has to be reachable by the tools that need it and by nothing else. The principles below are how the code enforces that, and each one has a visible consequence.

Local by default

The admin UI and the admin APIs are loopback-only. They have no login because they are not reachable from another machine, and the proxy's own listen address is a setting the operator chooses. The dashboard does not open a second port and does not embed a remote widget.

A token once it leaves this machine

Proxy authentication is a bearer token. When it is set, the proxy accepts exactly that token, compares it in constant time, and ignores other credential headers so a stale provider key cannot mask valid proxy authorization. When the host is opened to other machines and the token is empty, the server refuses to start rather than serving an unauthenticated proxy. The token is generated for the machine on first start and lives in the configuration home.

Owner-only stores

OAuth credentials live in owner-only files, and a login a proxy listener asks for is stored owner-only and never shown again. A credential read from another application's file is read-only to MCC. The configuration home is one directory, so an operator can see and protect everything in one place rather than hunting for scattered state.

Redacted by default

Values under keys that look like an API key, an authorization, a token or a secret are redacted where structured traces are emitted. API payloads and streamed events are not logged raw unless explicitly enabled. The provider's own bytes are kept only behind an opt-in flag. Messaging text, transcription previews and CLI diagnostics each have their own flag, so a normal install does not record a conversation by accident.

Narrow egress

The only outbound traffic is a request to a provider the operator configured, a search service the operator enabled, or a web page a client asked to fetch. There is no telemetry and no call home. Web fetch enforces its allowed URL schemes and blocks private-network targets unless the operator explicitly allows them. Local provider status checks are exposed only through the local admin API.

Evidence over assertion

A price is recorded with the source that stated it. A skipped model is a row with its reason. A key's health is decided from the provider's own signals, and a bench duration is never invented. The same discipline is applied to this site: every claim is recorded against a path or a command in the repository, and a figure that cannot be traced is not published.

What this page does not claim

  • It does not claim the software is free of defects. No such claim is made anywhere on this site.
  • It does not claim a deployment is safe regardless of how it is configured. Opening the proxy without a token is refused, but the operator still chooses the address, the network and the keys.
  • It does not describe an audit, a penetration test or a certification, and none is implied.
  • It does not repeat a known issue as a public roadmap. Issues are handled in the repository's own channel.

Operating principles for the reader

  • Keep the proxy on loopback unless a client on another machine genuinely needs it; if it needs it, set the token and put the proxy behind a network you control.
  • Use a separate key per machine or per purpose, so a key can be revoked without taking everything down.
  • Read a provider's own terms before routing a subscription credential through any proxy. MCC documents the Anthropic subscription position rather than hiding it.
  • Treat the configuration home as a secret. It holds the keys, the stores and the log.
  • Prefer a short retention window and raw logging off unless you are actively diagnosing a request.
