Install, run, and the first five minutes

Every route ends at the same server, the same dashboard and the same configuration directory. Pick the one that fits your machine, then follow four steps.

Install

The one-liners install uv if it is missing, install Python 3.14 through uv, verify the release wheel's SHA-256, install MCC into an isolated tool environment and put every mcc-* command on your PATH. The wheel is the same one the PyPI route installs, and the desktop app installs the server on first launch if it is not there yet.

Linux, macOS or WSL
curl -fsSL "https://raw.githubusercontent.com/FiredMosquito831/my-claude-code/main/scripts/install.sh" | sh
Windows PowerShell
& ([scriptblock]::Create((irm "https://raw.githubusercontent.com/FiredMosquito831/my-claude-code/main/scripts/install.ps1")))
Windows Command Prompt
curl -fsSL -o "%TEMP%\install-mcc.cmd" https://raw.githubusercontent.com/FiredMosquito831/my-claude-code/main/scripts/install.cmd && "%TEMP%\install-mcc.cmd"
npm, any platform
npm install -g @firedmosquito831/my-claude-code

There are also native desktop installers for Windows, Linux and macOS on the latest release page, and a PyPI route for people who already manage Python 3.14. Close and reopen your terminal after installing: the installer adds ~/.local/bin to your PATH, and a shell that was already open cannot see it.

The first five minutes

  1. Start it and open the dashboard: run mcc-server, then open http://127.0.0.1:8082/admin. The desktop app does both for you.
  2. Add a provider key: on Providers, find your provider, click Configure, paste the key, then Validate and Apply.
  3. Point the tiers at a model: on Model Config set MODEL and, if you want per-tier routing, the Mythos, Fable, Opus, Sonnet and Haiku models, each with a fallback chain.
  4. Launch an agent: mcc-claude, mcc-codex, mcc-opencode, mcc-gemini, or Configure on the Coding agents page for a desktop app.
A fresh install already routes. Since 7.78.0, the Mythos, Fable, Opus and Sonnet tiers start on OpenCode Zen's free model with no key at all. MODEL and Haiku still point at NVIDIA NIM, so they need a key or a new model.

Update

The dashboard shows your version, announces releases and installs them with checksum verification. Re-running the install command does the same thing, because it always fetches the newest release. Since 7.1.0 every install restarts the server by default: it stops the one server bound to that configuration directory's port, by its exact process ids, installs, starts the server again and waits until the health endpoint answers. --no-restart never stops a running server, and --no-start stops and starts nothing. There is no separate updater to install.

An update is atomic. The new version is built beside the running one, run once to prove it works, and swapped in by two directory renames. If it never answers the health endpoint, the previous version is put back and started.

Uninstall

Uninstall is one line, and it verifies every MCC command is gone before it reports success. If you installed through npm, mcc uninstall is the other route. The desktop app is removed separately, through Apps and Features, the package manager, the app's own uninstall script or the Trash.

Uninstall (Linux, macOS or WSL)
curl -fsSL "https://raw.githubusercontent.com/FiredMosquito831/my-claude-code/main/scripts/uninstall.sh" | sh

Four things that bite

  • Windows SmartScreen flags the unsigned installer: choose More info, then Run anyway. With Smart App Control on, use the PowerShell server one-liner instead.
  • macOS quarantines the unsigned disk image. After dragging the app across, run one xattr command to clear the quarantine, or take the server one-liner and let the desktop command fetch the same binary.
  • WSL has no tray. Install the server there and reach the dashboard in a Windows browser.
  • A pre-6.40.0 install lives in the legacy configuration home. The first start of 6.65.0 or later migrates it by one atomic rename, provided nothing is holding the directory open.
