When a step does not work

Each entry below is a symptom the product's own documentation names, its verified cause, and the fix it gives. If your case is not here, the repository's issue tracker is the right channel. It is the LLM gateway troubleshooting page: the failures this site can verify, with the fix for each.

mcc-server is not found after a successful install

Symptom: the installer finished, but mcc-server is not recognised. Cause: the installer added ~/.local/bin to your PATH, and a terminal that was already open cannot see the change. Fix: close and reopen the terminal, then check mcc-server --version.

Windows SmartScreen refuses the desktop installer

Symptom: Windows blocks the unsigned installer. Cause: the desktop installer is unsigned. Fix: choose More info, then Run anyway. On a machine with Smart App Control on, the app cannot run at all; use the PowerShell server one-liner instead.

macOS will not open the app

Symptom: the app is blocked after it is dragged across. Cause: the disk image is unsigned and macOS quarantines it. Fix: clear the quarantine once with the xattr command the documentation gives, or take the server one-liner and let the desktop command fetch the same binary, which is never quarantined.

The tray is missing in WSL

Symptom: the desktop app refuses to start in WSL. Cause: WSL has no tray. Fix: run the server in WSL and reach the dashboard in a Windows browser. The app says so and refuses rather than pretending.

The dashboard will not open

Symptom: the admin address does not answer. Cause: one of three things: the server is not running, it is on a different port, or a launcher and the server resolved different configuration directories. Fix: start the server and read the startup log, which names the directory in use; check PORT; and if you set MCC_CONFIG_DIR, set it for the launchers too.

The install reports a port it will not touch

Symptom: the installer says the port is held by something that is not MCC. Cause: another program owns the port. Fix: MCC reports it and leaves it alone rather than killing an unknown process. Choose another PORT or stop the other program yourself.

Every key is benched

Symptom: a provider card says every key is benched until a time. Cause: the provider rate-limited the keys or refused the balance. Fix: wait for the bench to expire, or read the credential-health card to see which signal caused it. A 429 bench lasts the wait the provider published; an exhausted balance benches the whole key for the cooldown window.

A request fails with a readiness error

Symptom: a request returns an error before any provider is called. Cause: a missing provider configuration or a request runtime that is shutting down. This is an application-readiness error, not a provider failure. Fix: open Providers, confirm the card is configured, and Validate and Apply. A request that never reached a provider is not a credential problem.

Web fetch refuses a page

Symptom: a fetch to a local or private address is refused. Cause: web-fetch egress enforces its allowed URL schemes and blocks private-network targets by default. Fix: this is the intended boundary. If the target is genuinely intended, the operator can allow private networks explicitly; do not widen it to make one page load.

A model is missing from the picker

Symptom: a model a provider publishes does not appear in /v1/models or an agent's picker. Cause: the model is hidden, or its stated kind is not chat, or a catalogue snapshot predates the latest refresh. Fix: check visibility on the Models page, check the model's kind, and restart the client that reads a startup catalogue. Hiding changes listings and never routing.

A media request is skipped as unsupported

Symptom: an image or speech request moves past a model without trying it. Cause: the provider declares no endpoint for that operation. MCC never guesses from a model name. Fix: put a model whose provider declares the endpoint on that rail. The skipped model is not charged a failure.

An update does not finish

Symptom: an update runs but the new version never answers the health check. Cause: the new build failed to start. Fix: the previous version is put back and started automatically. Read the install log and the progress document in the configuration home to see where it stopped, then re-run the update.

A setting does not take effect

Symptom: a saved setting appears to be ignored. Cause: the setting is restart-required, so the running process still holds the value it read at startup. Fix: the dashboard marks these settings for exactly this reason. Restart the server, or use the update's restart, after saving.

A launcher will not start its agent

Symptom: a launcher exits instead of starting the agent. Cause: the agent is not installed. Fix: the launcher prints that agent's own install command and exits, and the Coding agents page has an Install button for the same job. MCC does not install agents on its own.
