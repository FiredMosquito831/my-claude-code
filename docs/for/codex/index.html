Codex CLI through one local address

Codex CLI is OpenAI's terminal agent, and it speaks the OpenAI Responses API. mcc-codex points it at My Claude Code on your machine, so the model behind its next request can be any provider you have configured, with a fallback chain and a priced log entry behind it. It is the Codex CLI proxy setup in one command.

The command

Install Codex CLI yourself, because MCC never installs an agent, then launch it through the proxy with one command:

Launch Codex CLI against the local proxy
mcc-codex

The launcher passes the proxy as an ephemeral -c assignment on the command line, so your own config.toml is never rewritten. The provider it declares is named for the proxy, points at the proxy's /v1 root, uses the Responses wire API and reads its key from an environment variable the launcher sets for that one process.

A single prompt runs the same way, using Codex's own subcommand: mcc-codex exec "summarise this diff". mcc-codex resume --last continues the most recent session, and neither form needs a different launcher.

MCC also generates a model catalogue for Codex and points the launch at it, so the models Codex offers are the ones your routes actually resolve to, with the limits and prices the metadata ladder found.

The catalog is written under the MCC configuration home and named on the command line for that one launch, in the same way as the provider assignment. Nothing under your Codex home is rewritten, and a Codex session you start without mcc-codex sees exactly the configuration it saw before.

What Codex gets

  • One address for every provider, over the OpenAI Responses API that Codex already speaks.
  • Fallback chains. When the first model cannot serve a request, the next rung is tried before the agent sees a failure, and each step is recorded.
  • A generated model catalogue, so the models Codex lists are the ones your routes resolve to.
  • Credential rotation and health, so a rate-limited key is benched and another key in the pool is tried for the same request.
  • A priced request log: which model answered, which key it used, how many tokens it spent and where the price came from.
  • Per-agent attribution. The launcher marks the request as Codex's, so the log can name the agent behind it.

What the launcher does not change

Your Codex installation and its config.toml are untouched, because every assignment the launcher adds exists for one launch only. If Codex is not installed, the launcher prints OpenAI's own install line and exits rather than installing anything on your behalf.
