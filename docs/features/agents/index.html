A first-class client for every agent

Claude Code is one client here, not the frame around everything else. MCC can launch the CLI agents, configure the desktop apps it cannot launch, generate a real model catalogue for each one, and name the agent behind every request in the log.

Every agent MCC can launch is declared in one registry, and the Coding agents page shows each one's installed state, its commands and flags with a copy button, its protocol and its generated catalogue. Applications MCC does not launch get a Configure button on the same page instead, which edits the one file each of them reads.

The launchers

A launcher is a small command that points an agent at the local proxy and starts it. The set covers Claude Code (mcc-claude), Codex (mcc-codex), OpenCode and OpenCode 2 (mcc-opencode, mcc-opencode2), Gemini CLI (mcc-gemini), Crush, Cline, Goose, Aider, Kimi Code, Qwen Code, Command Code, OpenClaw, Hermes Agent, Droid, Pi and Kilo. mcc-claude --discover-models wires Claude Code's native /model picker to MCC's catalogue; mcc-claude-old keeps the older launch shape.

Installing an agent from the dashboard

An agent that is not installed gets an Install button on its card, with the vendor's own line beside it to copy instead. The plan is shown before anything runs: every download, command, permission prompt and PATH or profile change. The vendor's own installer is used first, npm only where it is the only way, and Node.js is installed first only when it is missing. MCC never runs sudo and never upgrades your Node.js.

Desktop apps: Configure and Undo

For an app MCC cannot launch, Configure writes MCC's keys into the one file that app reads and carries every other byte through. A .mcc-backup is taken before the first edit, a diff preview is shown before every write, and a drift badge appears after a hand-edit. Undo works two ways: remove only MCC's keys, or restore the exact values MCC replaced. The files MCC does not reformat are left alone.

The same work is available without a browser. mcc-apps list, mcc-apps status, mcc-apps configure [--preview] and mcc-apps undo [--restore] do what the buttons do, which matters on a headless machine.

Generated catalogues

Each agent's model list is generated from the same metadata the router uses: real context windows, output ceilings, vision support, tool support and the host's own effort vocabulary. The composition bridge that writes a catalogue uses the same visibility filter, ref enumeration and projection as /v1/models, so a model cannot appear in one and not the other. Writes are atomic, identical bytes are not rewritten, and a last-known-good catalogue is preserved when a projection resolves no routable models.

Request attribution

Analytics names the coding agent behind every request. The harness is identified from the x-mcc-harness header or the request's user-agent fingerprint, and it drives both the log's attribution and the per-agent tier map. An unidentified request is not failed; it resolves against the global chain and is logged as unidentified.

The same attribution is what lets one agent run a different tier map from another without a second proxy. Claude Code can route Opus-tier traffic to one model and Codex to another while both talk to the same address.

Media tools for an agent

MCC's media server, mcc-mcp, gives an agent one tool per filled media rail, plus a free status tool. It is added per agent with an Add MCP server button and taken out with Remove. The buttons write only MCC's own launch lines and configuration layers, never your files; the token stays in MCC's settings; each agent's own prompt asks before a paid tool. It is off for every agent by default.

Other clients

Anything that speaks OpenAI, Anthropic or Gemini can be pointed at the proxy, including VS Code's Copilot custom endpoint and the JetBrains ACP surface. The clients documentation carries an API reference with one runnable example per endpoint. An agent MCC cannot launch and an app MCC cannot configure are both still clients if the user points them here. A client that speaks one of the four protocols needs no plugin, and a client that speaks none of them is out of scope rather than half-supported.

Limits and behaviour

  • A launcher whose agent is missing prints that agent's own install command and exits; it does not try to install the agent itself.
  • A drift badge appears when a hand-edit moves a configured file away from what MCC wrote.
  • A tool-returned image and a media request share the same rails and the same cost accounting as chat.
  • The Media server is off for every agent until it is added, and no agent button writes to a file MCC did not create.
