The native web-search and web-fetch proxy

Claude Code's web_search and web_fetch are Anthropic server tools: normally Anthropic runs the search and bills you for it. MCC fulfils them at the proxy instead, against a provider you choose or a keyless fallback, and streams the result back as ordinary text. No Anthropic search credits are used, and it works with any model provider. It is a web search proxy and a web fetch proxy, in front of fifteen search backends.

A client emits a web_search tool-use block. MCC runs the search against the configured chain and returns the results as a regular text block, so a model that has never heard of the tool still receives useful text. The same shape covers web_fetch, which retrieves a page and returns its main content.

Fifteen search backends

The search backends are DuckDuckGo (keyless), Ollama Web Search, Exa, Tavily, Brave Search, SearXNG, Jina Search, Serper, Firecrawl, Linkup, Perplexity Search, Parallel, SearchAPI.io, SerpAPI and Context7 for library documentation. WEB_SEARCH_PROVIDER accepts auto, off, disabled or one of those provider IDs.

SettingBehaviour
autothe first configured provider in catalogue order, never Context7; with no keys set it falls back to the keyless hops, so search works zero-config
offonly the keyless DuckDuckGo hop, without the provider registry
disabledreject web searches without making an outbound search request
an explicit IDpin that provider; missing credentials or an upstream failure are surfaced instead of silently changing providers

WEB_SEARCH_FALLBACK_POLICY controls how far the chain may move after the selected provider: auto, none, ddgs or legacy. Configuration failures such as a missing API key always fail visibly, DDGS is never attempted twice, and the rich digest names the provider that ultimately produced the results.

The keyless DuckDuckGo hop

The last hop reads DuckDuckGo's HTML page first and its lite page only as a second try, with declared parser profiles and headers. Snippets are kept, ads are skipped, and your region and time window are respected through the DDGS_REGION and DDGS_TIMELIMIT settings. A bot check is reported as a rate limit rather than as no results, and optional spacing between requests is available, off by default.

Keys rotate like model keys

Every search service's keys follow the same rules as a model provider's keys: comma-separated pools, the same rotation policies, and the same health engine. The bench is shown in plain words with a Reset, and every key try is a row in Analytics. The chain itself is an ordered list of services with repeats, pause and drag, edited on the Search chain card.

Web fetch

Web fetch returns the page's main content as markdown with links and tables: menus and footers are dropped. The extractor is loaded on the first fetch of a process, the output is capped at 24,000 characters and the marker names the extracted total, markdown is asked for in the Accept header, a Cloudflare challenge gets one honest retry, and a page served without a charset is read rather than refused. WEB_FETCH_EXTRACTOR=basic restores every earlier release's bytes.

Analytics

Web search has its own route and attempt analytics, with the captured input and output, separate from the chat log. That split matters because a search attempt is a different kind of call: it can fail on a key, on the query or on the search host, and the analytics keeps those apart from the model request that asked for it.

Configuration

The route is WEB_SEARCH_PROVIDER and WEB_SEARCH_FALLBACK_POLICY. Each backend has its own key variable, named on its card. The keyless hop uses DDGS_REGION and DDGS_TIMELIMIT, and optional request spacing uses WEBSEARCH_LEGACY_MIN_INTERVAL_SECONDS. Web fetch uses WEB_FETCH_EXTRACTOR. Variable names only; no values are published.

Limits and behaviour

  • Context7 is never picked by auto: it answers with library documentation rather than web pages.
  • An explicit provider is strict by default; a missing key fails visibly instead of silently swapping to another backend.
  • The keyless hop is an unofficial metasearch and its engines may rate-limit an address. That is reported as a rate limit, not as an empty result.
  • Advanced options allow the model to receive full page text rather than snippets, restrict searches to specific sites, and set safe search, locale and freshness.
  • This is a server-tool proxy: a client that does not use the Anthropic server-tool shape is not affected.
