Every capability, with a deep page for each

MCC is deep because a proxy that sits in front of every coding agent has to be. Each area below has its own page, written from the source and the product's own documentation, with real screenshots of the dashboard where the feature lives. This page is the index of LLM gateway features: every capability area, with a deep page for each.

The shortcut below is the whole product in one sentence: one address, every provider you configure, and a control plane that keeps the model, the credential, the reasoning setting and the cost in one place. The pages after it go one area at a time.

The pages are written this way because the product is not one feature. A proxy that sits in front of sixteen agents and sixty providers has to answer the same question differently for each of them, and a one-page summary would either flatten that or repeat it. Each page takes one area and follows it through the code, the dashboard and the request log.

The order is deliberate: a reader who wants the architecture can start there, and a reader who wants to install can stop after the quick start. Nothing on a page depends on having read another first, though the related links at the foot of each one point at the neighbour that explains a term in more depth.

How to read these pages

Each deep page answers the same questions in order: what the capability is, why it matters, how to use it with verified steps, what you see in the dashboard, and what its limits are. Configuration is named by variable, never by value. Where a feature depends on another, the related links at the foot of the page point at it.

A capability is on this site only when the code or the tests prove it exists. Every number is either computed from the repository or recorded against the command that produced it. If a page is not here, the feature did not meet that bar.
