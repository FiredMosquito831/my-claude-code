The local control panel

The Admin UI is local-only and is where everything is configured. It opens on a Get Started checklist and gets out of the way once dismissed. It reads and writes the same .env the server reads, so the page and the file never disagree.

The dashboard is served by the server it configures, on loopback, at http://127.0.0.1:8082/admin. It has no login because it is not reachable from another machine. A change is collected on the page and written only when you press Apply, at the foot of the page, which validates first.

Appearance

A page is a view over configuration, not a separate store. The Analytics page reads the request log; Model Config reads and writes the tier variables; the Providers page reads the key pools and the credential stores. Closing the browser changes nothing, and reopening it shows the server's current state rather than a cached copy.

The dashboard's own look is a feature. There are two designs, Today and Hybrid, the latter with a masthead, a numbered rail and a right-hand drawer; seven colour families, each in light and dark; and three densities. They are chosen per browser on Get Started, or machine-wide with ADMIN_DESIGN, ADMIN_THEME, ADMIN_MODE and ADMIN_DENSITY. A browser choice always wins, and a shell that cannot start falls back to Today with a one-line note.

Validate and Apply

The footer of a settings page validates before it writes. A setting the server can only read at startup is marked restart-required, so Apply cannot report success while a running server keeps using the old value. A managed write backs the file up first. The dashboard and the file are one source of truth: a value set by hand is shown on the page, and a value set on the page is in the file.

Updates

The sidebar shows the running version and live status. A newer release is announced with its changelog, and the Update button runs the same installer path as the command line: checksum verified, built beside the running version, run once, swapped in, and the previous version restored if the health check never answers.

Local only, by construction

  • The admin UI and admin APIs are loopback-only.
  • The dashboard has no third-party analytics, no remote fonts and no embedded widgets.
  • A hidden tab reads nothing; the Usage page refreshes only while it is open.
  • The Docs page renders the documentation bundled with the installed version, so it works offline.
  • The page loads no remote font, script or image; its stylesheet and its one small script are served by the server itself.

Configuration

Most settings are written to the managed .env. The appearance settings are ADMIN_DESIGN, ADMIN_THEME, ADMIN_MODE and ADMIN_DENSITY; the log retention settings are on the Analytics page; and the usage auto-refresh interval is USAGE_AUTO_REFRESH_SECONDS. The configuration home itself is MCC_CONFIG_DIR, which is environment-only and cannot be set from the dashboard.

Limits and behaviour

  • A restart-required change is labelled, not silently deferred.
  • A setting the page cannot validate is not written.
  • The dashboard never opens a port beyond the server's own address.
  • A browser-level appearance choice overrides a machine-wide one without changing it.
